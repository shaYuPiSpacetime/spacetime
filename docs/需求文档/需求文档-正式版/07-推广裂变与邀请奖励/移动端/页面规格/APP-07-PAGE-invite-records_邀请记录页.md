# 页面规格 - APP-07-PAGE-invite-records 邀请记录页

> 版本：02｜更新日期：2026-07-17｜状态：已确认
> 对应设计稿：待补充；设计画板按第 2 节输出。

## 1. 页面定位

展示当前用户已经成功建立的永久邀请关系，以及每位被邀请人的累计已发奖励和奖励发放结果。

## 2. 布局

导航栏下方为状态筛选、记录列表和滚动分页。没有关系状态筛选或冻结原因弹层。

| UI画板 | 内容 | 关键状态 |
|---|---|---|
| 邀请记录 | 四筛选+记录卡 | 正常/空/加载/错误/发放失败 |
| 奖励展开 | 基础与阶梯明细 | 单笔/多笔 |

## 3. 筛选

筛选项为全部、待发放、已发放、发放失败。筛选对象是该邀请关系关联奖励的发放状态；一条关系有多笔奖励时按最近一笔/汇总规则展示。

## 4. 字段表

| 字段 ID | 显示名 | 类型 | 必填 | 取值范围 | 校验规则 | 默认值 | 可编辑 | 敏感级别 | 数据来源 |
|---|---|---|---:|---|---|---|---|---|---|
| `APP-07-FIELD-invitee` | 好友 | json | 是 | 头像+昵称 | 昵称/手机号脱敏 | 无 | 否 | 敏感：手机号138****1234，不导出，注销后匿名化 | PRD-01用户资料 |
| `APP-07-FIELD-registered-at` | 完成注册时间 | datetime | 是 | 合法时间 | 后端返回 | 无 | 否 | 普通 | 邀请关系 |
| `APP-07-FIELD-paid-total` | 已发奖励 | int | 是 | ≥0 | 仅success流水求和 | 0 | 否 | 普通 | 奖励聚合 |
| `APP-07-FIELD-reward-status` | 奖励状态 | enum | 是 | `M07-ENUM-invite-reward-status` | 枚举校验 | 无 | 否 | 普通 | 奖励流水 |
| `APP-07-FIELD-reward-items` | 奖励明细 | json | 否 | 基础事件+动态阶梯 | 按生成时间倒序 | 空数组 | 否 | 普通 | 奖励流水 |

## 5. 操作表

| 操作 ID | 操作名 | 触发条件 | 前置权限 | 二次确认 | 成功态 | 失败态 | 影响（副作用） |
|---|---|---|---|---|---|---|---|
| `APP-07-ACT-filter-records` | 切换筛选 | 页面已加载 | 登录用户 | 否 | 刷新匹配记录 | 保留旧列表并提示 | 重置分页 |
| `APP-07-ACT-expand-reward` | 展开奖励明细 | 记录存在 | 登录用户且为本人数据 | 否 | 展示奖励项 | `M07-ERR-*`提示重试 | 无数据变更 |
| `APP-07-ACT-reload-records` | 重新加载 | 加载失败 | 登录用户 | 否 | 恢复列表 | 保持错误态 | 重试原查询 |

## 6. 数据规则

不满足资格的请求不会建立关系，因此不会出现在列表。已发奖励为该关系状态=已发放的基础与阶梯奖励合计。

## 7. 状态与异常

支持空数据、加载中、网络失败和发放失败。页面不展示冻结、无效、作废或风险原因。

## 8. 查询与列表

默认按完成注册时间倒序，每页20条，下拉刷新和触底加载。

## 9. 验收标准

`APP-07-AC-record-filter`：**Given** 已有三种奖励状态记录，**When** 切换筛选，**Then** 只显示匹配记录且不出现关系状态或风险原因。

`APP-07-AC-record-ladder`：**Given** 第5位好友的两笔奖励均已发放，**When** 展开奖励明细，**Then** 显示完成注册20、阶梯累计5人50，合计70。

- 筛选只含全部、待发放、已发放、发放失败。
- 列表不展示关系状态、冻结、无效或风险原因。
- 第5位好友的明细可同时展示完成注册20和阶梯累计5人50两项；累计已发奖励为70。
