## 1. 模块术语

| 术语 ID | 统一术语 | 定义 |
|---|---|---|
| `M07-TERM-inviter` | 邀请人 | 已注册普通用户，通过个人分享入口或邀请链接邀请新用户 |
| `M07-TERM-invitee` | 被邀请人 | 通过普通用户或校园代理入口首次完成注册的新用户 |
| `M07-TERM-campus-agent` | 校园代理 | 后台录入的学校/校区推广合作方，奖励以奖金台账记录 |
| `M07-TERM-success-invite` | 成功邀请 | 被邀请人首次完成注册并建立唯一邀请关系；口径固定，不后台配置 |
| `M07-TERM-ladder-bonus` | 阶梯额外奖励 | 累计成功邀请人数首次等于已启用档位阈值时，额外生成的一笔奖励；不是区间内每人加奖 |
| `M07-TERM-invite-rules-h5` | 邀请规则 H5 | 从 PRD-06 `invite_rules` 预置配置加载的移动端说明页；页面内容不得改变 PRD-07 实际业务规则 |

### 1.1 统一口径

| 口径 | 结论 |
|---|---|
| 成功人数 | 固定统计已完成注册并建立关系的人数 |
| 关系有效性 | 只创建有效关系；关系永久有效，无状态字段，无人工失效/冻结操作 |
| 来源类型 | 仅普通用户、校园代理 |
| 奖励币 | 普通邀请使用千寻币；代理使用奖金金额（元） |
| 发奖异常 | 不进入风控冻结；发放失败保留失败流水，供后续技术补偿机制处理 |

> 命名说明：本项目正式名称统一为“千寻币”；历史原始 PRD 中的“成家币”均指同一资产，正式实现、接口和页面不得继续使用历史名称。

## 3. 模块状态机

### M07-SM-invite-reward（普通邀请奖励）

| 起始状态 | 事件 | 目标状态 | 前置条件 | 副作用 |
|---|---|---|---|---|
| 无 | 奖励事件或阶梯档位命中 | `pending` | 幂等键不存在 | 创建独立奖励流水 |
| `pending` | 资产服务发放成功 | `success` | 写币流水成功 | 提交成功后调用 PRD-03 创建到账系统消息 |
| `pending` | 资产服务发放失败 | `failed` | 返回失败原因 | 保留失败原因和幂等键 |
| `failed` | 技术补偿重试成功 | `success` | 使用原幂等键 | 写币流水，不重复发奖；创建到账系统消息 |
| `failed` | 技术补偿重试失败 | `failed` | — | 更新最近失败原因/时间；自动重试耗尽后创建最终失败系统消息 |

补偿策略：首次失败后由系统按 5 分钟、30 分钟、2 小时三个时间点自动重试，最多 3 次；仍失败时保持 `failed`，记录最后失败原因和时间，并允许具备 `promotion:reward:retry` 权限的人员在奖励流水页手工重试。手工重试继续复用原幂等键，不创建新奖励单。

### M07-SM-agent（校园代理）

| 起始状态 | 操作 | 目标状态 | 副作用 |
|---|---|---|---|
| `enabled` | 停用 | `disabled` | 停止建立新代理关系和新奖金记录，历史数据保留 |
| `disabled` | 启用 | `enabled` | 恢复建立新关系和计奖 |

### M07-SM-agent-settlement（代理结算单）

| 起始状态 | 操作 | 目标状态 | 副作用 |
|---|---|---|---|
| 无 | 每月 1 日 01:00 定时生成 | `pending_confirm` | 汇总上一个自然月未归集奖金；同代理+月份唯一 |
| `pending_confirm` | 确定结算 | `confirmed` | 记录确定人、确定时间；金额不可再由页面修改 |

### 3.x 废弃状态机

| 旧 ID | 状态 | 原因 |
|---|---|---|
| `M07-SM-invite-relation` | `[已废弃]` | 邀请关系无状态变化 |
| `M07-SM-agent-bonus` | `[已废弃]` | 奖金明细不维护独立结算状态机 |

## 4. 模块业务规则

### M07-RULE-invite-bind（关系绑定）

1. 入口只接受普通用户或校园代理来源。
2. 被邀请人必须是首次完成注册的新用户；注册成功时建立关系。
3. 每个被邀请人最多一条关系，关系一经建立永久有效且不可覆盖。
4. 无效来源、老用户、重复绑定、自邀请在建关系前直接拒绝，不创建“无效关系”记录。
5. 注册前同时命中普通用户和校园代理来源时，校园代理优先。

### M07-RULE-invite-success（成功邀请）

固定为“被邀请人完成注册并建立邀请关系”。资料完善、认证、首次会员、首次充值只影响各自奖励，不改变成功人数。

### M07-RULE-register-reward-required（完成注册奖励固定启用）

1. 普通邀请奖励和推广员奖励都必须包含“完成注册”奖励事件，启用状态固定为 `true`。
2. 后台状态控件必须以选中且禁用的方式展示，并明确标注“固定开启”；运营只能编辑奖励金额，不能停用或删除该事件。
3. 保存并发布时服务端必须再次校验 `register_reward.enabled=true`；请求缺失该事件或传入 `false` 时阻止发布并提示“完成注册奖励为固定业务口径，不可关闭”。
4. 该规则用于保证“好友完成注册即邀请成功”后必定进入完成注册奖励处理链路；奖励金额允许按普通邀请、推广员分别配置。

### M07-RULE-invite-ladder（阶梯额外奖励）

```text
本次注册总奖励 = 完成注册奖励金额 + 本次命中档位的阶梯额外奖励金额
本次命中档位 = 累计成功邀请人数恰好等于某个已启用阈值，且该阈值从未给该邀请人发放
未命中档位时，阶梯额外奖励 = 0
幂等键 = 邀请人ID + 来源类型 + ladderThreshold
```

配置示例（仅解释计算，不是默认值）：完成注册奖励 20；累计 5 人额外 50、累计 10 人额外 100、累计 20 人额外 200。

| 场景 | 计算 | 生成流水 |
|---|---|---|
| 第 1 人完成注册 | `20 + 0 = 20` | 完成注册奖励 20 |
| 第 5 人完成注册 | `20 + 50 = 70` | 完成注册奖励 20 + 累计 5 人阶梯额外奖励 50 |
| 第 8 人完成注册 | `20 + 0 = 20` | 完成注册奖励 20；5 人档已发过，不重复 |

普通邀请与代理奖励使用同一计算方法，分别以千寻币和元为单位。奖励模式选“固定奖励”时不计算阶梯；选“阶梯奖励”时显示档位配置并应用本规则。

### M07-RULE-reward-idempotency（奖励幂等）

- 普通事件：`relationId + eventType` 唯一。
- 阶梯事件：`inviterId/agentId + ladderThreshold` 唯一。
- 支付事件只接受 PRD-04 支付成功回调。

### M07-RULE-agent-settlement-generate（代理结算单生成）

- 时区：北京时间（Asia/Shanghai）。
- 执行时间：每月 1 日 01:00。
- 统计周期：上一个自然月 1 日 00:00:00 至月末 23:59:59。
- 汇总口径：周期内已生成且未进入其他结算单的代理奖金明细。
- 唯一约束：`agentId + settlementMonth`；重跑不得重复生成。
- 页面不提供手动生成、登记打款或打款流水字段。

### M07-RULE-invite-rules-h5（邀请规则 H5）

- 入口、页面 ID 和邀请/奖励业务规则归 PRD-07；标题、H5 URL、版本、状态和预览归 PRD-06 `M06-CFG-business-h5-links.invite_rules`。
- H5 正文必须覆盖完成注册成功口径、永久关系、五类奖励事件、阶梯命中当次额外奖励、资格限制，并与当前已发布 `M07-CFG-*` 规则一致。
- 页面打开时通过 PRD-06 H5 内容接口读取当前启用版本；加载成功后覆盖本地最近成功缓存。
- 当前版本未配置、停用或加载失败时，优先展示最近成功缓存并标注“当前内容加载失败，正在展示最近成功版本”；无缓存时展示不可用态、重试和返回，不在客户端硬编码一份完整规则冒充最新内容。
- PRD-07 奖励规则发布不自动改写 H5；上线/发布验收必须由运营核对 H5 版本与 PRD-07 规则版本。二者冲突时以实际 `M07-*` 业务规则执行，并阻止该版本通过发布验收。
