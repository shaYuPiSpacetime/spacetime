## 1. 模块目标

移动端 PRD-03 承接悄悄话申请、匹配成功后的普通私信、官方小助手和系统消息，让用户从“申请认识”进入安全、可控、可追溯的互动链路。

**用户故事：** 作为已登录用户，我想在消息 Tab 中查看官方消息、通知和可聊天对象，并在满足匹配与安全规则后发送私信或回复悄悄话，以便完成从关系反馈到真实互动的闭环。

**核心指标：** 消息 Tab 到达率、悄悄话付费发起率、悄悄话回复匹配率、匹配后私信发起率、官方消息点击率。

## 2. 用户与角色

| 角色 | 在本模块中做什么 | 引用全局角色/规则 |
|------|------------------|-------------------|
| 未登录访客 | 不能进入消息 Tab，需先登录 | `GLB-ROLE-visitor` |
| 已登录未三重认证用户 | 查看官方消息和通知中心，不能查看用户私信和发送悄悄话 | `M01-RULE-core-access`、`M03-RULE-message-tab-scope` |
| 三重认证通过用户 | 查看私信会话、发送文本消息、处理悄悄话、查看通知 | `GLB-ROLE-app-user` |
| 时空邂逅会员用户 | 可使用每日免费悄悄话次数 | `M04-CFG-vip-free-whisper-daily` |
| 被处罚/冻结用户 | 可查看处罚相关系统通知，但不可继续聊天 | `M03-RULE-conversation-invalid` |

## 3. 关键业务流程

### 3.1 匹配成功后普通私信流程

```text
入口：消息中心会话列表为主入口；匹配成功回流、相互喜欢列表、社区动态/评论/用户主页已匹配态为辅助入口
正常路径：
  1. 用户点击聊天入口
  2. 后端校验双方均满足 `M01-RULE-core-access`、账号正常、未拉黑、`M02-SM-mutual-match=matched`
  3. 创建或打开 `M03-SM-conversation=active` 会话
  4. 用户进入 `APP-03-PAGE-private-chat`
  5. 若未命中女性保护机制，底部输入框可发送文本消息
异常：
  - 未匹配成功：提示相互喜欢后才能聊天
  - 男方命中女性保护：输入框置灰，等待女方先发送真实消息
  - 任一方账号异常/拉黑：历史可看，会话不可发送
出口：继续聊天、查看主页、举报或拉黑
```

### 3.2 悄悄话破冰流程

```text
入口：推荐页推荐卡片/推荐详情为主入口；社区动态、评论区、用户主页未匹配态为辅助入口
正常路径：
  1. 按 `M03-RULE-contact-entry-routing` 校验关系；已匹配直接进入普通私信，未匹配进入悄悄话流程
  2. 校验登录、三重认证、账号、处罚、拉黑、重复待回应和到期冷却；任一失败均不进入扣费
  3. 发送方填写 1～60 字内容并通过内容安全检测
  4. 展示免费次数或千寻币消耗；用户确认后进入 `M03-SM-whisper-payment=paying`
  5. 权益核销/扣费与消息创建均成功后写入 `M03-SM-whisper=pending`，接收方在消息中心收到悄悄话卡片
  6. 接收方从“申请我的”列表进入详情，可直接回复；不单独提供“暂不回应”按钮，未处理状态到期后自动结束
  7. 接收方回复：原子完成回复落库、`M03-EVT-whisper-replied`、PRD-02 `whisper_reply` 匹配和普通私信会话创建
  8. 发送满 7 天未回复：后台定时任务或延迟队列自动转 `expired`，并从到期时间起进入 7 天冷却；列表弱化展示“申请已结束”
  9. 原接收方在过期详情点击“申请认识”时，反向新建一条悄悄话并重新执行权益校验与付费
异常：
  - 存在同对象待回复悄悄话：不允许重复发送
  - 存在同对象待回复申请：打开原申请详情，不重复展示付费入口
  - 余额不足：唤起 PRD-04 充值引导
  - 内容安全失败、资格失效：不扣费、不创建悄悄话
  - 已扣费但消息创建失败、未有效送达或平台主动下架：进入 `refunding` 并原路补回权益
  - 任一方拉黑、处罚或账号异常：状态转 `invalid`，发送方不看到具体原因
发送方等待态：
  - 在“我申请的”列表查看申请记录和弱化状态
  - 不可编辑、撤回、补发、连续追问，不展示对方已读
出口：回复后进入普通私信；超时/取消/失效后本次结束；原接收方可反向发起新悄悄话
```

### 3.3 官方小助手与系统消息流程

```text
入口：消息列表固定“官方小助手”“系统消息”会话
正常路径：
  1. 官方小助手低频发送功能介绍、安全规则、帮助入口和服务号关注引导
  2. 系统消息发送社区热点、精选内容、活动和重要公告
  3. 用户点击固定会话后直接进入全文消息流，不经过通知列表或通知详情页
  4. 进入会话后将该会话消息置已读；页面不提供类型筛选和全部已读
异常：
  - 微信订阅消息未授权：不影响站内通知落库
  - 模板停用：通知生成失败需后台可查错误
```

## 4. 核心数据模型

### 4.1 实体清单

| 实体 | 表名（建议） | 说明 | 所属模块 | 关键字段 |
|------|-------------|------|----------|----------|
| 私信会话 | `message_conversation` | 匹配成功后创建的普通私信会话 | 03 | conversationNo, userAId, userBId, matchNo, status, lastMessageTime |
| 私信消息记录 | `message_record` | 私信会话内文本与系统提示 | 03 | messageNo, conversationNo, senderUserId, receiverUserId, messageType, sendStatus |
| 悄悄话申请 | `message_whisper` | 匹配前独立申请；回复后才创建匹配和私信会话 | 03/04 | whisperNo, senderUserId, receiverUserId, status, payType, expireTime, cooldownExpireTime |
| 官方/系统消息 | `message_official_feed` | 官方小助手和系统消息全文记录 | 03 | feedNo, userId, channelType, title, content, readStatus, actionType |
| 未读汇总 | `message_unread_summary` | 消息 Tab 红点和分组未读 | 03 | userId, privateUnreadCount, whisperUnreadCount, assistantUnreadCount, systemUnreadCount |

### 4.2 实体关系

```text
用户 1──N 会话（userAId/userBId）
会话 1──N 消息记录
用户 1──N 悄悄话申请（senderUserId/receiverUserId）
悄悄话申请 0──1 匹配记录（仅 replied 后创建，归 PRD-02）
匹配记录 1──1 私信会话
用户 1──N 官方/系统消息
```

### 4.3 跨模块字段引用

| 本模块使用字段 | 来源模块 | 来源实体 | 若来源模块未上线如何处理 |

| 三重认证状态 | PRD-01 | 用户认证状态 | 私信和悄悄话入口展示认证引导 |
| 匹配成功状态 | PRD-02 | 相互喜欢/匹配成功记录 | 普通私信入口隐藏或置灰 |

## 9. 非功能性需求

### 9.1 权限与安全

| 场景 | 要求 |
|------|------|
| 私信/悄悄话 | 必须服务端校验核心准入、匹配状态、拉黑、处罚、女性保护，不依赖前端控制 |
| 消息内容 | 文本内容入库前需走内容安全检测；违规进入举报/审核联动 |
| 官方/系统消息 | 只能查看属于当前用户的消息流 |
| 历史消息 | 用户侧只可查看自己参与的会话 |

### 9.2 性能

| 场景 | 要求 |
|------|------|
| 消息列表 | 首屏 20 条以内，常规网络 800ms 内返回 |
| 私信历史 | 默认定位最新消息，上滑每次加载 20 条 |
| 官方/系统消息流 | 默认 20 条分页，进入页面 800ms 内返回 |
| 未读汇总 | Tab 红点接口 300ms 内返回，允许缓存 30 秒 |

### 9.3 并发与幂等

| 操作 | 幂等要求 |
|------|----------|
| 发送文本消息 | 客户端幂等 key + 服务端去重，重复提交不产生多条消息 |
| 标记已读 | 重复调用返回成功，不重复扣减未读 |
| 发送悄悄话 | 同一发送方+接收方存在 pending 时禁止新增 |
| 回复悄悄话 | 同一 whisperNo 只能从 pending 流转一次到 replied |
| 悄悄话到期任务 | 按 whisperNo 幂等执行；重复消费只返回 `expired` 与既有冷却截止时间，不重复延长冷却 |
| 悄悄话支付 | 客户端幂等 key 贯穿资格复校验、扣费和消息创建，重复点击只扣费一次 |
| 悄悄话退款 | 同一支付流水只允许成功补偿一次，重复回调返回当前退款状态 |

## 10. 验收总则

```text
AC-ID: APP-03-AC-message-auth-guide
Given 用户已登录但未完成实名、头像、学历任一认证
When  用户进入消息列表页
Then  页面展示官方消息与通知入口，不展示用户私信会话，并展示认证引导文案 `M03-TXT-core-access-chat-block`

AC-ID: APP-03-AC-private-chat-open
Given 双方三重认证通过、账号正常、未拉黑且 `M02-SM-mutual-match=matched`
When  任一方点击聊天入口
Then  系统打开 `M03-SM-conversation=active` 会话，输入框可发送文本消息

AC-ID: APP-03-AC-female-protection
Given 男方和女方刚匹配成功且处于 `M03-CFG-female-protection-days` 保护期内，女方未发送真实用户消息
When  男方进入私信对话页
Then  输入框置灰，展示 `M03-TXT-female-protection-block`，发送接口返回 `M03-ERR-female-protection-blocked`

AC-ID: APP-03-AC-whisper-reply-match
Given 接收方收到状态为 `pending` 的悄悄话
When  接收方点击回复并发送成功
Then  回复落库、悄悄话变为 `replied`、PRD-02 生成 `whisper_reply` 匹配和普通私信会话创建原子完成；该回复视为真实用户消息，不再触发女性保护禁发

AC-ID: APP-03-AC-whisper-expire-cooldown
Given 接收方收到状态为 `pending` 的悄悄话
When  连续 7 天未回复且后台到期任务执行
Then  状态幂等变为 `expired`，双方不匹配且费用不退；从到期时间起进入 7 天冷却，移动端只弱化展示“申请已结束”

AC-ID: APP-03-AC-system-message-fulltext
Given 用户已登录并位于消息首页
When  用户从消息首页点击系统消息
Then  直接进入全文消息流，不展示类型筛选、全部已读或独立通知详情页
```
