- **页面 ID**：`APP-05-PAGE-post-publish`
- **所属模块 PRD**：`模块PRD_APP-05_推荐模块（朋友、社区与内容互动）`
- **页面路由**：`/pages/qianxun/community/publish`
- **入口来源**：千寻 -> 成家 -> 发布按钮、千寻 -> 知音 -> 诚意贴发布入口
- **对应设计稿**：[蓝湖“发布动态”与“发布动态-诚意贴”](https://lanhuapp.com/web/#/item/project/stage?tid=428e8368-c279-4369-947b-a5828487924d&pid=d9c9e50f-fee5-47ca-bd6b-ae05c0d5332b)；两类内容仅由入口带入不同 `contentType`，表单结构一致
- **对应移动端 / 技术方案**：`MVP-PAGE-005`

## 1. 页面定位

- **目标用户**：满足 `M05-RULE-interaction-gate` 的用户
- **核心任务**：填写动态或诚意贴内容并提交审核
- **页面类型**：表单页

| AC ID | 场景 | 类型 | 优先级 |

| `APP-05-AC-publish-abandon` | 放弃编辑后清草稿并刷新来源列表 | 正常 | P0 |
| `APP-05-AC-publish-image-grid` | 图片九宫格展示计数、缩略图和删除 | 正常 | P0 |
| `APP-05-AC-publish-topic-required` | 未选话题不能发布 | 异常 | P0 |

| `APP-05-AC-publish-gate` | 未满足互动门槛时引导认证 | 异常 | P0 |

## 11. 蓝湖反向缺口补充

### 11.1 图片上传状态

单图 `uploadStatus` 取值为 `queued/uploading/success/failed`。上传中显示进度；失败显示重试和删除；仅 `success` 图片进入提交 payload。任一图片为 uploading/failed 时发布按钮禁用并提示 `M05-ERR-upload-incomplete`。“上传成功”只表示文件完成上传，不表示动态已提交、审核通过或公开。

### 11.2 草稿

- 自动保存触发：正文、话题或图片成功结果变更后 2 秒防抖；每个 `contentType` 最近 1 份。
- 再次进入同类型发布页时直接恢复最近草稿，不新增恢复确认画板。
- 点击放弃/取消时清除当前类型草稿，直接返回并刷新来源列表，不展示确认弹窗或额外状态。
- 已失效话题自动清空并提示重选，失败图片不恢复；服务端确认内容创建后删除对应草稿。
- 图片上传中、上传失败分别使用 `APP-05-publish-07`、`APP-05-publish-08`。

验收：草稿不会自动发布；“上传成功”仅作为单图上传反馈，动态审核状态只在“我的动态”卡片展示；页面和草稿均不包含 @Ta 或标题数据。

### 11.3 发布失败反馈

- 仅在内容记录未创建时展示；提交成功、待复核和异步驳回不使用该反馈。
- 视觉复用蓝湖“千寻-成家-热门-发布失败”中央半透明灰色反馈层，不新增独立页面；标题固定为“发布失败”，第二行展示具体失败原因。
- 失败原因优先使用业务可理解文案，例如“请选择话题”“正文内容不能为空”“图片尚未上传完成”“内容中包含不支持的联系方式”或“网络异常，请稍后重试”，不得直接展示技术异常栈或原始接口报错。
- 反馈自动消失但表单、已成功上传图片和草稿内容全部保留，用户可直接修正或重试。
