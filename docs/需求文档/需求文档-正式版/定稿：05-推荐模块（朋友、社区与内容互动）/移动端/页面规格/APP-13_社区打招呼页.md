- **页面 ID**：`APP-05-PAGE-community-greeting`
- **所属模块 PRD**：`模块PRD_APP-05_推荐模块（朋友、社区与内容互动）`
- **页面路由**：无独立路由；从来源页打开底部弹窗
- **入口来源**：信息流作者区、动态详情作者区、个人动态区、社区更多操作
- **对应设计稿**：蓝湖 `YO悄悄话-弹窗`、`YO悄悄话-弹窗-文字点亮`
- **对应移动端 / 技术方案**：`MVP-PAGE-010`、`M03-RULE-whisper-send`

## 1. 页面定位

- **目标用户**：已登录且满足核心准入的用户
- **核心任务**：从社区场景向目标用户发送悄悄话式招呼
- **页面类型**：底部表单弹窗

## 6. 数据联动规则

| 触发字段 | 触发事件 | 影响字段 | 联动行为 | 备注 |
|----------|----------|----------|----------|------|
| 悄悄话内容 | 输入 | 字数统计/发送按钮 | 0 字或超过 60 字时发送按钮不可提交；1-60 字时进入可发送态 | UI 点亮态以蓝湖为准 |
| payType/cost | 弹窗打开 | 资产提示/发送按钮 | 展示模块 08 返回的免费次数或千寻币消耗；蓝湖中的 100 仅为展示示例 | 引用 PRD-04/模块 08 |
| whisperStatus | pending | 操作区 | 展示等待对方回复，隐藏发送按钮 | `M03-RULE-whisper-repeat-limit` |
| balance | 不足 | 操作区 | 调用模块 08 余额不足与充值入口 UI | PRD-04 提供余额规则，模块 08 提供界面 |
| 目标用户状态 | 异常 | 页面整体 | 禁用发送，展示目标不可用 | `M05-ERR-community-target-unavailable` |

|----------|----------|----------|----------------|------|

## 9. 验收标准

| AC ID | 场景 | 类型 | 优先级 |
|-------|------|------|--------|
| `APP-05-AC-community-greeting-send` | 发送社区打招呼 | 正常 | P0 |
| `APP-05-AC-community-greeting-content-limit` | 悄悄话正文只允许 1-60 字并实时展示字数 | 正常 | P0 |
| `APP-05-AC-community-greeting-pending` | 已有待回复悄悄话不可重复发送 | 异常 | P0 |
| `APP-05-AC-community-greeting-quota` | 余额或次数不足时拦截 | 异常 | P0 |

```
AC-ID: APP-05-AC-community-greeting-send
Given 用户已登录、满足核心准入，目标用户正常可见，且符合 `M03-RULE-whisper-send`
When  输入 1-60 字悄悄话并点击“发送悄悄话”
Then  系统触发 PRD-03 悄悄话发送，记录社区来源上下文，并提示等待对方回复
```

```
AC-ID: APP-05-AC-community-greeting-content-limit
Given 用户已打开 `YO悄悄话-弹窗`
When  输入为空、超过 60 字或处于 1-60 字范围
Then  页面实时展示字数；仅 1-60 字可提交，发送时按弹窗已展示的免费次数或千寻币消耗执行
```

```
AC-ID: APP-05-AC-community-greeting-pending
Given 用户对同一目标已有状态为 pending 的悄悄话
When  从社区入口再次打开 `YO悄悄话-弹窗`
Then  页面展示等待对方回复提示，不展示发送按钮
```

## 11. “申请认识”文案别名

蓝湖中的“申请认识”不是新的关系类型。未建立互动关系时，入口携带 `standardAction=greeting` 进入本页；资格、免费次数/千寻币消耗、重复发送和目标不可用反馈复用 PRD-03 与模块 08。对方回复并建立互动关系后，来源页隐藏“申请认识”，头像/昵称进入 `APP-05-PAGE-user-posts` 他人主页，显式消息动作直接进入 `APP-03-PAGE-private-chat`。
