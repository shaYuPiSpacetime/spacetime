## 1. 模块目标

为完成核心准入的用户提供可理解、可主动控制的一期婚恋候选发现方式：推荐 Tab 按位置、年龄和会员高级条件展示候选卡片；理想型 Tab 允许用户组合资料与标签条件进行更精准筛选，并通过 PRD-04 完成结果解锁。

**用户故事：** 作为完成资料和三项认证的用户，我想设置明确的择偶条件并查看符合条件的异性，以便在没有测评和复杂推荐模型的情况下高效发现合适对象。

**一期成功指标：** 推荐首屏成功率、筛选保存成功率、理想型筛选结果非空率、理想型结果解锁转化率；指标只用于埋点观察，不用于一期排序。

## 2. 用户与角色

| 角色 | 在本模块中做什么 | 权限来源 |
|------|------------------|----------|
| 未完成核心准入用户 | 只能看到资料与认证拦截，不读取真实候选 | PRD-01 `M01-RULE-core-access` |
| 普通用户 | 使用基础筛选、推荐、理想型筛选和千寻币解锁 | `APP-08_端内定义.md` |
| 时空邂逅会员 | 在普通能力上增加高级筛选和三天回放 | PRD-04 `advanced_filter` / `three_day_replay` |

## 3. 关键业务流程

### 3.1 推荐流程

```text
荐入口
-> 校验登录、核心准入和账号状态
-> 读取筛选偏好；无保存记录则生成现居城市 + 年龄±5岁的前端默认值
-> 候选池应用异性、三项认证、账号/关系安全过滤
-> 应用位置、年龄；会员再应用有效高级条件
-> 按最近活跃时间倒序返回稳定游标分页
-> 用户查看详情 / 喜欢 / 悄悄话 / 跳过
-> 本轮无候选或商业化服务返回剩余浏览数为 0时进入等待页
```

分支与异常：

- 普通用户点击高级筛选，唤起 PRD-04 VIP 引导，不改变已保存基础条件。
- 推荐精确城市不足 20 条时，仅在用户开启“周边城市”后补入邻接城市。
- 字典不可用时保留上次成功结果；筛选设置进入只读降级态，不允许保存未知 code。
- 候选在浏览时冻结、注销、拉黑或认证失效，当前卡片移除并继续下一条，不暴露失效原因。

### 3.2 理想型流程

```text
切换理想型 Tab
-> 回显共享位置、年龄和上次理想型条件
-> 用户选择外在、教育、经济、家庭、兴趣、感情条件
-> 依赖本人资料的条件先校验学校/兴趣/感情观
-> 点击“选好了”
-> 所有已选条件按 AND 生成筛选快照
-> 进入模糊结果页
-> 单个或最多 5 个批量选择
-> 调用 PRD-04 千寻币扣费与解锁
-> 解锁成功查看公开资料；筛选记录与历史解锁分别可追溯
```

分支与异常：

- 理想型不自动补周边城市，也不自动移除任何已选条件。
- 0 候选时保留条件并引导返回修改；不展示“为你放宽了条件”。
- 本人学校、兴趣或感情观缺失时，对应条件不可选并跳转 PRD-01 编辑资料。
- 支付失败、余额不足、并发解锁或候选失效均由 PRD-04 返回明确结果；失败不清空勾选。

### 3.3 筛选偏好同步

推荐筛选设置页与理想型 Tab 共用位置、年龄。保存操作使用版本号乐观锁；任一入口保存成功后两个 Tab 都刷新为新版本。会员高级条件不与理想型条件互相覆盖。

## 4. 核心数据模型

### 4.1 实体清单

| 实体 | 建议表名 | 说明 | 关键字段 |
|------|----------|------|----------|
| 筛选偏好 | `ct_recommend_preference` | 当前用户唯一有效的共享基础与推荐高级条件 | `userNo, targetCityCodes, allowNeighborCity, ageRange, advancedFilters, version` |
| 理想型快照 | `ct_ideal_filter_snapshot` | 每次“选好了”的不可变条件摘要 | `snapshotNo, userNo, preferenceVersion, conditionCodes, resultCount, status, expiresAt` |
| 快照候选 | `ct_ideal_snapshot_candidate` | 保证历史结果可回看与分页稳定 | `snapshotNo, candidateNo, sortTime, sortTieBreaker` |
| 推荐浏览记录 | `ct_recommend_view_log` | 回看、曝光去重和操作追溯数据源 | `userNo, candidateNo, scene, action, viewedAt` |

### 4.2 实体关系

```text
用户 1──1 筛选偏好
用户 1──N 理想型快照
理想型快照 1──N 快照候选
用户 1──N 推荐浏览记录
快照候选 N──1 PRD-01 用户公开资料
解锁操作 N──1 PRD-04 理想型解锁记录
```

### 4.3 跨模块字段引用

| 本模块使用内容 | 来源模块 | 未就绪/不可用兜底 |
|----------------|----------|-------------------|
| 核心准入、性别、账号、资料字段与学校/标签 code | PRD-01 | 核心准入不可用则阻断真实候选；单个筛选字段缺失按不满足 |
| 喜欢、匹配、场景屏蔽与关系来源 | PRD-02 | 关系状态不可用时不允许互动，候选查询失败而非默认放行 |
| VIP 高级筛选、额外浏览、三天回放、千寻币理想型解锁 | PRD-04 | 权益查询失败按普通用户；扣币服务失败禁止解锁，不创建假成功记录 |
| 我的资料编辑与用户公开主页 | PRD-01/PRD-06 | 依赖字段缺失时引导完善；主页不可用时停留当前页 |
| 悄悄话 | PRD-03/PRD-04 | 服务或额度不可用时展示付费/稍后重试，不影响候选浏览 |

## 6. 边界（本期不做）

| 不做能力 | 原因 | 本期处理 | 后续 |
|----------|------|----------|------|
| 测评或人格特征参与推荐 | 测评模块移出一期 | 不读取、不展示入口 | 后续重新立项 |
| 推荐模型、评分、权重与解释 | 一期改为固定条件 | 接口不返回分数/解释 | 数据成熟后另立 PRD |
| 精选 Tab | 与双 Tab 结构冲突 | 历史入口隐藏 | 产品重新定义后承接 |
| 认证状态筛选 | 候选已全部三项认证通过 | 页面不展示该区块 | 核心准入规则变化时重评 |
| 高颜值、收入可观 | 无确认字段与客观规则 | 理想型不展示按钮 | 补字段和规则后评估 |
| 理想型关键词搜索 | 会引入模糊匹配和不可解释规则 | 不展示搜索框 | 二期另立搜索方案 |
| 推荐/理想型独立后台 | 复用现有字典和商业化配置 | 不新增菜单、权限或页面 | 需要运营策略时另立 |

## 10. 非功能性需求

### 10.1 权限与安全

- 所有真实候选接口要求登录、核心准入通过、账号正常；客户端隐藏不能替代服务端鉴权。
- 未解锁理想型结果不得返回清晰头像、昵称、学校名称或联系方式；支付成功后仍只返回 PRD-01 当前有效公开资料。
- 筛选日志不记录候选原始敏感字段；字段用于筛选的目的需纳入隐私政策。

### 10.2 性能与可靠性

- 推荐首屏 P95 < 800ms；理想型搜索 P95 < 1500ms；单页固定 20 条。
- 候选有效性缓存最长 60 秒，冻结/注销/拉黑/认证失效必须在下页或详情请求实时复核。
- 筛选保存采用版本号乐观锁；理想型筛选采用客户端幂等 key；解锁幂等完全引用 PRD-04。
- 字典加载失败不得把 code 当中文直接展示，不得清空用户已保存条件。

### 10.3 埋点

| 事件 | 触发 | 参数 |
|------|------|------|
| `recommend_page_view` | 进入双 Tab 主页面 | `tab, filterVersion, vipEffective` |
| `recommend_filter_open` | 点击推荐筛选图标 | `sourceTab` |
| `recommend_filter_save` | 保存成功/失败 | `basicCount, advancedCount, result` |
| `recommend_candidate_view` | 卡片进入可见区 | `candidateNo, position, scene` |
| `ideal_condition_select` | 选择/取消理想型条件 | `conditionCode, selected` |
| `ideal_search_submit` | 点击选好了 | `conditionCodes, result` |
| `ideal_unlock_start/result` | 发起/完成解锁 | `sceneCode, batchSize, result`；金额由 PRD-04 记录 |

## 12. 上线、迁移与回滚

| 项 | 说明 |
|----|------|
| 存量偏好 | 只迁移能明确映射的位置、年龄、身高、体重、学历、家乡、学校、专业；算法权重和测评特征丢弃 |
| 老用户默认 | 无有效偏好时使用现居城市与年龄 ±5 岁临时默认值，用户保存后才落库 |
| 老版本兼容 | 历史觅缘路由跳推荐 Tab，历史理想型路由跳理想型 Tab；旧接口不再返回评分字段 |
| 灰度 | 内部账号 -> 5% -> 20% -> 全量；每阶段检查准入泄漏、筛选准确性、支付和隐私日志 |
| 回滚 | 回滚页面入口与接口路由，不删除筛选偏好、快照、浏览记录或 PRD-04 解锁记录 |
| Mock 隔离 | 生产构建禁止启用候选 mock、固定用户编号或绕过核心准入开关 |
