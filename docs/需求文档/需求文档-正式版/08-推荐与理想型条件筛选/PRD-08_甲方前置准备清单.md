# PRD-08 推荐与理想型条件筛选 - 甲方前置准备清单

|------|------|--------|----------|

## 1. P0 上线前必须提供

| 编号 | 准备项 | 验收要求 | 缺失影响 | 临时处理 |
|------|--------|----------|----------|----------|
| `M08-PREP-01` | 推荐 + 理想型双 Tab 正式设计稿 | 覆盖主页面、推荐筛选、空态、VIP 锁定、理想型结果模糊态、解锁确认、筛选记录、历史解锁 | 无法完成设计一致性验收 | PRD 可评审，不能宣称达到生产 UI 门禁 |
| `M08-PREP-02` | 学校分类数据 | 每个学校使用稳定业务 code，并提供 `985/211` 分类；重复、合并、改名学校需有映射 | “985/211”条件不可用 | 该条件隐藏，不允许按学校名称猜测 |
| `M08-PREP-03` | 个人标签字典 | 提供 6.2.1 中稳定 code、`interest` 和 `relationship_view` 分组及用户可选文案 | 多个理想型条件不可判定 | 对应条件置灰并引导稍后再试 |
| `M08-PREP-04` | 城市邻接数据 | 中国大陆城市业务 code 及邻接关系，明确直辖市、省直管县等边界 | 推荐“周边城市”不可用 | 自动关闭周边城市补足，不影响精确城市筛选 |
| `M08-PREP-05` | 隐私政策更新 | 明示位置、年龄、身高体重、教育、家乡、学校专业、住房购车和标签用于推荐/理想型条件筛选 | 合规阻塞 | 不开放 PRD-08 真实数据筛选 |

## 3. 数据质量检查

| 检查项 | 通过标准 | 不通过处理 |
|--------|----------|------------|
| 核心准入 | 候选接口只返回 `M01-RULE-core-access` 通过用户 | 阻断灰度 |
| 学校业务 code | 同一学校别名映射到同一 code | 校友和 985/211 条件关闭 |
| 标签冲突 | 结构化住房/购车与旧标签冲突可识别 | 结构化字段优先，记录清洗清单 |
| 地区层级 | 目标城市、现居地、家乡、户口均能映射统一地区 code | 不提供字符串模糊匹配 |
| 敏感字段缺失 | 空值比例有统计且不会被默认填充 | 按不满足处理并在空结果分析中单独统计 |

## 4. 明确不需要准备

- 不需要测评题库、测评结果或特征映射。
- 不需要模型训练数据、模型文件、算法参数或版本回滚方案。
- 不需要 PRD-08 独立管理后台菜单或推荐效果 BI 看板。
- 不需要“高颜值”“收入可观”的计算或运营名单。
