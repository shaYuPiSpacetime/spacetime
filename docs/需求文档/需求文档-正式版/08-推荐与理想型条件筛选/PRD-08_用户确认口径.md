## 1. 模块定位

一期删除测评量表与复杂推荐算法，PRD-08 调整为移动端「推荐 + 理想型」双 Tab 模块，使用明确、可解释的条件筛选完成候选人匹配。

- 「推荐」：面向日常浏览，展示候选人卡片，并支持基础筛选与 VIP 高级筛选。
- 「理想型」：面向更明确的择偶诉求，通过预置条件标签组合筛选；筛选免费，查看清晰结果需要消耗千寻币解锁。
- 一期不建设独立的“推荐算法配置”管理后台，不提供权重、排序、测评、机器学习或运营算法编排能力。

## 2. 候选准入与浏览者认证规则

- 候选人进入候选池继续沿用 PRD-01 三项核心认证准入：实名认证、头像认证、学历认证。参考图中的“人脸认证”只作为旧版筛选示意，不改变 PRD-01 已定稿的头像认证口径。
- 推荐筛选中删除“认证状态”条件，不允许用户用认证类型二次筛选候选人。
- 浏览者已登录、账号正常且已完成进入时要求的基础资料，即可浏览推荐、候选详情、跳过、编辑筛选、执行理想型查询及使用记录/解锁相关非关系动作；不得因为浏览者本人尚未完成三项认证而阻断 PRD-08 主流程。
- 浏览者点击“喜欢”或“悄悄话”时，服务端实时校验 PRD-01 三项认证。未完成时弹出未认证提示；完成认证返回原候选人，不自动补发原操作，用户需再次点击。

## 3. 推荐 Tab

### 3.1 基础筛选

- 地理位置：按候选人现居地匹配；默认当前用户所在城市，至少保留 1 个、最多选择 3 个城市。达到 3 个时隐藏添加入口，删除后重新显示；草稿为 0 个城市时禁止保存并提示“请至少选择一个城市”。
- 年龄：按候选人出生日期实时计算年龄后匹配。
- “嘉宾不足时允许推荐周边城市”仅作用于推荐 Tab；关闭时严格按已选城市匹配。

### 3.2 VIP 高级筛选

- 身高
- 体重
- 学历
- 家乡
- 学校
- 专业

非 VIP 可以查看高级筛选入口和字段，但不能编辑；点击高级筛选区域内任一内容直接进入 PRD-04“时空邂逅会员”页面。开通后返回筛选页，重新查询会员权益，高级条件转为可编辑，当前基础筛选草稿完整保留。地理位置与年龄不受 VIP 限制。

### 3.3 推荐行为

- `推荐-首屏`就是推荐首页第一顺位状态：首页仅展示一张候选摘要卡，不在首页展开长资料；点击候选卡进入 APP-04 详情。
- 首页不新增“当前条件摘要”，目标城市、年龄范围和高级条件数量不直接占用首屏；调整筛选沿用蓝湖右上角筛选入口。
- 首页底部操作沿用蓝湖：跳过、悄悄话、喜欢；“详情”不是独立底部按钮，由点击候选卡承接。
- 左滑等同跳过，右滑等同喜欢；悄悄话只响应点击，不绑定滑动手势。操作成功后展示下一张，失败时当前卡片回位并提示。
- 推荐加载或动作请求遇到网络失败时，只使用 Toast 提示“网络错误”，保留当前页面、候选卡及已编辑草稿；不新增独立错误页或单独“重试”按钮，用户再次触发原操作即重试。
- 未完成三项认证的浏览者仍可查看候选卡、详情和使用跳过；点击喜欢或悄悄话时弹出认证提示，认证成功返回后停留原候选人，不自动执行喜欢或悄悄话。
- 蓝湖稿没有“匹配分”“推荐解释”或“测评标签”；此前相关差异判断作废。“我的标签”是候选人公开资料，继续保留。
- `可信度 92%`位于详情页“我的认证”区域，不是匹配分。由于一期没有百分比计算、数据来源及申诉口径，删除百分比，仅保留真实、头像、学历等认证徽章。
- 保留推荐回看和筛选记录能力；具体权限与商业规则以页面规格为准。
- 见面偏好页移出 PRD-08：推荐 Tab 不展示入口，不注册 `/pages/recommend/meeting-preference/index`，PRD-08 不提供查询/保存接口，也不读取相关资料参与推荐或理想型筛选。
- 推荐候选不足时，仅可按用户开关补充周边城市；不得自动放宽年龄、认证准入或 VIP 高级条件。
- 候选展示后才失效时：用户执行跳过/左滑，不提示原因，直接切换下一位；执行查看详情、喜欢、悄悄话或更多操作时，提示“该用户已注销”后切换下一位。服务端不得区分展示注销、冻结、认证失效等内部原因。
- 悄悄话完成认证、付费并发送成功后，进入 PRD-03 对应候选人的悄悄话会话页，不跳到通用消息首页。
- 推荐无候选时使用蓝湖 `推荐-筛选未找到合适的人`：文案“当前条件下暂未找到推荐人”，按钮“去千寻同城看看”，进入 PRD-05 千寻同城页；该状态不再同时提供“调整筛选/稍后重试”按钮。

### 3.4 详情资料展示与隐私

- 蓝湖 `推荐` 长页中的“填写后可查看”覆盖音乐人、歌曲、理想型、恋爱期待和空闲时间等资料；`推荐-信息完善`是同一详情页在资料可见时的另一状态，不是推荐首页之后新增的一页。
- 一期删除“查看者先填写自己的同类资料，才能查看候选人资料”的互惠解锁限制。
- 候选字段是否展示，只取决于候选人是否填写、是否允许公开以及账号/资料是否有效；不得再根据查看者自己的资料完善度锁住候选内容。
- 候选人未填写或设为不公开时，该区块隐藏或按页面规格展示空态，不得泄露私密字段。
- 更多操作包含“举报用户”和“不再推荐”；举报具备原因选择、提交中、成功与失败反馈；不再推荐必须二次确认，成功后返回首页并切换下一位。
- “不再推荐”仅从 PRD-08 推荐和理想型实时结果中剔除，不等同拉黑，不影响消息、双方主页或动态；蓝湖 `推荐/不看他弹窗`中描述全局阻断的文案及“重新发送”按钮必须修正。

### 3.5 推荐回看

- APP-06 以蓝湖 `三天回看`、`三天回看-已开通会员`为准，不改造成精细行为流水。
- 普通用户展示会员权益说明和开通入口；会员用户展示最近三天的日期分组。
- 每个日期组展示“推荐 N 人 / 跳过 N 人”的当日汇总；有记录时展示头像、昵称、出生年份、城市、职业和“查看”，无记录时展示“这一天你没来，无推荐嘉宾”。
- 不要求展示精确查看时间、最近动作、是否喜欢，也不在列表中提供喜欢/取消喜欢操作。
- 回看权益到期直接展示未开通/购买会员状态；失效候选直接从列表隐藏；点击“查看”失败时提示“查看失败，请返回后重新查看”，保留当前回看页。
- 达到浏览上限时展示服务端返回的北京时间绝对重置时间，不增加实时倒计时；普通用户展示会员入口，会员用户隐藏会员入口。

## 4. 理想型 Tab

### 4.1 基础筛选

- 地理位置：按候选人现居地匹配。
- 年龄：按候选人出生日期实时计算年龄后匹配。
- 地理位置与年龄和推荐 Tab 共用当前筛选值；任一入口保存后，另一入口展示最新值。
- 理想型筛选不启用周边城市扩展，也不自动放宽任何已选条件。

### 4.3 组合与缺失值规则

- 不同字段之间使用 AND：候选人必须同时满足所有已选条件。
- 同一结构化字段存在多个可选值时使用 OR：命中任一已选值即可。
- 候选人关键字段为空、标签缺失或无法识别时，该条件判定为不命中，不得推测或默认通过。
- 依赖当前用户资料的条件（如校友、兴趣相似、感情观相合）在当前用户资料不足时直接不展示，不使用置灰、缺失原因或“去完善资料”入口；某分类无任何可展示条件时，整个分类不展示。
- 当前用户完善资料后返回理想型 Tab，重新计算并展示可用条件，但不自动选中新增可见条件。
- “本地人”的目标城市取理想型筛选当前选中的现居地城市；多城市时命中任一目标城市即可。

### 4.4 结果与解锁

- 选择和执行理想型筛选免费。
- 未解锁结果以脱敏、模糊卡片展示，不得泄露头像、昵称或可识别个人信息。
- 支持单人解锁与批量解锁；批量单次最多选择 5 人。
- 解锁消耗千寻币，VIP 不豁免；价格、余额校验、扣减及失败处理复用 PRD-04 商业配置与交易能力。
- 扣币前必须展示确认信息；余额不足时引导充值；扣币成功后展示清晰资料并写入历史解锁记录。
- 保留理想型筛选记录与历史解锁记录入口。

## 5. 后台与配置边界

- PRD-08 一期不提供独立管理后台页面和算法配置 CRUD。
- 城市、学历、学校层级、专业、标签、脱单目标等枚举复用系统字典或对应资料模块的稳定编码。
- 理想型单人/批量解锁价格、千寻币余额与订单流水复用 PRD-04 商业配置及交易能力。
- 管理后台如需展示模块边界，仅允许提供只读说明与既有配置入口跳转，不得形成新的算法配置中心。

## 6. 明确排除项

- 测评量表、性格测评、测评相似度。
- 推荐权重、排序分、推荐算法参数、机器学习模型。
- “高颜值”“收入可观”等一期无稳定字段或无可审计口径的筛选项。
- 推荐筛选中的认证状态条件。
- 理想型条件的自动放宽、默认猜测或隐式兜底。
- 独立 PRD-08 管理后台。
- 见面偏好页及其入口、路由和 PRD-08 查询/保存接口；PRD-01 若保留相关资料字段，由 PRD-01 自身范围承接。

## 7. 公共组件与状态稿口径

- 当前蓝湖“推荐”分组为 32 张 UI 稿，已覆盖 8 个有效页面；本轮新增的无候选、筛选返回确认、举报、不再推荐和提交成功均是现有页面内状态，不新增页面。
- 蓝湖“缺省页-切图”提供 9 张可复用 PNG 素材，属于公共插图资产，不计入 32 张页面稿。无候选、无记录、加载失败、网络错误和搜索无结果按实际场景选择插图；标题、说明、按钮继续使用真实组件绘制。
- 全局复用一套移动端公共状态组件：首屏骨架、局部加载、按钮提交中、服务错误、通用成功/失败提示、通用确认弹窗和图片加载失败占位；不为这些状态分别新增整页画板。推荐动作的网络失败按第 3.3 节直接 Toast“网络错误”，用户再次触发原操作重试。
- 筛选页草稿变化后返回使用蓝湖弹窗“温馨提示 / 是否保存该设置？ / 不保存 / 保存”；“保存”提交当前草稿后返回，“不保存”丢弃草稿并返回。
- 返回或重新进入筛选结果时，如果上次结果快照查不到，只清除结果快照并按最近一次已保存条件重新查询，不得把用户筛选偏好重置为平台默认值。
- 会员到期视觉优先复用 PRD-04 已有会员过期稿；举报、不再推荐等危险操作使用公共弹层结构，但保留各自业务文案和按钮语义。
- 设计稿与本文件、模块公共定义冲突时，保留设计的布局、色彩和组件关系，业务字段、隐私、价格、状态与交互以正式 PRD 为准。
- 用户主页与主页预览共用同一套资料展示组件和显隐规则；推荐详情只在共享主页上注入来源和底部关系动作，不复制第二套资料页面。

## 8. 理想型通信、解锁与隐私口径

### 8.1 通信模式

- 推荐或理想型对象尚未获得有效解锁关系时，资料页通信主操作固定为“悄悄话”，服务端返回 `communicationMode=WHISPER`。
- 理想型对象完成有效解锁后，资料页通信主操作切换为“私信”，服务端返回 `communicationMode=PRIVATE_MESSAGE`。
- 客户端不得根据按钮文案、页面来源或本地缓存推断通信模式；解锁过期、退款、对象失效或关系阻断后由服务端重新判定。

### 8.2 批量解锁与折扣

- 商业化配置新增“理想型批量解锁优惠比例”，字段 `idealBatchDiscountPercent`，取值 0–100，默认 10，表示在当前单人解锁价合计基础上优惠 10%。
- “解锁全部”指解锁当前筛选快照中仍有效、尚未解锁且可解锁的全部候选，不按客户端当前已加载页截断。
- 批量最大人数仍受后台 `idealBatchMax` 安全上限约束；超过上限时服务端拒绝报价并提示调整条件，不允许静默只取前 N 位。
- 批量应付金额由服务端报价：`ceil(有效候选单价合计 × (100 - 优惠比例) / 100)`，不得由客户端自行计算或提交价格。
- 报价返回候选数量、原价、优惠比例、优惠金额、应付金额和短期有效的 `quoteToken`；确认解锁必须携带 `quoteToken + requestId`，配置或候选集合变化后旧报价失效。
- 批量扣币后的逐人解锁成本按服务端分摊并保证合计严格等于应付金额；重复确认不得重复扣币或重复写解锁记录。

### 8.3 动态文案与隐私纠错

- “什么是理想型”、结果页优惠、充值承接页中的价格、折扣、人数上限和保留期均取服务端当前配置，不写死设计样例中的 100、200、9 折或 90 天。
