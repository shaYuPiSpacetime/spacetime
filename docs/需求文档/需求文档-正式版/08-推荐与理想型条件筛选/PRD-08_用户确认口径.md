# PRD-08 用户确认口径

> 状态：已确认
> 确认日期：2026-07-16
> 适用范围：一期「推荐与理想型条件筛选」模块
> 优先级：本文件高于历史版《细化PRD-08_推荐算法（觅缘匹配与精选）》及《管理后台细化PRD-08_推荐算法配置》中的冲突描述。

## 1. 模块定位

一期删除测评量表与复杂推荐算法，PRD-08 调整为移动端「推荐 + 理想型」双 Tab 模块，使用明确、可解释的条件筛选完成候选人匹配。

- 「推荐」：面向日常浏览，展示候选人卡片，并支持基础筛选与 VIP 高级筛选。
- 「理想型」：面向更明确的择偶诉求，通过预置条件标签组合筛选；筛选免费，查看清晰结果需要消耗千寻币解锁。
- 一期不建设独立的“推荐算法配置”管理后台，不提供权重、排序、测评、机器学习或运营算法编排能力。

## 2. 核心准入与认证规则

- 沿用 PRD-01 的三项核心认证准入：实名认证、头像认证、学历认证。参考图中的“人脸认证”只作为旧版筛选示意，不改变 PRD-01 已定稿的头像认证口径。
- 推荐筛选中删除“认证状态”条件，不允许用户用认证类型二次筛选候选人。
- 未满足核心准入条件的用户按 PRD-01 统一拦截，不进入 PRD-08 主流程。

## 3. 推荐 Tab

### 3.1 基础筛选

- 地理位置：按候选人现居地匹配，可选择一个或多个城市。
- 年龄：按候选人出生日期实时计算年龄后匹配。
- “嘉宾不足时允许推荐周边城市”仅作用于推荐 Tab；关闭时严格按已选城市匹配。

### 3.2 VIP 高级筛选

- 身高
- 体重
- 学历
- 家乡
- 学校
- 专业

非 VIP 可以查看高级筛选入口和字段，但提交高级条件前必须完成 VIP 权益校验。地理位置与年龄不受 VIP 限制。

### 3.3 推荐行为

- 支持查看候选人卡片、进入详情、喜欢、暂不喜欢/下一位。
- 保留见面偏好、推荐回看和筛选记录能力；具体权限与商业规则以页面规格为准。
- 推荐候选不足时，仅可按用户开关补充周边城市；不得自动放宽年龄、认证准入或 VIP 高级条件。

## 4. 理想型 Tab

### 4.1 基础筛选

- 地理位置：按候选人现居地匹配。
- 年龄：按候选人出生日期实时计算年龄后匹配。
- 地理位置与年龄和推荐 Tab 共用当前筛选值；任一入口保存后，另一入口展示最新值。
- 理想型筛选不启用周边城市扩展，也不自动放宽任何已选条件。

### 4.3 组合与缺失值规则

- 不同字段之间使用 AND：候选人必须同时满足所有已选条件。
- 同一结构化字段存在多个可选值时使用 OR：命中任一已选值即可。
- 候选人关键字段为空、标签缺失或无法识别时，该条件判定为不命中，不得推测或默认通过。
- 依赖当前用户资料的条件（如校友、兴趣相似、感情观相合）在当前用户资料不足时置为不可选，并提供完善资料入口。
- “本地人”的目标城市取理想型筛选当前选中的现居地城市；多城市时命中任一目标城市即可。

### 4.4 结果与解锁

- 选择和执行理想型筛选免费。
- 未解锁结果以脱敏、模糊卡片展示，不得泄露头像、昵称或可识别个人信息。
- 支持单人解锁与批量解锁；批量单次最多选择 5 人。
- 解锁消耗千寻币，VIP 不豁免；价格、余额校验、扣减及失败处理复用 PRD-04 商业配置与交易能力。
- 扣币前必须展示确认信息；余额不足时引导充值；扣币成功后展示清晰资料并写入历史解锁记录。
- 保留理想型筛选记录与历史解锁记录入口。

## 5. 后台与配置边界

- PRD-08 一期不提供独立管理后台页面和算法配置 CRUD。
- 城市、学历、学校层级、专业、标签、脱单目标等枚举复用系统字典或对应资料模块的稳定编码。
- 理想型单人/批量解锁价格、千寻币余额与订单流水复用 PRD-04 商业配置及交易能力。
- 管理后台如需展示模块边界，仅允许提供只读说明与既有配置入口跳转，不得形成新的算法配置中心。

## 6. 明确排除项

- 测评量表、性格测评、测评相似度。
- 推荐权重、排序分、推荐算法参数、机器学习模型。
- “高颜值”“收入可观”等一期无稳定字段或无可审计口径的筛选项。
- 推荐筛选中的认证状态条件。
- 理想型条件的自动放宽、默认猜测或隐式兜底。
- 独立 PRD-08 管理后台。
