## 1. 目标与范围

让通过学历认证的同校用户免费发起认识。**保留悄悄话与私信的区分：同校悄悄话免费、不限总次数，对方回复后才建立匹配并转入私信。**

复用现有发起弹窗、悄悄话列表/详情及私信会话，不增加页面或独立后台菜单。本次只改变符合条件的悄悄话计费方式，不扩大图片、语音等消息类型，不开放同校未匹配直接私信。

规则事实源：同校资格使用 `GLB-RULE-verified-school-pair`，消息分支使用 `M03-RULE-school-free-whisper`，费用类型使用 `M03-ENUM-whisper-pay-type`，资产处理使用 `M04-RULE-whisper-pay`。本文件说明其页面差异、流程与验收。

## 2. 已确认业务规则

| 序号 | 规则 | 本次确定的处理 |
|---|---|---|
| 1 | 消息形态 | 采用方案 A。未匹配先发悄悄话，接收方回复后，按原流程建立/复用匹配和唯一私信会话；仅同校不会直接产生匹配 |
| 2 | 次数与重复发送 | 不设置同校悄悄话每日或累计业务总次数上限；同一对象仍只能有一条待回复申请，对方未回复时不能连续发多条。不限次数不等于取消待回复限制 |
| 3 | 同校认定 | 以双方当前有效、已通过的学历认证学校为准；同校不同校区、在校生与毕业生均算同校。不能只凭资料中填写的学校名称获得免费资格 |
| 4 | 用户准入 | 普通用户和会员均适用；发送方与接收方仍须满足现有实名、头像、学历认证及账号正常要求，拉黑、禁言、冻结等限制继续生效 |
| 5 | 入口范围 | 推荐、理想型中已有的悄悄话入口、用户主页、社区动态/评论、同校信息流等全部已有入口统一判定。不能仅在同校 Tab 免费，也不能因切换入口绕过限制 |
| 6 | 费用与会员次数 | 同校发送不扣千寻币、不占会员每日免费悄悄话次数；会员额度留给非同校对象。余额为 0、会员次数耗尽或未开通会员，都不影响已满足其他条件的同校免费发送 |
| 7 | 到期与冷却 | 遵守现有有效期、冷却及配置快照规则，当前默认未回复 7 天到期、到期后同对象冷却 7 天；同校不豁免，也不新增独立同校配置 |
| 8 | 女性保护 | 转私信后按现有保护开关、关系来源和发送权限处理；同校免费不新增保护豁免，也不改变悄悄话回复本身在现有流程中的作用 |
| 9 | 资格变化 | 学校修改或学历认证失效后，取消后续新联系的免费资格；重新认证后按新的有效学校重新判定。学校变更本身不删除既有消息/匹配/会话；认证失效等情形仍按原生命周期限制处理 |

非同校对象继续执行原收费规则；同校免费不包含历史付费悄悄话的追溯退币、返还已消耗会员次数或其他解锁费用减免。

## 3. 用户流程与费用判定

1. 用户从任意已有入口点击“悄悄话”或“申请认识”。
2. 复用发送资格预检查：认证/账号及安全限制不通过时按原反馈拦截；已有匹配进入原私信；已有待回复申请进入原详情；处于冷却期则不能重发。
3. 具备发送资格后，按顺序确定费用：**同校免费 → 原会员免费次数 → 原千寻币扣费**。同校由服务端按认证资料判定，客户端不提交“我是同校”或自行决定价格。
4. 展示当前费用及发送确认。用户提交时再次校验目标、同校资格、待回复状态和报价；资格变化时刷新费用说明并要求重新确认，不能静默扣币或消耗会员次数。
5. 创建并投递悄悄话；有效送达后进入原待回复列表。同校发送记录标记 `school_free`，实际币消耗和会员次数消耗均为 0。
6. 对方回复后沿用原原子流程：回复、匹配、唯一私信会话及开场消息整体成功；申请退出双方悄悄话默认列表，双方进入私信交流。

免费只免除费用和总次数额度，不绕过原 `M03-RULE-whisper-repeat-limit`、`M03-RULE-whisper-expire`、`M03-RULE-whisper-reply-atomic`。资格查询失败属于服务错误，不能直接视为非同校并收费。

### 4.3 状态与异常

| 状态类别 | 展示和操作 |
|---|---|
| 加载 | 预检查未完成时不提前展示“同校免费”，禁止确认发送 |
| 空态 | 输入为空沿用原提示；无有效认证学校不提供同校免费报价，其他资格按原规则处理 |
| 错误 | 网络、认证资格查询或报价服务失败时保留输入并提示重试，不自动转扣费 |
| 无权限 | 未认证、账号受限、拉黑、禁言等按原原因拦截；免费资格不能覆盖这些限制 |
| 业务态 | 可发送时展示免费说明；已有 `pending` 进入原申请；已匹配进入原私信；到期/冷却/失效沿用原规则 |
| 降级 | TIM 投递失败走原可靠投递与重试；`school_free` 未消耗资产，不补发千寻币或会员次数；不开放临时直接私信 |

## 5. 数据、依赖与交付边界

| 模块 | 本次承接 | 依赖未就绪或异常时 |
|---|---|---|
| PRD-01 | 提供当前有效的已通过学历认证学校及统一准入状态，按全局同校规则区分学校与校区 | 无有效认证不享同校免费；查询失败阻止报价并允许重试，不能用资料学校猜测 |

| PRD-03 | 预检查、提交复验、免费类型、原申请/会话生命周期 | 不新增页面、消息形态、独立免费次数配置或直接聊天接口 |
| PRD-04 | 免费优先判定、不扣币、不占会员次数；其他对象继续原权益 | 不把同校免费伪装成会员核销或零金额扣币/退币流水 |
| PRD-05/08 | 所有已有发起入口共用规则与展示 | 不按来源页面授予免费；已有理想型解锁后的通信权限不受本次变更影响 |

新增费用类型须贯穿预检查、确认、消息记录及已有后台相关查询；旧 `vip_free`、`coin` 记录保留原费用事实，不追溯修改。重复点击、跨入口并发和网络重试复用既有幂等约束，不重复建申请；免费资格及消息状态变化均由服务端复验。

本次不改变消息正文留存、举报权限、非同校价格、会员每日次数配置和认证审核流程。学校变更不单独清空历史；账号/认证失效后的可见与发送权限继续遵循原规则。
