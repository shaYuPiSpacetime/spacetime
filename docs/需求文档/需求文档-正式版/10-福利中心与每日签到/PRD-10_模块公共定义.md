# PRD-10 福利中心与每日签到 - 模块公共定义

| 版本 | 日期 | 修改人 | 变更摘要 |
|------|------|--------|----------|
| 版本01 | 2026-07-14 | Codex | 根据一期目标和用户确认口径创建 |

## 1. 已确认决策

| 决策 ID | 决策 | 结论 |
|---------|------|------|
| `M10-DEC-01` | 奖励方式 | 连续签到阶梯奖励 |
| `M10-DEC-02` | 后台配置 | 支持每日基础奖励、连续签到额外奖励、活动启停 |
| `M10-DEC-03` | 日期口径 | `Asia/Shanghai` 北京时间自然日 |
| `M10-DEC-04` | 福利中心入口 | 直接进入每日签到页，不建设福利首页 |
| `M10-DEC-05` | 补签 | 一期不支持补签 |

## 2. 术语与枚举

| ID | 名称 | 定义 |
|----|------|------|
| `M10-TERM-sign-day` | 签到日 | 北京时间 `00:00:00-23:59:59` 的自然日 |
| `M10-TERM-streak` | 连续签到天数 | 从最近一次中断后重新累计的连续自然日签到次数 |
| `M10-TERM-cycle` | 阶梯周期 | 后台配置的连续签到奖励周期，范围 1-31 天；完成后次日从第 1 天重新循环 |

### 2.1 `M10-ENUM-sign-status`

| code | 显示名 | 说明 |
|------|--------|------|
| `available` | 今日可签到 | 今日无成功签到记录且活动启用 |
| `signed` | 今日已签到 | 今日已有成功签到记录 |
| `disabled` | 活动已暂停 | 后台关闭签到活动 |

### 2.2 `M10-ENUM-reward-status`

| code | 显示名 | 说明 |
|------|--------|------|
| `pending` | 待发放 | 签到记录已创建，奖励事务处理中 |
| `success` | 已发放 | 千寻币已到账并产生资产流水 |
| `failed` | 发放失败 | 奖励未到账，等待系统重试 |

## 3. 状态机

### 3.1 `M10-SM-sign`

| 起始状态 | 触发 | 目标状态 | 前置条件 | 副作用 |
|----------|------|----------|----------|--------|
| `available` | 用户点击签到 | `signed` | 活动启用、今日无签到记录 | 创建签到记录并发放奖励 |
| `available` | 运营关闭活动 | `disabled` | 配置发布成功 | 前台不可签到，历史记录保留 |
| `disabled` | 运营开启活动 | `available`/`signed` | 配置有效 | 按今日是否已有记录决定状态 |
| `signed` | 北京时间跨日 | `available` | 新自然日且活动启用 | 连续天数按昨日是否签到计算 |

### 3.2 `M10-SM-reward`

| 起始状态 | 触发 | 目标状态 | 处理规则 |
|----------|------|----------|----------|
| `pending` | PRD-04 资产入账成功 | `success` | 记录资产流水号和到账时间 |
| `pending` | 入账失败 | `failed` | 记录失败原因并进入系统重试 |
| `failed` | 自动重试成功 | `success` | 不重复创建签到记录，只补发原奖励 |

## 4. 核心规则

| 规则 ID | 规则 | 判定逻辑 |
|---------|------|----------|
| `M10-RULE-day-boundary` | 签到日边界 | 服务端统一按 `Asia/Shanghai` 计算，不信任客户端日期 |
| `M10-RULE-no-makeup` | 不补签 | 历史未签到日期只展示未签到，不提供补签入口或接口 |
| `M10-RULE-idempotency` | 每日幂等 | `(user_id, sign_date)` 唯一；重复请求返回首次签到结果，不重复发币 |
| `M10-RULE-streak` | 连续天数 | 昨日已签到则 `streak+1`，否则从 1 开始；达到周期末后次日回到第 1 档 |
| `M10-RULE-reward` | 奖励计算 | `当日奖励=基础奖励+命中阶梯的额外奖励`；以签到瞬间生效配置快照为准 |
| `M10-RULE-config-change` | 配置变更 | 奖励金额变更只影响发布后的新签到；周期长度变更只影响发布后开始的新周期，进行中的周期继续使用原配置版本；历史签到和奖励不追溯、不补差 |
| `M10-RULE-disabled` | 活动关闭 | 关闭期间不可签到且连续天数中断；重新开启后从第 1 天开始 |
| `M10-RULE-asset` | 资产闭环 | 奖励通过 PRD-04 千寻币入账能力发放，流水来源固定为 `daily_signin` |

## 5. 配置项

| 配置 ID | 配置项 | 默认值 | 类型 | 配置路径 | 生效 | 高风险 |
|---------|--------|--------|------|----------|------|--------|
| `M10-CFG-enabled` | 签到活动开关 | 关闭 | bool | 福利中心 -> 签到规则配置 | 发布后立即 | 是 |
| `M10-CFG-base-reward` | 每日基础千寻币 | 0 | int，0-10000 | 同上 | 发布后新签到 | 是 |
| `M10-CFG-streak-rewards` | 连续签到额外奖励 | 空数组 | json[]，天数 1-`cycleDays`、奖励 0-10000 | 同上 | 发布后新签到 | 是 |
| `M10-CFG-cycle-days` | 阶梯周期 | 7 | int，1-31 | 同上 | 发布后新周期 | 是 |

配置发布校验：活动开启时，`cycleDays` 对应的每一天都必须有明确奖励结果；允许某天额外奖励为 0，但不得缺日、重复或超出周期。修改周期只影响发布后开始的新周期；正在进行的用户继续使用其签到记录保存的原配置版本直至当前周期结束。

## 6. 事件、错误码与接口草案

| ID | 类型 | 内容 |
|----|------|------|
| `M10-EVT-signed` | 事件 | `userId, signDate, streakDay, rewardAmount, configVersion` |
| `M10-EVT-reward-failed` | 事件 | `signRecordId, userId, rewardAmount, failureReason` |
| `M10-ERR-already-signed` | 409 | 今日已签到；接口返回首次结果 |
| `M10-ERR-disabled` | 409 | 签到活动暂未开放 |
| `M10-ERR-reward-pending` | 202 | 签到成功，奖励发放处理中 |
| `M10-ERR-config-invalid` | 400 | 阶梯配置重复、越界或无效 |

| 端 | 方法 | 路径 | 说明 |
|----|------|------|------|
| APP | GET | `/api/app/welfare/signin` | 查询今日状态、周期日历和最近奖励 |
| APP | POST | `/api/app/welfare/signin` | 每日签到，幂等返回签到结果 |
| ADM | GET | `/api/admin/welfare/signin/config` | 查询当前配置和版本 |
| ADM | PUT | `/api/admin/welfare/signin/config` | 校验并发布配置 |
| ADM | GET | `/api/admin/welfare/signin/records` | 查询签到及奖励记录 |

## 7. 非功能要求

- 签到接口 P95 小于 500ms；资产服务短暂不可用时允许返回奖励处理中。
- 签到记录、奖励金额、配置版本和资产流水号永久可追溯；用户注销后按全局规则匿名化 userId。
- 配置发布、活动启停、奖励补发重试必须写入 PRD-10 自身变更日志；后台在签到规则配置页内提供“查看变更日志”入口，不建设跨模块公共日志页面。
- 不提供后台人工补签或人工修改连续天数。
