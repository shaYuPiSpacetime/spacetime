## 1. 目标

为已登录且完成核心准入的用户提供低成本日活激励，通过连续签到阶梯奖励发放千寻币，并保证重复点击不重复发奖。

## 2. 本期范围

| 需求 ID | 能力 | 优先级 |
|---------|------|--------|
| `APP-10-REQ-01` | 我的页福利中心入口直接进入每日签到页 | P0 |
| `APP-10-REQ-02` | 按后台周期动态展示签到阶梯、今日状态、连续天数及奖励 | P0 |
| `APP-10-REQ-03` | 每日签到并承接奖励成功/处理中结果 | P0 |
| `APP-10-REQ-04` | 查看最近签到和奖励记录 | P0 |
| `APP-10-REQ-05` | 通过统一 H5 容器查看运营发布的签到规则，失败时展示原生基础规则 | P0 |

## 3. 本期不做

| 能力 | 处理方式 |
|------|----------|
| 补签 | 不展示入口、不提供接口 |
| 任务系统、活动福利、兑换商城 | 隐藏，不建设福利首页 |
| 分享加倍、广告翻倍、抽奖 | 不展示 |
| 用户自行选择奖励 | 不展示 |

## 4. 核心流程

1. 用户从“我的 -> 福利中心”进入签到页。
2. 客户端查询服务端今日状态和配置快照。
3. 今日可签到时点击“立即签到”；服务端按北京时间及唯一键判定。
4. 创建签到记录并请求 PRD-04 千寻币入账。
5. 入账成功展示奖励；入账暂失败展示“奖励处理中”，后台自动重试。
6. 重复点击或弱网重试返回同一签到结果，不重复发奖。

## 5. 数据与依赖

核心对象包括签到配置版本和签到记录。签到记录字段为 `userId, signDate, streakDay, cycleDay, baseReward, extraReward, totalReward, configVersion, rewardStatus, assetFlowNo, createdAt`；一个配置版本对应多条签到记录，每名用户每个北京时间自然日最多一条签到记录。

| 依赖 | 内容 | 不可用兜底 |
|------|------|------------|
| PRD-04 | 千寻币入账和流水 | 签到成功、奖励标记处理中并自动重试 |
| PRD-06 | 我的页入口 | 入口按依赖隐藏或展示活动关闭态 |

## 6. 改动影响面

| 影响对象 | 影响方式 | 处理 |
|----------|----------|------|
| PRD-06 我的页 | “福利中心”入口直接路由到签到页 | 同步入口路由与活动关闭态 |
| PRD-04 千寻币资产 | 新增 `daily_signin` 流水来源与幂等入账请求 | 资产服务不可用时转奖励处理中 |
| 老版本客户端 | 无签到页路由或无法识别新增状态 | 入口按客户端最低兼容版本控制；服务端未知状态按暂不可用降级 |

## 8. 上线、灰度与回滚

- 首次上线不迁移或补造历史签到记录，所有用户连续天数从首次成功签到开始。
- 默认活动关闭；先对内部测试账号开放并核对签到记录与资产流水，再全量开启。
- 回滚前由运营关闭活动；保留已经产生的签到、配置快照和资产流水，不做反向扣币。
- 生产环境禁止使用 Demo mock 数据；客户端无法加载真实配置时进入降级态并禁止签到。

## 9. 验收门禁

- 引用 `PRD-10_模块公共定义.md` 的状态机、奖励和幂等规则。
- P0：同一用户同一自然日只能生成一条有效签到记录和一笔奖励流水。
- P0：活动关闭和资产服务异常均有明确用户反馈。
