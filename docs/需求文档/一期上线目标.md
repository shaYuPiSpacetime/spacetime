## 1. 一期上线总目标

一期上线以“小程序核心闭环可用、后台可运营可审核可追踪”为目标，移动端和管理后台必须成组交付：

| 目标方向       | 移动端上线内容                                                          | 管理后台上线内容                                                             |
| -------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 用户准入与资料 | 微信登录、资料初始化、编辑资料、用户主页、实名/学历/头像认证、单身承诺  | App 用户管理、用户详情、准入状态、资料完整度、冻结/解冻、启用/停用、认证审核 |
| 推荐与关系     | 推荐与理想型双 Tab、推荐筛选设置、理想型筛选/结果/记录/历史解锁、心动列表、喜欢/相互喜欢、用户主页 | 用户关系摘要、VIP/千寻币权益配置、用户状态处置；筛选字段复用系统字典，不建设独立推荐算法后台 |
| 社区与内容     | 千寻成家信息流、话题、发布动态、动态详情、评论/互动、举报               | 内容审核、评论审核、举报处理、社区配置、资料照片与文字审核                   |
| 消息与通知     | 消息列表、私信、官方助手、官方消息、悄悄话、通知中心、邀请响应          | 消息/通知记录查询、模板文案配置、举报与处罚联动、操作日志                    |
| 商业化         | VIP 会员、成家币充值、明细、权益弹窗、解锁/悄悄话消耗                   | VIP 权益配置、VIP 套餐配置、成家币套餐配置、订单管理、流水管理、退款管理     |
| 推广裂变       | 推荐给好友、活动规则、邀请响应、邀请奖励展示入口                        | 推广规则、邀请关系、奖励流水、校园代理、代理结算                             |
| 我的与安全     | 我的页、帮助客服、设置、隐私设置、账号注销、协议清单                    | 注销申请、公告与帮助内容、协议配置、搜索屏蔽词                               |

## 2. 一期范围边界确认

| 边界项         | 一期确认口径                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 聊天关系规则   | 普通私信必须在双方相互喜欢后才能开聊；未相互喜欢时不开放普通私信。                                                                                |
| 社区触达入口   | 未建立互动关系时展示“申请认识”并进入社区打招呼页；对方回复并建立互动关系后，消息动作直接进入 PRD-03 私信对话，不设置社区发私信中转页。          |
| 破冰能力       | 悄悄话/小纸条作为一期破冰能力保留，和普通私信区分；其次数、消耗、审核、举报等细节进入后续详细设计。                                               |
| 举报与安全闭环 | 聊天举报纳入一期；推荐卡、用户主页、社区详情、会话页需保留举报及场景内屏蔽/不再推荐能力。本期不做完整黑名单管理页、关键词屏蔽页、安全中心独立页。 |
| 后台举报承接   | 后台统一承接用户举报、内容举报、聊天举报、悄悄话举报等举报来源，按来源区分处理上下文和处置记录。                                                  |
| 测评相关       | 测评、心印测试、惊鸿测试、灵魂测试、知音测评、职业测评报告、题目/题库、作答、报告、测评统计/导出等全部不纳入一期；一期不设置测评入口、测评报告中心或测评后台。 |
| 觅知音         | 知音中的觅知音不纳入一期。                                                                                                                        |
| 知音保留场景   | 悦目作为偏视觉浏览与悄悄话破冰入口保留；诚意贴作为征友/自我介绍贴发布与互动入口保留。                                                            |
| 立业场景       | 立业中的职业推荐、推荐职位、职业测评报告等不纳入一期。                                                                                              |
| 搜索范围       | 一期搜索按入口限定搜索对象，不定义为全站统一搜索；理想型不提供自由关键词搜索，只按 PRD-08 固定条件筛选，其他入口按所属场景收敛搜索范围。         |
| 通知机制       | 不做用户自助通知设置页，也不做后台完整通知偏好开关；保留业务节点通知和站内通知。微信订阅消息模板申请作为上线前置风险确认项。                      |
| 登录与手机号   | 微信登录和手机号绑定作为一期强制准入要求；用户未完成手机号绑定时不进入核心使用流程。                                                              |
| 福利中心       | 一期福利中心仅保留每日签到，不包含任务系统、活动福利或其他福利玩法。                                                                              |
| 签到规则       | 每日签到按北京时间自然日计算，采用可配置周期的连续签到阶梯奖励；一期不支持补签，福利中心入口直接进入签到页；周期和奖励由 PRD-10 后台配置。       |
| 公告入口       | 我的 -> 帮助与客服不保留公告栏；公告栏仅保留在我的 -> 设置 -> 关于我们下。                                                                        |
| 推荐与理想型   | 一期由 PRD-08 定义固定条件筛选：推荐基础条件为位置、年龄，VIP 高级条件为身高、体重、学历、家乡、学校、专业；理想型在共用位置、年龄上叠加固定资料/标签条件。所有已选条件按 AND 处理，不做模型评分、测评特征、自动放宽或推荐解释。候选人仍须三项认证通过；浏览者完成基础资料即可浏览与筛选，只有喜欢、悄悄话校验浏览者三项认证。 |
| 客服与反馈     | 一期不建设反馈提交、后台反馈箱或独立客服中心；“帮助与客服”页面仅保留联系客服能力。                                                                  |
| 搜索运营       | 一期删除搜索热词及搜索展示配置，只保留搜索屏蔽词后台能力；搜索结果类型、排序和提示由代码固定。                                                      |
| 移动端配置     | 一期不建设我的页面、设置页面、安全中心和搜索展示配置；对应入口及展示由客户端代码固定。后台保留 H5 内容配置，除公告、协议与合规清单外，预置承接 PRD-07 邀请规则 H5。 |
