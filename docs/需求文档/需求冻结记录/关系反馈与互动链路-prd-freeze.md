## 3. 本轮不做范围

| 内容 | 冻结处理 | 后续条件 |
|------|----------|----------|
| 移动端后端接口实现 | 不编码、不联调、不验收，仅输出接口交接草案 | 用户另行确认启动移动端开发 |
| 移动端页面实现 | 不实现喜欢/访客/相互喜欢/匹配弹窗/解锁弹窗页面 | 补齐 UI 并重新执行移动端设计门禁 |
| 隐藏访问 | 一期完全不开发入口、开关、权益校验、过滤、统计排除、接口或后台筛选 | 后续单独立项并重新评审隐私和审计权限 |
| 独立关系反馈一级菜单或工作台 | 不新增 | 客服排查量或运营需求达到单独立项条件后评估 |
| 关系反馈配置页 | 7 天、30 分钟、模糊 10 条等按固定规则；不做配置接口和页面 | 后续需运营动态调整时另立配置化需求 |
| 人工制造/恢复匹配、补喜欢、补访客 | 全角色禁止 | 高风险能力必须单独 PRD、审批和审计设计 |
| 普通角色导出 | 客服、运营禁止；风控、超管仅按授权导出 | 技术方案不得把首版普通导出作为默认入口 |
| 前台失效卡片/关系失效弹窗 | 不展示 | 后台保留真实原因用于受控查询 |
| 海量曝光/10 倍曝光入口、喜欢筛选胶囊 | 不属于 PRD-02 一期 | 不得从旧稿或旧 Demo 恢复 |

## 4. 冻结业务口径

| 编号 | 冻结口径 |
|------|----------|
| `C02-01` | 隐藏访问一期完全不开发，PRD-04 仅保留不可启用的后续权益编码，PRD-06 不提供入口 |
| `C02-02` | 婚恋用户主页归 PRD-05，PRD-02 仅输出访客、喜欢、匹配和会话入口状态 |
| `C02-03` | 同一无序用户对同时最多一条有效匹配；来源明细并存；失效后重新满足条件时创建新生命周期 |
| `C02-04` | 单条解锁采用两步确认；第一步不扣币，第二步复验对象与幂等后确认成功才扣币；任一步取消不扣币 |
| `C02-05` | 对象或关系失效后前台立即移除，不展示失效卡片、真实原因或关系失效弹窗 |
| `C02-06` | 女性保护只限制发送；PRD-02 返回 `canEnterConversation`，PRD-03 返回 `canSend`、`protectStatus` |
| `C02-07` | 匹配弹窗按 `matchNo + userId` 为双方分别生成和记录；主动关闭/导航算已读，未展示成功或异常退出不算已读 |
| `C02-08` | 隐藏访问后续若开发，不计对方前台 UV/PV，仅保留受控安全审计；普通客服和运营不得查身份 |
| `C02-09` | 单条解锁在对象与关系可展示时永久清晰；对象失效后移除且不自动退款；异常客诉走 PRD-04 特批退款 |
| `C02-10` | 关系事实永久保留且不物理删除；注销后匿名化；客服、运营、风控、超管按最小权限查看并记录审计 |
| `C02-13` | 同一访客访问同一主页 30 分钟内只生成或更新一条展示记录；PV 实际累计，UV 按用户去重 |
| `C02-14` | 普通用户最多返回最近 10 条模糊喜欢；`total` 为有效真实总数；会员按 20 条加载更多 |
| `C02-15` | 后台四类关系明细默认 10 条，支持 10/20/50，按业务时间倒序；切换 Tab/条数回第一页 |
