## 4. 冻结业务口径

| 编号 | 冻结口径 |
|------|----------|
| `C03-01` | 一期移动端固定为 7 个有效页面，不恢复通知详情页或邀请响应页 |
| `C03-02` | 私信会话状态仅表达会话生命周期；悄悄话、进入权、发送权和保护状态独立建模 |
| `C03-03` | 系统消息包括治理、资产、邀请、社区运营和平台安全；认证结果仍归 PRD-01 |
| `C03-04` | 系统消息没有独立详情页；当前加载或曝光成功的批次统一标记已读 |
| `C03-05` | 悄悄话回复、匹配关系和私信会话必须整体原子成功；失败时全部回滚并保持待回复 |
| `C03-06` | 会话内提供举报、拉黑、拉黑并举报；支持指定消息举报；主页不可访问不影响举报 |
| `C03-07` | 客服和运营无私信正文权限；仅举报/风险案件上下文可受控查看；导出永不含正文；查看必审计 |
| `C03-08` | 受限账号只读必要安全、处罚和申诉消息，不得产生真实互动 |
| `C03-09` | 普通配置版本只作用于新对象；全局安全开关立即覆盖发送等高风险能力 |
| `C03-10` | 消息首页固定三个业务入口及最近 3 条私信；完整私信列表独立游标分页 |
| `C03-11` | 留存按普通内容、系统消息、举报证据、安全日志和敏感审计分级处理 |
| `C03-12` | 01/03 静态 Demo、Mock 和交付报告与正式 PRD 使用同一口径 |
| `C03-13` | PRD-04/05/07 通过统一系统消息命令投递，生产事件幂等重试；通知失败不回滚原业务 |
| `C03-14` | 正式 UI 缺失期间视觉验收为 `N/A`，不得声明高还原；最终验收前补齐 7 页设计稿 |
| `C03-15` | 普通私信与悄悄话统一使用腾讯云 TIM 传输，平台与 TIM 均不执行本期日常消息发送前文本内容审核 |
| `C03-16` | 日常私信、悄悄话申请与回复完整明文直接归档到 `app_message_record`；普通移动端和后台接口不返回正文或内容摘要，案件正文仅按授权查看独立冻结证据 |

## 5. 数据与留存口径

| 数据类型 | 冻结处理 |
|----------|----------|
| 有效关系中的普通私信/悄悄话 | 在关系和对象有效期内按权限使用 |
| 关系失效、拉黑或申请取消后的普通内容 | 前台立即不可见；隔离 180 天后删除或匿名化，案件冻结证据除外 |
| 用户可见系统消息 | 建议保留 2 年 |
| 普通举报案件证据 | 建议保留 3 年 |
| 严重违规或永久封禁案件证据 | 建议保留 5 年 |
| 网络安全日志 | 不少于 6 个月 |
| 敏感正文查看与管理操作审计 | 建议保留 3 年 |
| 账号注销 | 立即隐藏；30 天冷静期后删除普通数据，仅保留最小法定和安全证据 |

上述期限是技术设计和容量估算基线。法务复核只能收紧或合法调整保存方式；若改变产品可见性、证据用途或删除语义，必须重新执行需求变更评审。

## 9. 冻结后变更规则

| 变更类型 | 处理规则 |
|----------|----------|
| 非语义文案、提示和低风险视觉调整 | 记录变更并同步页面规格 |
| 页面数量、对象、状态、接口、字段、权限或跳转变化 | 更新技术方案和测试用例，并重新通过对应门禁 |
| 悄悄话原子性、资产补偿、举报事实源、正文权限变化 | 重新执行需求评审和 PRD 冻结 |
| 系统消息承接范围或生产模块事件语义变化 | 同步修改生产模块 PRD 与技术方案，不得单边调整 |
| 留存、注销、案件证据用途变化 | 重新经过产品、法务、隐私和安全评审 |
| 新增正文导出、全局正文查询或人工改写消息 | 作为高风险能力单独立项 |
| 恢复历史页面或旧状态 | 视为范围变更，必须重新评审 |
