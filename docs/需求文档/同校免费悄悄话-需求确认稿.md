# 同校免费悄悄话需求确认稿

日期：2026-10-21｜版本：v0.1｜状态：待老板确认

## 1. 需求概述

同校用户发送悄悄话免费，发送次数不限。是否可以在对方未回复时连续发送、是否直接进入普通私信，需要进一步确认。

**本稿修正此前“同校可直接免费私信、无需先匹配”的确定性表述。** 最新聊天明确的是“悄悄话不收费、次数不限制”；“没有悄悄话和私信区分”是小皮提出的推论，尚未得到明确答复。

## 2. 聊天中已明确的需求意向

| 项目 | 需求内容 | 来源 |
|---|---|---|
| 适用对象 | 同校用户之间的联系 | Honor，14:52“同校直接免费” |
| 免费范围 | 发送悄悄话不收取千寻币 | Honor，14:55“发悄悄话不收费” |
| 次数 | 悄悄话发送次数不设业务额度上限 | Honor，14:56“不限制” |

以上为 Honor 表达的意向，仍需老板最终确认。“次数不限”是否同时取消对同一对象的待回复限制、到期冷却限制，聊天中没有明确区分。

## 3. 老板需确认的规则

| 编号 | 确认项 | 需要拍板的内容 | 老板结论 |
|---|---|---|---|
| 1 | 悄悄话与私信是否区分 | A. 保留悄悄话，对方回复后才建立匹配并转入私信；B. 同校首次联系就直接进入普通私信，无需等待回复或预先匹配 | 待确认 |
| 2 | 同一对象连续发送 | 若选择 A，对方尚未回复时，能否连续发送多条？还是保留“同一对象只能有一条待回复申请”，仅取消总次数额度？ | 待确认 |
| 3 | 同校如何认定 | 依据本人填写的学校，还是学历认证通过的学校？同校不同校区、在校生与毕业生是否都算同校？ | 待确认 |
| 4 | 用户准入 | 普通用户、会员是否均适用？发送方和接收方是否仍需满足现有实名、头像、学历认证要求？ | 待确认 |
| 5 | 免费入口范围 | 仅从“同校”信息流进入时免费，还是从推荐、用户主页、社区等任意入口联系同校用户都免费？ | 待确认 |
| 6 | 会员免费额度 | 同校免费发送是否不占用会员每日免费悄悄话次数，会员次数继续留给非同校对象？ | 待确认 |
| 7 | 到期与冷却 | 若选择 A，是否保留悄悄话 7 天未回复到期、到期后对同一对象冷却 7 天的规则？ | 待确认 |
| 8 | 女性保护 | 同校转入普通私信后，是否继续适用当前女性保护规则？若选择 B，从首次联系时是否适用？ | 待确认 |
| 9 | 同校资格变化 | 学校修改或学历认证失效后，后续新联系是否取消免费资格？已建立的聊天是否继续保留？ | 待确认 |

**最关键的是第 1、2 项：免费且不限总次数，不必然等于可以未读连续发送，也不必然等于直接普通聊天。**

## 4. 两种方案的用户流程

| 方案 | 用户流程 | 与现有功能的区别 |
|---|---|---|
| A：保留悄悄话 | 识别同校 → 免费发送悄悄话 → 等待对方回复 → 建立匹配 → 转入普通私信 | 取消同校收费和业务次数额度；重复发送、到期和冷却是否取消，按第 2、7 项决定 |
| B：同校直接聊天 | 识别同校 → 直接建立普通私信会话 → 持续聊天 | 同校新增普通私信开放条件，不再依赖悄悄话回复或预先匹配；是否同时生成匹配关系需补充确认 |

两种方案供选择，不默认采用其中一种。已有匹配用户继续使用原有私信会话，不重复创建。

## 5. 确认后的验收要点

| 场景 | 验收要求 |
|---|---|
| 同校且千寻币余额为 0 | 满足最终确认的联系条件时，可以发送，不要求充值、不扣千寻币 |
| 多次联系同校用户 | 不因同校发送次数用完而收费或拦截；同一对象是否可连续发送按确认结果执行 |
| 未匹配、对方未回复 | 按选定方案停留在悄悄话待回复，或直接进入私信，页面入口与实际权限一致 |
| 非同校用户 | 继续执行现有收费、次数和关系规则 |
| 拉黑、禁言或账号受限 | 本次不提出取消既有安全限制，继续按现有规则处理 |
