# 蓝湖 MCP 高还原闭环流程

> 适用场景：按蓝湖、蓝湖 MCP、设计稿截图或设计标注还原小程序 H5、管理后台、静态 Demo 或正式前端页面。  
> 核心目标：把 UI 还原从“肉眼多轮返工”改成“基线采集 -> token/组件 -> 页面实现 -> 截图差异 -> 修复闭环”的工程流程。  
> 默认要求：以后涉及蓝湖/MCP UI 还原的任务，先执行本文档，不得直接进入页面编码。

---

## 1. 总原则

蓝湖 MCP 只能提供设计信息，不能直接保证还原度。高还原必须依赖三件事：

1. **设计基线**：明确页面、视口、截图、素材、状态、字体和安全区。
2. **组件基线**：先沉淀颜色、字号、间距、圆角、阴影、按钮、输入框、卡片、导航栏等 token 和组件。
3. **截图闭环**：每页实现后必须截图，对照蓝湖基线列差异，再修复。

禁止把“页面大概像”当作完成。没有截图证据、没有差异清单、没有还原度评分时，不得宣称高还原完成。

---

## 2. 触发口径

用户出现以下表达时，默认进入本流程：

- “按蓝湖还原”
- “用蓝湖 MCP 还原”
- “小程序按设计稿还原”
- “这个页面照设计稿做”
- “还原度太差，重新按设计做”
- “根据蓝湖生成 H5 / 静态 Demo / 前端页面”
- “按截图像素级/高保真还原”

如果用户要求快速粗略原型，可以降级，但必须明确说明“本次不是高还原流程”。

每次高还原任务至少产出以下记录，放在对应模块的设计或验收目录中：

```text

```

```text

├── 01-页面元素清单.md

```

## 4. 阶段门禁

### Step 0：任务澄清与范围锁定

开始实现前必须明确：

| 项目 | 要求 |
|------|------|
| 页面范围 | 页面 ID、页面名称、端类型，小程序/管理后台/H5 必须分开 |
| 设计来源 | 蓝湖链接、MCP 节点、截图目录或本地设计图 |
| 目标视口 | 默认小程序 375x812；管理后台默认 1440x900；有设计稿尺寸时以设计稿为准 |
| 页面状态 | 默认态、空态、加载态、错误态、弹窗态、抽屉态、按钮禁用态 |
| 素材来源 | 设计稿切图、项目现有素材、可替换图标，缺失素材必须登记 |
| 验收阈值 | 默认整体还原度 >= 95%，关键首屏 >= 97% |

不清楚的信息必须先问；用户明确“直接做”时，可以先按默认值执行，但要写入假设。

### Step 1：设计基线采集

使用蓝湖 MCP 或设计截图读取以下内容：

| 类型 | 必采集 |
|------|--------|
| 页面结构 | 顶部导航、安全区、滚动容器、底部栏、主内容分区 |
| 尺寸 | 画布宽高、组件宽高、边距、间距、固定高度 |
| 字体 | 字号、字重、行高、颜色、对齐方式 |
| 色彩 | 背景、主色、文本、边框、状态色、遮罩 |
| 圆角阴影 | 卡片、按钮、输入框、弹窗、图片圆角 |
| 素材 | 图片、头像、图标、插画、背景图 |
| 交互状态 | 选中、禁用、加载、成功、失败、空态 |

输出到技术方案的“设计基线表”。如果 MCP 无法拿到完整信息，必须用截图补充，不得凭经验脑补。

### Step 2：视觉 Token 与组件映射

页面编码前先建立映射：

| 设计元素 | 项目落点 |
|----------|----------|
| 颜色 | CSS 变量、Tailwind token 或局部样式常量 |
| 字体 | 全局字体、字号层级、行高 |
| 间距 | 页面 padding、组件 gap、列表间距 |
| 圆角 | 按钮、卡片、图片、弹窗 |
| 阴影 | 卡片、浮层、底部操作栏 |
| 按钮 | 主按钮、次按钮、图标按钮、禁用态 |
| 表单 | 输入框、选择器、开关、上传组件 |
| 导航 | 小程序标题栏、管理后台菜单、面包屑 |

规则：

1. 先复用项目已有组件和样式体系。
2. 只有确实重复出现的设计元素才抽组件。
3. 不允许每个页面临时硬编码一套颜色、字号和按钮样式。
4. 小程序/H5 必须处理安全区、状态栏、底部栏和滚动容器。
5. 管理后台必须处理信息密度、表格列宽、筛选区和弹窗/抽屉层级。

### Step 3：一页一闭环实现

不得一次性铺完所有页面再统一返工。按页面或页面组执行：

```text
读取页面设计 -> 实现页面 -> 截图 -> 差异清单 -> 修复 -> 再截图 -> 达标后进入下一页
```

每页必须覆盖：

1. 首屏默认态。
2. 关键交互态。
3. 主要弹窗/抽屉/浮层。
4. 空态或异常态。
5. 长文案或长数据撑开后的布局。

大模块拆分建议：

| 场景 | 拆分方式 |
|------|----------|
| 小程序 | 按页面栈拆：登录/资料/认证/列表/详情/支付/结果 |
| 管理后台 | 按工作台拆：列表、详情、配置、审核、统计 |
| 静态 Demo | 按移动端与管理后台分文件，再按页面组推进 |

### Step 4：截图与差异核对

每次实现后必须生成截图证据。推荐视口：

| 类型 | 默认视口 |
|------|----------|
| 小程序 H5 | 375x812 |
| 小程序大屏补充 | 414x896 |
| 管理后台 | 1440x900 |
| 管理后台窄屏补充 | 1280x800 |

截图核对必须输出差异清单：

| 维度 | 示例 |
|------|------|
| 布局 | 顶部栏高度差 8px、内容区上边距差 12px |
| 字体 | 标题字号小 2px、按钮字重不一致 |
| 色彩 | 背景色偏灰、主按钮色值不一致 |
| 组件 | 卡片圆角过大、输入框高度不对 |
| 图片 | 裁剪比例不一致、素材缺失 |
| 状态 | 空态缺按钮、禁用态颜色不一致 |
| 响应式 | 小屏底部按钮遮挡内容 |

如果环境支持 Playwright，优先用 Playwright 截图；如果不能运行浏览器，必须说明原因，并用静态文件检查和人工差异清单替代。

### Step 5：还原度评分

每个页面单独评分，总分不是主观感受，而是按矩阵扣分：

| 维度 | 权重 |
|------|------|
| 页面结构与信息层级 | 20% |
| 尺寸、间距、对齐 | 20% |
| 字体、颜色、圆角、阴影 | 20% |
| 素材、图标、图片裁剪 | 15% |
| 交互状态与弹窗浮层 | 15% |
| 响应式与安全区 | 10% |

门禁：

| 分数 | 处理 |
|------|------|
| >= 97% | 可交付 |
| 95% - 97% | 可交付，但必须列出剩余差异 |
| 90% - 95% | 不可交付，必须继续修复 |
| < 90% | 需要回到 Step 1 或 Step 2 重建基线 |

关键首屏低于 97% 时，即使总体超过 95%，也必须修复首屏差异。

### Step 6：验收报告

验收报告必须包含：

1. 设计来源和视口。
2. 页面清单与状态清单。
3. token/组件映射说明。
4. 截图证据路径。
5. 差异清单和修复记录。
6. 每页还原度评分。
7. 未闭环问题和原因。
8. 是否达到交付门禁。

---

## 5. 蓝湖 MCP 使用规则

使用蓝湖 MCP 时，必须遵守：

1. 先读取页面节点树，不直接写页面。
2. 先导出或定位关键截图，作为视觉基线。
3. 读取组件尺寸、样式、字体、颜色、素材信息后再编码。
4. MCP 信息缺失时，用截图和设计标注补齐。
5. MCP 返回的节点命名不等于业务字段，必须结合 PRD 或页面规格确认业务含义。
6. 切图、icon、图片无法导出时，必须登记素材缺口，不能用近似素材冒充已还原。
7. 多页面任务必须逐页读取，不得一次性读一堆节点后凭记忆实现。

---

## 6. 允许和禁止

### 允许

1. 使用子代理做只读设计审查、差异复核、截图对比清单。
2. 使用 Playwright 截图和像素差异检查。
3. 使用项目现有 UI 组件承接蓝湖样式。
4. 在设计稿缺失时，用明确假设推进，但必须写入报告。
5. 先做 H5 静态还原，再迁移到小程序/正式前端。

### 禁止

1. 禁止不截图就宣称“已高还原”。
2. 禁止一次性做完多个页面再让用户肉眼找问题。
3. 禁止把蓝湖节点名直接当业务字段。
4. 禁止用项目默认样式覆盖设计稿关键样式后仍打高分。
5. 禁止缺素材不登记。
6. 禁止只做默认态，遗漏空态、弹窗态、错误态。
7. 禁止因为页面能运行就忽略视觉还原。

---

## 7. 默认执行模板

以后收到蓝湖/MCP 还原任务时，Codex 默认按以下话术和动作执行：

```text
我会按蓝湖 MCP 高还原闭环流程处理：
1. 先锁定页面范围、视口、素材和状态。
2. 读取蓝湖/MCP 设计基线并产出 token/组件映射。
3. 按页面逐个实现，不一次性铺完所有页面。
4. 每页实现后截图，列差异清单并修复。
5. 达到还原度门禁后输出验收报告。
```

如果用户要求“直接做”，也必须在内部按上述步骤推进，只是不反复等待确认。
