# 小程序体验版发布与分包缓存校验

2026-10-10 已证实：微信开发者工具可以在 CLI 上传成功、版本号更新的情况下继续打包旧分包。仅核对 Git SHA 和 Taro dist 不足以确认实际上传包。

## 每次发布

1. 按仓库规则重新 fetch 并同步 `origin/master`。相关测试完成后，从当前源码构建生产 dist，关闭 `MINIAPP_DEV_FIXED_LOGIN` 和 `MINIAPP_E2E_MODE`。执行 `postbuild:weapp` 检查。
2. 为本次发布创建全新目录（例如 `.runtime/weapp-release-<时间>-<SHA>/project`），复制本次 dist 与 `miniapp/project.config.json`；不沿用已经被 IDE 编译过的发布目录，不复制 `project.private.config.json`。逐文件核对 SHA-256，记录源码 SHA。
3. 用微信 CLI 对这个新目录 `preview --info-output <文件>`，保留打包后各主包/分包字节数。预览操作只用于包校验，不替代上传。
4. 上传前重新 `git ls-remote origin refs/heads/master`，必须与构建 SHA 一致。远端变化则先同步并重新构建，重新生成发布目录。
5. 对同一独立目录执行 `upload --version <版本> --desc <说明> --info-output <文件>`。逐项比较 preview/upload 的包名和字节数，必须完全一致；保留结果到测试报告。不要仅凭 `upload` 成功就宣称修复已进入体验包。
6. 如必须复用日常开发目录，上传前执行微信 CLI `cache --project <路径> --clean compile` 和 `cache --project <路径> --clean file`，再重新预览核对；无需清空 storage/auth/session，避免破坏登录和用户数据。
