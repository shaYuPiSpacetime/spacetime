## 4. 交互与数据结果

| 需求 | 验收结果 |
| --- | --- |
| 年、月、日均可滑动 | 运行态 1 个 `picker-view`、3 个 `picker-view-column`；自动化读取 `columns=3` |
| 原生惯性与吸附 | 保留微信原生 `PickerView`，未接管触摸和滚动物理参数 |
| 五行视觉 | 仅展示选中项上下各两行；选中、相邻、远端三档字号和色值 |
| 无透明热区 | 五行外使用 `visibility: hidden`；实体覆盖层 `pointer-events: none` |
| 月份天数 | 28/29/30/31 天按年月动态生成 |
| 非法日期收敛 | 请求 `[40,1,30]` 后得到 `[40,1,28]`，闰年 2 月共 29 项 |
| 接口协议 | 继续提交 `saveInitStep(2, { birthday })`，格式 `yyyy-MM-dd` |

## 5. 差异闭环记录

| 轮次 | 发现 | 处理与证据 |
| --- | --- | --- |
| 原截图实现 | 静态点击行不能滑动 | 替换为三列原生 `PickerViewColumn` |
| 蓝湖精确稿 | 年/月/日列中心与五行透视不一致 | 依据原始 PNG 包围盒调整三列中心、字号和上下位移 |
| 蓝湖精确稿 | 原生组件额外露出第六、七行 | 五行之外改为 `visibility: hidden`，保留原生列表布局 |
| 微信运行态 | 选中框内残留原生上下指示线 | 验证 `indicator-style`、颜色覆盖和 `indicator-class` 均无效后，使用不拦截事件的浅蓝实体层闭环 |
| 最终像素复核 | 下边缘剩余 1 像素、RGB 差 1 | 覆盖高度由 `4rpx` 扩至 `6rpx`，复核后内部采样只有一种颜色 |
| 最终纵向复核 | 原生排版起点整体低约 `2rpx` | 滚轮整体上移 `2rpx`，覆盖层同步上移；五行最大误差收敛至 `1.9rpx` |

## 8. 遗留风险

- 不同 iOS/Android 真机的原生阻尼由微信基础库控制；视觉与状态已自动化，发布前仍建议各抽查一台真机的手感。
- 默认年份由后端年龄范围和已有生日决定，设计示例 `1997` 仅用于同值截图，不写入业务默认值。
