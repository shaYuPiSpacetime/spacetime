# 用户准入与资料认证小程序动态配置接入验收报告

## 验收范围

- 微信手机号、手机号验证码登录与首登状态续接。
- 性别、生日、身份、学历、地区五步初始化。
- 基础资料、主页统一详情、标签、关于我、自我介绍、歌曲、微信号。
- 头像、实名、学历三重认证。
- 相册、主页背景图、语音介绍的查询、上传、保存、替换和删除。
- 推荐、社区、消息入口的后端准入状态控制。
- 字典 code、运行时文案、上传数量/大小/格式、语音时长动态配置。
- 小程序申请短时凭证后直接上传 OSS。

## 核心验收结果

1. 枚举选项由 `/miniapp/dict/profile-options` 和地区懒加载接口提供，业务表与提交参数只使用 code。
2. 页面文案通过 `/miniapp/config/prd01.copywriting` 的 copyKey 消费；迁移脚本只补缺失 copyKey，不覆盖已有运营内容。
3. 登录后及每个首登步骤均以后端 `firstLoginCompleted/nextStep` 决定跳转，不再进入旧的 `/pages/verification/basic` 流程。
4. 首页、编辑资料和个人中心读取基础资料、认证状态及主页统一详情，不再读取蓝湖演示资料。
5. 头像、学历材料、相册、背景图、语音均先申请 5 分钟 OSS 表单凭证，再由 `Taro.uploadFile` 直传；客户端不包含 AccessKey Secret。
6. OSS policy 同时限制唯一对象 Key 和最大字节数，后端签发前再次校验配置中的扩展名和大小。
7. 语音格式、大小、最短/最长时长来自 `prd01.upload.rules` 的 `voice` 配置行，业务服务与客户端使用同一配置源。
8. 相册、背景图和语音页面使用后端审核状态、驳回原因和 `canSubmit`，不在客户端推断审核枚举。

## 已知环境与历史门禁项

- `npm run build:weapp` 的业务前置门禁可依次通过登录、头像、消息 18 稿、认证跳转、固定登录和资料导航检查；随后被既有 `validate-profile-preview-lanhu.mjs` 阻断，原因是旧主页预览组件当前的认证按钮 padding 与该历史蓝湖像素断言不一致。该组件不属于本次 PRD01 运行链路。绕过前置脚本直接执行 `npx taro build --type weapp` 已成功。
- 全仓 TypeScript 检查仍包含 Taro 依赖声明和旧会员/旧认证页面的既有错误；本次变更文件的定向类型检查无错误。
- 当前环境没有可用的测试账号、数据库配置和 OSS 凭证，因此未执行真机上传及 OSS 实对象写入。上线联调前需在微信公众平台把各环境响应的 OSS Bucket Host 加入 `uploadFile` 合法域名，并用真实账号分别验证公有媒体和学历敏感材料访问权限。
