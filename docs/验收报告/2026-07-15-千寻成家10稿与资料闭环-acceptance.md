## 根因与闭环结果

| 问题 | 根因 | 闭环结果 |
| --- | --- | --- |
| 固定 Token 开启仍跳登录 | 启动页和运行态使用两套开关，普通构建还会覆盖开发产物 | 统一为 `MINIAPP_DEV_FIXED_LOGIN`；`dev:weapp` 默认开启，`dev:weapp:login` 显式关闭；当前 `dist` 首页已核对为 `pages/index/index` |
| 更多照片第二行上传不回显 | 运行时相册上限仍为 3，历史数据顺序异常时前端又会压缩槽位 | 配置迁移调整为 6；前端按 `sortOrder=0..5` 稳定合并；用第 4 槽实际执行新增、查询回显和清理，回显槽位为 3 |
| 标签文字自行换行、无色彩 | 主页预览按演示数据写死四个宽度，三个页面各自渲染 | 统一 `ProfileTagChip`，根据真实 code 稳定配色；色块内 `nowrap`，色块之间 `flexWrap` |
| 千寻数据与设计状态断开 | 原页面未按关注/同城/热门场景请求，作者还误读后台用户表 | 服务端增加 `FOLLOWING/CITY/HOT` 查询语义，统一读取 `app_user`；前端对接真实列表、关注、点赞、举报和发布接口 |
| 认证成功后分流不稳定 | 页面容易自行拼认证条件或使用假数据 | 核心准入只消费后端 `coreAccessStatus`；关注和同城空态只根据实际接口 total 渲染 |
