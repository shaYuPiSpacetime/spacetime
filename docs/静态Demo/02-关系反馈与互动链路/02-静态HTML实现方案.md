> 方案日期：2026-07-13

## 1. Demo 目标

1. `html/index.html` 直接打开即进入可操作的“心动”移动端 Demo，不先展示营销式总览页。
2. 真实还原喜欢我的、最近看过我的、相互喜欢三页的字段、按钮、空态、准入拦截、网络失败和加载状态。
3. 用本地状态完整串联“模糊卡片 -> 单条解锁场景弹窗 -> 千寻币确认/余额不足 -> 当前卡片清晰”的核心闭环。
4. 删除旧 Demo 中已经废弃的匹配成功弹窗、前台失效态、筛选胶囊、曝光入口、聊天按钮、来源直出和写死 20 千寻币。
5. 所有数据与交互仅使用本地 Mock，不请求接口、不依赖登录态、不产生真实支付。
6. 视觉按仓库内 2026-07-10/13 已验收微信运行截图、Token 与运行切图重建；原始蓝湖节点/标注未随静态包提供，因此可声明“已验收运行态基线还原”，不声明相对原始蓝湖像素 1:1。

### 5.1 本地状态结构

```js
const state = {
  page: 'likes',
  pageMode: { likes: 'normal', viewers: 'normal', mutual: 'normal' },
  walletBalance: DemoData.wallet.balance,
  visibleCount: { likes: 6, viewers: 6, mutual: 4 },
  unlockedRecordNos: new Set(DemoData.initialUnlockedRecordNos),
  vipActive: false,
  modal: null,
  selectedRecordNo: null,
  pendingScene: null
};
```

渲染顺序固定为：先按业务状态过滤异常对象，再计算模糊/清晰展示状态，最后按 `visibleCount` 截取当前页数据。内部失效样例不得进入前台 DOM。

## 10. 错误处理与无障碍

1. 弹窗均支持右上关闭、遮罩关闭、`Escape` 关闭；关闭后焦点回到触发按钮。
2. loading 期间主操作按钮 `disabled`，防止重复扣币；失败后恢复按钮且资产不变。
3. 网络错误保留上次数据并显示可重试提示，不使用空白页代替错误态。
4. 核心准入拦截不把真实关系列表留在 DOM 中，避免演示中泄露内容。
5. 头像均有 `alt`；图标按钮有 `aria-label` 与 `title`；状态徽标不只依赖颜色。
6. 手机窄屏隐藏桌面演示控制台，真实页面按钮触达高度不低于 44px。
7. 所有动态文案使用 `textContent` 或安全模板转义，Mock 文本不直接插入未转义 HTML。
