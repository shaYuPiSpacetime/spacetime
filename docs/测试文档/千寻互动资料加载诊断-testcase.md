# 千寻互动资料加载诊断 - 测试用例

日期：2026-10-09。范围：判断“资料已完善却提示资料审核中”是数据还是页面加载逻辑。基线 master b4fd8886；仅诊断，不修改业务代码或用户数据。

| ID | 场景 | 正确预期与诊断目标 |
|---|---|---|
| DIAG-01 | 本人资料尚未返回，登录缓存没有昵称 | 应表达加载状态；检查是否未经审核判断就显示审核中。 |
| DIAG-02 | 本人资料接口失败 | 应提示加载失败/重试，不能表示真实审核中。 |
| DIAG-03 | 本人资料成功返回昵称及基础资料 | 应显示服务端本人资料。 |
| DIAG-04 | 本人资料失败，但社区 profile-summary 成功返回身份与统计 | 检查 summary 是否能恢复身份；不以错误审核状态代替加载失败。 |
| DIAG-05 | 互动列表某个请求持续未返回 | 检查其是否使统计、其他列表都无法展示，骨架持续保留。 |
| DATA-01 | 查询原号码对应账号与最新审核记录 | 只读事务查询；不以历史用户 ID 代替当前账号。 |
| DEVICE-01 | 原截图手机的接口、登录 userId 和版本 | 需要原设备/会话，未取得时不推断具体失败请求。 |

派生诊断脚本放在 `tmp/qianxun-profile-loading-diagnosis.cjs`，直接执行当前源码中的初始化与加载函数，模拟接口慢响应和失败，不伪造线上登录。执行结果写入同目录 testreport。
