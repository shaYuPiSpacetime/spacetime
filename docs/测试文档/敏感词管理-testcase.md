## 策略

后端新增 7 个 API、跨资料/社区公共安全入口与词库缓存，A=2 B=1 C=2 D=1 E=2 F=1，总分 9，选择 L1/L2/L3；前端 G/H/J 命中，选择 L4。L1/L4 按已有环境可用性执行；不可用需记录跳过与原因。初始化另做空表一次性写入、已有数据整批跳过和事务回滚核查。

| L3-02 | 非法分类、不存在记录 | 返回业务错误，不写入 |
| L3-03 | 新增、编辑、启停、逻辑删除及多人编辑 | 编辑和删除按 ID 执行，不要求记录版本；多人编辑以最后一次成功保存为准；已删除记录不能被编辑恢复；实际维护成功后更新服务端词库刷新标记；状态 PATCH 只改 status；相同目标状态幂等不增加标记 |
| L3-04 | 字面词、单字符、重叠词、全半角/大小写、网址 | 统一规范化后匹配；正则符号按字面；超长词可匹配 |
| L3-05 | 提交后预热、多次校验及词库变化 | 提交成功后才异步重建，回滚不刷新；同标记复用索引；新增/修改/启停/删除后的新检查使用新快照或故障跳过；新树与元数据、标记原子替换 |
| L3-06 | 初始化缺失、词库连接/查询失败、版本读取/重建异常 | 跳过本地检查，继续调用微信；内部记录跳过原因，最终结果完整保留微信 PASS/REJECT/REVIEW/UNAVAILABLE；只读池启动失败不阻断应用启动 |
| L3-07 | 本地命中 | 微信 HTTP/Token 均不调用，返回 REJECT 与本地来源/分类证据 |
| L3-08 | 本地未命中 | 调用微信并完整保留 PASS/REJECT/REVIEW/UNAVAILABLE |
| L3-09 | 图文及空正文 | 正文命中短路图片审核；无正文继续原图片逻辑 |
| L3-10 | Provider 映射与 C 端隐私 | 本地拒绝 safe=false、来源 local-sensitive-word；证据使用独立 evidenceJson，固定 detail/rejectReason 不含词库内容；资料、社区所有 C 端返回均不含命中词明细；参见 L3-21/DB-07 |
| L3-11 | 资料/动态/诚意贴/评论状态回归 | 本地 REJECT 与原微信 REJECT 一致；诚意贴通过仍人工；评论拒绝仍回执不公开 |
| L3-12 | 本地不可用后各业务处理 | 资料、动态、诚意贴、评论继续微信审核，状态和回执与本地未命中后收到相同微信结果时一致；不因本地故障额外转人工或提示重试 |
| L3-13 | 本地不可用后图文审核 | 继续微信文字审核；微信文字通过才继续图片审核，文字拒绝仍短路图片；诚意贴机审通过后仍需人工 |
| L3-14 | 本地异常恢复 | 故障期间继续微信；词库恢复且新索引构建成功后重新检查敏感词，命中时仍拒绝且不调用微信；旧版本有效性未知时不用于拒绝 |
| L3-15 | 本地异常边界与事务 | 本地读取/匹配异常被限定处理，不令健康业务事务仅因本地失败而 rollback-only；微信自身异常及业务校验/保存失败仍执行原规则 |
| L3-16 | 跳过记录及 C 端 | 服务端记录本地跳过及原因，不伪造本地匹配通过；C 端不增加词库故障提示，沿用后续业务回执 |
| L3-17 | 提交后任务拒绝、刷新通知遗漏、另一实例或进程重启 | 已提交的保存不误报失败；后续审核通过主库标记发现变化，重建或故障跳过，不依赖主动通知送达 |
| L3-18 | 连续修改及并发审核 | 每实例最多一个构建任务，连续修改合并；构建前后标记变化需重试，不能发布混合数据或用较旧快照覆盖较新快照；请求不重复构建 |
| L3-19 | 外层业务事务已有旧读视图 | 专用只读池的新自动提交会话从主库获取新标记和词条，不被外层旧快照、查询缓存或副本延迟影响；刷新失败不污染业务事务；真实验证见 DB-04/05 |
| L3-20 | 保存成功与在途审核的生效边界 | 提交后开始检查的请求看到新标记，更新成功用新快照，异常按规则跳过；提交前已开始的请求可完成旧快照检查 |

## 回归方法与环境边界

1. 既有 DATA-01…05、L2-01…03、L3-01…20、L1-01、L4-01…04 全部保留，追加用例不是替代。既有 L2-01 的接口口径统一为七个接口。
2. DATA-02/04 在隔离测试表/专用测试库中做非空跳过、故障回滚和并发初始化；不得在用户真实词库上清空数据做测试。
3. L3-01/05/15/17/18/19/20 的 Mock/纯逻辑部分不能证明锁和真实事务；对应 DB-01…06 提供真 MySQL 与实际 Spring 代理/读会话证据。H2 与手动调用 afterCommit 均不能替代。
4. 外部微信以实际适配器加受控 HTTP/Token 传输验证完整分支，覆盖 本地 PASS/UNAVAILABLE × 微信 PASS/REJECT/REVIEW/UNAVAILABLE × 资料/普通动态/诚意贴/评论；本地 REJECT 验证 HTTP/Token 零调用。另验证纯媒体、空正文、Mock Provider、机审关闭分支。真实微信凭证/有效 openId/样本缺失时单列外部联调未执行，不伪造在线结果。
5. L1/L4 优先读取 frontend/e2e-tests/.env 的真实地址和有效会话；不从 Redis 任意冒用其他用户 Token，不编造账户权限。开发数据库内的测试词通过接口自建并仅清理自身。
6. 性能测试给出样本数量、线程数、预热、测量分布与环境；本轮设计不把独立实验的 0.4/0.6 s 设成生产硬 SLA。持续异常情况下验证有界等待与资源回收，不能只核查注解。
7. 所有 ID 必须进入 testreport 的逐项矩阵，标明 PASS/FAIL/NOT_RUN/BLOCKED、测试方法/脚本、证据路径。P0/P1 未完成不能标整体通过；用户要求全部回归时，任何未执行项都须明确列出，不以汇总“编译通过”替代。
