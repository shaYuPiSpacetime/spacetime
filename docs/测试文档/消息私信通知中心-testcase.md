## 1. 测试范围与策略

本轮覆盖 PRD-03 的 14 张新增表、消息正文留存、TIM 单一映射、Inbox/Outbox 可靠任务、会话与悄悄话
状态机、移动端后端接口、管理后台元数据接口及敏感正文访问边界。不实现小程序前端，不以本地 Mock
替代腾讯云 TIM/KMS 联调结果。

| 维度 | 评估 | 得分 |
|------|------|------|
| 接口数量 | 移动端、回调和管理后台多组接口 | 2 |
| 状态流转 | 会话、悄悄话、Inbox、Outbox、配置版本 | 2 |
| 数据关联 | 14 张新表及关系、资产、举报表 | 2 |
| 第三方依赖 | TIM、KMS、微信订阅消息 | 2 |
| 安全权限 | 正文白名单、案件复合授权、审计 | 2 |
| **后端合计** | **高复杂度** | **L1 + L2 + L3；外部环境具备后补真实联调** |

## 7. 通过标准

1. P0 自动化用例全部通过，既有消息模块基线失败已单独说明或修复。
2. 14 张表、三项结构修正与 Java 实体/DAO/Mapper 保持一致。
3. 构建通过，普通接口响应类型中不存在 `contentText` 或可还原正文的摘要。
4. TIM/KMS 外部资源缺失时只允许标记未联调，不得宣称生产闭环完成。
5. 测试执行结果写入 `docs/测试文档/消息私信通知中心-testreport.md`。
6. 本地数据库至少选择 2 个真实 `app_user`，构造并通过接口核验私信、悄悄话、系统/助手和举报数据；不得使用前端写死数据冒充流程通过。
