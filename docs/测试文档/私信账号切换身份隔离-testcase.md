# 私信账号切换身份隔离 - 测试用例

日期：2026-10-12。依据：用户 120/1052 的腾讯云双向与自身漫游历史、`authStore`、懒加载网关和私信页面。

## 策略与数据

无后端接口或数据库结构变更。执行小程序 L3 行为回归、消息既有定向门禁与生产构建。真实手机前台切号验收独立记录，不能以管理端 REST 投递代替。
自动化使用内存 SDK 与登录态，不请求真实短信、不输出 UserSig。真实数据仅只读核对。

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| IM-AUTH-P0-01 | P0 | 用户 A 登录聊天，退出，验证码登录 B 给 A 发消息 | 旧 SDK 已销毁，新消息 from=B、to=A |
| IM-AUTH-P0-02 | P0 | 无退出直接切换业务账号 | 认证代次变化，旧网关同步失效 |
| IM-AUTH-P0-03 | P0 | 登录尚未完成时退出 | 迟到的 SDK_READY 不恢复旧身份 |
| IM-AUTH-P0-04 | P0 | 切号后旧页面仍持有网关 | 发送拒绝，SDK sendMessage 不执行 |
| IM-AUTH-P0-05 | P0 | 目标 TIM 身份等于当前身份 | 发送和重试均拒绝，不产生自发消息 |
| IM-AUTH-P1-06 | P1 | 同账号资料更新、主页返回 | 复用现有网关，不重新连接，不改变滚动 |
| IM-AUTH-P1-07 | P1 | 旧连接登录在切号后完成 | 旧事件、发送结果不进入新账号页面 |
| IM-AUTH-P1-08 | P1 | 异步凭证返回期间切号 | 页面在初始化前后检查代次，拒绝旧请求 |
| IM-AUTH-M-09 | P0 | 真机分别微信授权/验证码登录，双向连续发送、主页返回 | 双方正文一致，顺序稳定，返回位置保留 |
| IM-AUTH-P1-10 | P1 | 同账号换 Token、checkLogin 恢复另一账号的本地登录态 | 旧连接立即失效，恢复的新账号使用对应 IM 身份 |

派生脚本：`miniapp/scripts/test-message-auth-session.cjs`。既有门禁：`npm run validate:message-closure`。
