## 3. 本轮发现并修复的问题

| 编号 | 问题 | 根因 | 修复 | 验证 |
|---|---|---|---|---|
| SM-BUG-01 | 用户、角色、菜单、字典类型、字典数据五类表单缺必填项时点击保存静默无响应 | 保存函数仅直接 `return`，没有用户反馈 | 统一使用现有 Toast 错误提示，保持弹窗和输入状态 | 5 个专项回归先失败后通过；真实浏览器复核 |
| SM-BUG-02 | 退出偶发 401 和重复跳转，可能打断紧接着的重新登录 | 先清本地 Token，再发退出请求，导致请求没有认证头 | 退出前保存 Token，并显式携带到退出请求 | 退出 Token 专项回归通过；全流程多次账号切换通过 |
| SM-BUG-03 | 用户、角色和字典类型搜索结果会被较早请求的晚到响应覆盖 | 三个列表都允许并发请求无条件更新 React 状态 | 为每个列表增加递增请求序号，只允许最新请求更新列表、总数和 loading | 3 个乱序响应专项回归先失败后通过；真实字典搜索复现修复 |
| SM-BUG-04 | 登录失败只显示泛化的“登录失败，请重试”，丢失服务端明确原因 | 请求拦截器抛出 `Error(msg)`，登录页只读取 Axios `response.data.message` | 同时读取 `msg`、`message` 和标准 `Error.message` | 登录失败专项回归通过；真实错误密码流程通过 |
| SM-BUG-05 | 1265px 桌面宽度下用户表格被强行压缩，状态、角色和日期逐字换行 | 表格容器可滚动，但 8 列表格没有最小宽度 | 用户表格设置 1120px 最小宽度，窄窗口使用横向滚动 | 布局专项回归通过；内置浏览器截图复核 |
