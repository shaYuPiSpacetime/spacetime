# 动态重提与理想型年龄测试用例

## 范围与策略

用户反馈：编辑重提后返回“我的动态”，卡片仍显示发布失败；理想型筛选结果需展示真实周岁，不展示年龄区间。
采用轻量问题回归：React 真实页面与服务调用测试、后端 JUnit 服务测试、微信正式构建。无有效登录测试凭证，不伪造线上 L1；真机流程单独待验收。

| ID | 场景 | 预期 |
| --- | --- | --- |
| RESUBMIT-01 | 驳回动态重提返回 pending_manual，旧列表请求迟到或新列表失败 | 两处我的动态立即替换成新帖并显示审核中，旧失败原因清除 |
| RESUBMIT-02 | 重提接口再次返回 rejected | 保留真实驳回状态并提示再次审核未通过，不伪装成审核中 |
| RESUBMIT-03 | 重提请求失败 | 旧动态保留，不发出成功替换事件 |
| RESUBMIT-04 | 重提成功后后台审核更新 | 返回列表重新查询并展示服务端最新状态 |
| RESUBMIT-05 | 点击两处“我的动态”的发布失败标签 | 展示本条动态审核原因，可关闭；重提再次驳回则提交后直接弹窗 |
| AGE-01 | 未解锁理想型结果，候选人 28 岁 | 显示 28岁；头像、身份与主页解锁规则不变 |
| AGE-02 | 出生日期与缓存年龄不一致，生日已到/未到 | 以北京时间生日计算周岁 |
| AGE-03 | 无出生日期 | 有历史年龄则显示该年龄；都没有则年龄保密 |

真机验收：修改驳回动态正文重新提交，返回查看状态并点击失败查看原因；筛选理想型查看未解锁与已解锁候选人的年龄。

生产只读诊断：按用户授权账号的哈希定位，仅查询状态、版本、审核码和实际命中规则，不查询或输出手机号、正文、图片、凭证；不修改审核结果或词库。
