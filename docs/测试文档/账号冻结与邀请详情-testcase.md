# 账号冻结与邀请详情 - 增量测试用例

## 1. 范围与依据

- 对应反馈 1、3、4；反馈 2 不在本次范围。
- 需求依据：APP-13《核心准入拦截态》、ADM-07《邀请关系详情页》《邀请奖励流水页》。冻结应展示账号异常说明与客服入口；邀请关系列表和奖励流水的“查看关系”共用详情。
- 复杂度：跨后端准入状态与小程序页面分支，另有普通邀请空代理 ID 边界；采用增量 L3、页面渲染/交互回归及小程序构建。没有数据库迁移。

## 2. 后端 L3

| ID | 优先级 | 条件与操作 | 预期 |
|---|---|---|---|
| ACCESS-01 | P1 | 冻结账号，首登未完成/已完成，查询准入 | 返回冻结状态、账号异常原因；五项能力全部关闭，不返回完善资料原因 |
| ACCESS-02 | P1 | 正常账号尚未完成资料 | 保持资料未完善拦截 |
| ACCESS-03 | P1 | 冻结后解冻，资料和认证均完成 | 恢复 CORE_ALLOWED 与全部能力 |
| ACCESS-04 | P1 | 正常账号完成基础资料、认证未全过 | 保持 NON_CORE_ONLY，仅浏览与社区开放 |
| REL-01 | P1 | 普通邀请 agentId 为空，有成功/失败奖励 | 正常返回来源、邀请对象、奖励明细；合计仅包含成功金额；不查询代理 |
| REL-02 | P1 | 普通邀请 agentId 为空，无奖励 | 正常返回空奖励列表与零合计 |
| REL-03 | P1 | 校园推广员邀请，存在代理信息和奖励 | 保留代理来源、人民币奖励和合计 |
| REL-04 | P2 | 邀请关系不存在 | 返回业务 404，不触发详情关联查询 |

## 3. 小程序行为回归

使用现有 TypeScript 编译器加载实际页面与组件；仅替换 Taro、数据请求和 Hook 运行环境，不依赖源码正则验证修复。

| ID | 优先级 | 条件与操作 | 预期 |
|---|---|---|---|
| UI-01 | P1 | 千寻/我的收到冻结状态（含资料未完成） | 展示冻结说明，不渲染完善资料和认证入口 |
| UI-02 | P1 | 冻结提示点击主操作 | 进入现有帮助与客服页 |
| UI-03 | P1 | 冻结提示刷新失败 | 保留冻结说明，允许重试，不能进入认证 |
| UI-04 | P1 | 原本正常的千寻页面收到冻结状态 | 冻结提示优先于已缓存的内容可见状态 |
| UI-05 | P1 | 冻结状态刷新后变正常 | 正常进入对应页面；普通未认证用户仍有认证入口 |
| UI-06 | P2 | 旧缓存不含新增账号状态字段 | 正常渲染，不产生运行异常 |

## 4. 环境验收

| ID | 层级 | 优先级 | 操作与预期 |
|---|---|---|---|
| ENV-01 | L1/L4 | P1 | 使用测试环境已有普通邀请，从关系列表和奖励流水分别查看关系；均应展示同一关系及事件时间线，无系统异常 |
| ENV-02 | 真机 | P1 | 测试账号登录后冻结，切换千寻/我的/消息/心动；显示冻结提示；解冻刷新后恢复 |

不修改生产数据；环境与可用测试账号不足时在独立测试报告标注未执行及原因。构建使用项目的 `npm run build:weapp`，后端使用指定 JDK 的定向 Maven 测试。
