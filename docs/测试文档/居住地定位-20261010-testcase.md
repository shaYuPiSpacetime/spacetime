# 居住地获取定位测试用例

范围：登录资料“你的居住地 → 获取定位”；增量验证生产地图配置传递与失败提示，不改地区字典及存储规则。

| ID | 场景 | 预期 |
|---|---|---|
| DEP-01 | 给部署环境注入测试地图 Key，执行真实 write_runtime_env 函数 | 生成的容器环境文件保留 Key 和两个超时值 |
| DEP-02 | 未配置地图 Key | 不产生假 Key，保留手选能力；只提示配置缺失，不输出密钥 |
| DEP-03 | 后续部署 | 发布流水线执行地图配置传递回归 |
| UI-01 | 微信坐标与省市解析成功 | 选中匹配城市，关闭弹层，释放 loading |
| UI-02 | 微信取坐标失败 | 区分权限、定位关闭、超时；未知失败提示重试或手选 |
| UI-03 | 已获得坐标，城市服务失败 | 显示城市识别失败，不误报手机未授权；保留手选 |
| UI-04 | 连续点击获取定位 | 同步锁仅执行一条定位链，失败后允许重试 |
| OPS-01 | 生产只读诊断 | 仅输出源配置/容器配置是否存在、是否一致、腾讯状态码与公共上海测试坐标匹配布尔值；不输出密钥、URL或用户坐标 |
| MAN-01 | 微信真机授权并定位 | 实际城市正确，拒绝授权仍可手选 |

本机执行 Node 配置/页面回归及小程序构建；线上只读审计使用已有部署通道。真实用户会话与手机未接入，真机验收单独记录，不用 Mock 冒充。
