## 1. 测试范围与策略

### 1.1 范围

1. 8 张关系事实表、`app_user` 与 `app_user_unlock_record` 增量字段、权限种子和历史状态迁移。
2. 喜欢、访客、匹配、匹配来源、匹配弹窗、失效、匿名化和解锁关联的公共领域规则。
3. App 用户列表关系准入/VIP 筛选、独立统计接口、关系摘要和四类明细接口。
4. 管理后台卡片入口、摘要、Tab 懒加载、10/20/50 分页、权限裁剪、匿名态和异常态。
5. 中文 DDL 注释、Java 枚举说明和前端中文映射的一致性。

### 1.2 测试策略决策

| 维度 | 评估 | 得分 |
|------|------|------|
| A 接口数量 | 修改列表并新增 5 个关系查询接口 | 2 |
| B 状态流转 | 喜欢、访客、匹配、来源、弹窗、解锁多状态联动 | 2 |
| C 规则复杂度 | 30 分钟归并、7 天精确统计、多来源单一匹配 | 2 |
| D 数据关联 | 关系表、用户、资产、审计等 4 张以上表 | 2 |
| E 既有代码影响 | 修改 App 用户核心列表与统一状态变化点 | 2 |
| F 安全变化 | 新权限、资产二次权限和失败关闭审计 | 1 |
| **后端合计** | **11 分** | **L1 + L2 + L3** |

| 前端条件 | 是否命中 | 说明 |
|----------|----------|------|
| G 多角色权限差异 | 是 | 关系权限、资产权限影响入口、筛选和字段 |
| H 复杂交互 | 是 | 弹窗、Tab 懒加载、筛选与分页联动 |
| I 多区域联动 | 是 | 用户卡片、模块补充弹窗和用户详情跳转 |
| J 核心业务页面 | 是 | App 用户管理为高频后台页面 |

**最终策略：L1 + L2 + L3 + L4 + 手工验收。**
