# 学校字典与歌曲保存测试用例

## 1. 测试范围

- C 端公开学校搜索接口及“本地优先、少于 10 条补三方、幂等回写、异常降级”。
- 基础资料与学历认证的 `schoolCode` 兼容保存。
- 小程序基础资料、四种学历认证表单的学校搜索接入。
- 登录态歌曲搜索、保存爱听歌曲、主页详情反查。

复杂度评分 4（外部数据源分支 1、数据库变更 1、核心服务逻辑 2），采用 L1 + L2 + L3；本次无可用微信开发者工具自动化环境，不执行 L4。

## 2. 用例

| ID | 级别 | 场景 | 预期 |
| --- | --- | --- | --- |
| SCHOOL-01 | L2 | 本地命中 10 条 | 不调用三方，直接返回本地 |
| SCHOOL-02 | L2 | 本地少于 10 条 | 调用 GuGuData、upsert、重新查本地 |
| SCHOOL-03 | L2 | `limit=5` 且本地 5 条 | 仍按固定阈值 10 调用三方，最终只返回 5 条 |
| SCHOOL-04 | L2 | 三方异常 | 不影响接口，降级返回已有本地数据 |
| SCHOOL-05 | L2/L3 | 三方请求协议 | AppKey 仅放 Header，参数和真实字段映射正确 |
| SCHOOL-06 | L1 | 两次搜索“浙大” | 两次 `code=200`，存在稳定编码、学校名及院校标签 |
| SCHOOL-07 | L1 | 重复搜索后查库 | provider UUID 不产生重复记录 |
| MINIAPP-01 | L3 | 基础资料学校编辑 | 调用学校接口，选择保存 name+code，手改清空 code |
| MINIAPP-02 | L3 | 四种学历认证方式 | 均使用学校搜索并按需提交 `schoolCode` |
| SONG-01 | L1 | 登录后搜索“晴天” | 返回可保存的歌曲 ID、名称、歌手、封面 |
| SONG-02 | L1 | 保存爱听歌曲 | `PUT` 返回 200 和完整歌曲四字段 |
| SONG-03 | L1 | 重新查询主页详情 | 返回的歌曲 ID 与保存结果一致 |
| REG-01 | L2 | 资料与认证回归 | 原有 Profile/Verification 单测全部通过 |
| BUILD-01 | L3 | 小程序契约与真实构建 | PRD01 门禁通过，Taro 微信小程序编译成功 |

## 3. 测试数据

- 学校关键词：`浙大`。
- 歌曲关键词：`晴天`。
- 登录用户：测试时动态生成手机号，只在报告保留脱敏号码。
- 三方 AppKey：由本地私有环境变量注入，不写入脚本、文档或日志。
