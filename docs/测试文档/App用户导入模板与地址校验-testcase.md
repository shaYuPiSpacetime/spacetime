# App 用户导入模板与地址校验 - 测试用例

日期：2026-10-15。轻量模式、增量缺陷修复；本文件为测试设计源头。

## 策略与安全边界

使用 Node 纯函数测试、Java L3 Mockito、既有 Controller 回归和管理端构建。L1 真实导入会写库，本次不执行；没有用户确认的独立空库和导入数据，不以“预校验”名义发送写入请求。L4 下载交互使用本地页面和只读/模拟数据验证，不提交实际导入。

## 输入文件诊断记录（不是系统异常根因结论）

男性 v18：72 列、200 行；头像与相册每行单张 URL 均超过审核表 500 字符限制。200 个输入手机号当前已在库；不得删除或替换手机号绕过重复保护。生日/年龄/星座不一致及未成年行仅报告，不擅自修改身份数据。截图导入女性 v17，与该附件不同。

## 审查补充用例

| ID | 来源/优先级 | 场景 | 期望 |
|---|---|---|---|
| REV-P1-01 | Important/P1 | 有生日且年龄为空或不匹配 | 导入时按生日计算年龄，和星座一样以生日为准 |
| REV-P2-02 | Important/P2 | 无生日、仅年龄 | 兼容旧文件的年龄输入 |
| REV-P1-03 | Important/P1 | 毕业生同时填两类材料 | 学历审核使用毕业证材料，不误选学生证 |
| REV-P1-04 | Important/P1 | 学生同时填两类材料 | 学历审核使用学生证，不误选毕业证 |
| REV-P2-05 | Important/P2 | 显式 educationMaterialUrls | 保留已有规范字段优先级 |

当前数据库配置将两类学历材料都标为必填，因此全字段示例保留两列格式示范；本次不变更用户的必填配置。选择审核材料必须按学历人群进行，不能依赖表头顺序。
