# 后台登录过期 - 测试用例

日期：2026-09-09。范围为 React 管理端登录状态、Axios401处理和路由跳转；后端权限规则不变。按系统排查/code-test流程，先复现再修复。L4受控错误覆盖边界，真实peter登录→正常注销使会话失效→旧浏览器访问→重新登录验证闭环。地址读取frontend/e2e-tests/.env，凭据仅从运行时环境读取；不清理无关localStorage，不更改词库或业务数据。

| ID | 优先级 | 场景 | 期望 |
| --- | --- | --- | --- |
| AUTH-01 | P0 | 旧token请求收到HTTP401 | 同时清理内存token/user、token键和auth认证缓存，停留登录页，主文档不循环重新加载 |
| AUTH-02 | P1 | 历史残留auth但token键缺失/两者不一致 | 页面启动清理不一致认证状态，登录页可用，不跳回后台 |
| AUTH-03 | P1 | 多个并发接口返回401 | 一次退出会话，无硬刷新风暴，后续迟到401不重复导航 |
| AUTH-04 | P1 | HTTP200且业务code401 | 与HTTP401同样清理当前过期会话 |
| AUTH-05 | P1 | 登录接口返回401 | 登录表单保留、展示服务端原因，不刷新页面，不删除无关存储 |
| AUTH-06 | P1 | 重新登录后旧请求迟到401 | 按发出请求时的token区分会话，旧401不能清除新token/user |
| AUTH-07 | P1 | 主动退出 | 立即清理本地认证状态；正常注销请求使用原token，注销失败不阻挡重新登录 |
| AUTH-08 | P1 | 非401错误 | 403/500/网络失败不当作过期登出，保持原会话 |
| AUTH-09 | P0 | 真实失效会话恢复 | 正常peter登录，使用注销接口使该测试会话失效；浏览器自然处理401后可重新登录，不手动清除localStorage |
| AUTH-10 | P1 | 旧权限/菜单响应在重新登录后返回 | 不覆盖新会话权限和菜单，不恢复已清理的旧会话数据 |


## 执行范围与映射

- AUTH-01～08、AUTH-10 → `frontend/e2e-tests/tests/auth-session-expiry.spec.ts`，参数化后共14项受控浏览器测试；所有后端请求均被明确限定到 `/api/` 的拦截规则接管，测试凭据不发送到真实后端。
- AUTH-09 → `frontend/e2e-tests/tests/auth-session-expiry-real.spec.ts`，使用真实账号及正常登录、注销、权限、敏感词列表接口，不 mock、不注入登录状态。正常注销仅撤销本次新建的测试会话，以复现服务器已不认可浏览器旧 token 的条件；不修改 TTL 配置。
- 关联回归 → `frontend/e2e-tests/tests/sensitive-words.spec.ts` 中13项既有用例，验证列表、筛选、权限、增删改及状态交互。其设计依据仍为 `敏感词管理-testcase.md`。
- 生产构建 → `frontend` 目录执行 `npm run build`。后端无代码变更，不安排新的 L2/L3；真实接口断言包含在 AUTH-09 中，不重复计数为独立 L1。
- 受控边界测试通过 Vite 已加载的模块 URL 访问运行中的认证实例（兼容 HMR 参数），只适用于开发服务器。真实浏览器脚本不依赖源码模块 URL。
