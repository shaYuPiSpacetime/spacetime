# 理想型解锁后查看主页定向用例

## 本次口径

当前筛选结果中的用户解锁成功后，卡片保留在原位置，展示审核通过的清晰头像，操作变为“查看主页”；用户点击后才进入对应主页。已解锁项不再参与本页或勾选解锁报价。

| 场景 | 预期 |
| --- | --- |
| 单人解锁成功 | 原卡片立即变为查看主页并显示回执中的清晰头像，不自动跳转、不重置滚动位置 |
| 点击查看主页 | 使用解锁对象身份进入统一主页，带 sourceScene=ideal，不再次报价或扣币 |
| 勾选多人/本页解锁 | 成功项保留，刷新结果后均显示清晰头像；已解锁项不再参与选择或报价 |
| 当前结果刷新/重新进入 | 根据有效权益返回已解锁状态和公开资料，不重新变为未解锁 |
| 当前页解锁后翻页 | 原卡片顺序与游标稳定，下一页不跳过候选 |
| 解锁失败 | 保持未解锁状态和模糊头像，不跳转主页 |
| 解锁成功但刷新失败 | 保留成功回执状态，禁止再次触发该人的解锁报价；可点击查看主页或重试加载 |
| 权益过期/账号不可用/双向拉黑 | 不返回不应可见的清晰资料，现有权限校验继续生效 |

## 交付检查

- 后端定向测试与前端真实组件事件回归。
- 当前 master 生产构建，通过既有门禁；新独立目录逐文件哈希和预览/上传各分包字节一致。
- Push master 后核对对应后端自动部署与公网健康接口；真实扣币和真机测试仅在具备测试环境、账号时执行，不替真实用户消费千寻币。
