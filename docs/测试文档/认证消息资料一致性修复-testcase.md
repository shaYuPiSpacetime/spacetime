# 认证消息资料一致性修复测试用例

## 测试范围与等级

- 复杂度：L3（跨后端、小程序、审核投影、登录与 IM）。
- L1：不执行，当前未提供可用线上账号、短信接收号码和认证材料。
- L2：执行后端 JUnit 服务测试。
- L3：执行小程序 Node 合约测试、TypeScript/构建门禁。
- L4：不执行，当前没有可操作的微信开发者工具登录态和双用户 TIM 测试账号。

## 用例

| 编号 | 场景 | 预期 |
|---|---|---|
| TC-01 | 已有生效学历后通过基础资料修改学校或学历 | 服务端拒绝，认证快照不被覆盖 |
| TC-02 | 学历审核通过 | 学校、学校编码、学历、身份同步到公开资料投影 |
| TC-03 | 本人存在待审/驳回相册和文字 | 编辑态可见；主页预览只展示 effective/APPROVED 内容 |
| TC-04 | 非 mock 消息首页接口暂未返回数据 | 不展示硬编码认证通过或匹配成功消息 |
| TC-05 | 用户年龄低于后台准入下限 | 首页展示硬拦截，不进入认证或核心功能 |
| TC-06 | 发送手机验证码 | 调用当前 SmsCodeProvider，缓存实际验证码与规则 TTL |
| TC-07 | 手机验证码登录 | 只接受 Redis 中尚未过期的验证码，成功后删除 |
| TC-08 | TIM 未登录时退出 | 2024 被作为幂等退出处理，后续登录仍可执行 |
| TC-09 | TIM 初始化失败或超时后重试 | 清理卡死中的初始化状态，返回具体错误，可重新初始化 |
| TC-10 | 喜欢我的人摘要 | 头像取最新入向点赞记录的 fromUserId |
| TC-11 | 在校生资料 | 行业、职业、公司不作为必填；“学生”保留为身份，不增加到行业字典 |
| TC-12 | 基础资料标签 | 学校字段展示“所属于院校” |
| TC-13 | 他人查看已认证用户的公开主页 | 学校和身份以已通过学历快照为准，不展示历史可变资料 |
| TC-14 | 实名认证通过后进入基础资料或调用保存接口 | 性别和出生日期显示为不可编辑；篡改请求被服务端拒绝 |
