# 全部分享展示-20261010 测试用例

依据：本人主页分享空图反馈；现有 7 个分享回调及原生分享按钮。轻量模式，执行前端领域逻辑和页面接线回归、正式小程序构建；微信聊天卡片真机检查单独记录，缺少可自动控制的微信收件端时不冒充通过。

| ID | 场景 | 预期 |
| --- | --- | --- |
| S-01 | 本人/他人主页缺背景、头像或加载中 | 始终有 PNG 主页封面和合理标题，不回落页面截图，不分享个人编辑页 |
| S-02 | 正常 PNG/JPEG、失效 URL、WebP/GIF、超时下载 | 只采用实际加载成功且分享支持的格式；异常及时回到品牌封面 |
| S-03 | 动态有多图/纯文字/空文字/过长昵称或内容 | 有明确标题封面；地址精确到动态；空白和 emoji 截断安全 |
| S-04 | 信息流在家人/知音反复切换 | 页面仅有一个分享回调，按钮分享当前动态，菜单分享当前栏目，不残留上一条动态 |
| S-05 | 话题菜单与动态操作面板分享 | 话题与动态标题、图片和目标一致；登录后能回原话题 |
| S-06 | 邀请分享 | 保留归因参数，独立邀请封面；未准备好时按钮不发送无归因邀请 |
| S-07 | 静态封面 | 4 张 PNG，5:4 比例；品牌、类别、引导清楚，离线可用 |
| S-08 | 小程序构建和既有回归 | 相关既有用例、正式构建及包体积门禁通过 |
| M-01 | 真机聊天内展示全部 7 个入口 | 分享卡片有图，点开目标正确；未登录主页公开展示，其余登录后回原内容 |

回归补充：C-04 服务端清空头像后，我的动态与互动页必须以服务端空值为准，不回填缓存旧头像。

构建补充：检查首页及全部分享页面产物 enableShareAppMessage；分享封面必须随包存在。主包不超过 1.50 MiB，邀请页插画允许归入自身推广分包。
