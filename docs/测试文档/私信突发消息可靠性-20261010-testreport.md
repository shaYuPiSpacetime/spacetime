# 私信突发消息可靠性测试报告

## 结论

本轮自动化消息闭环 54/54 通过，微信小程序编译和产物门禁通过。修复覆盖同秒突发消息排序、平台与 TIM 双源历史分页、全局未读角标刷新以及退出登录时的旧请求隔离。没有引入消息列表清空、整页历史重载或聊天页重新挂载；现有首次进入定位最新消息、返回位置保留、键盘和滚动锚点逻辑保持原边界。

真机双端 99+ 突发消息和底部角标时延两项 P2 用例因当前没有可操作的双设备会话而跳过，仍需在体验版补验。

## 原因与修改

- TIM 消息归一化原来丢失 SDK 的 sequence/random，同一秒大量消息只能依赖时间和本地 ID，存在跨批次乱序风险。现在保留提供方顺序元数据；没有 sequence 的平台历史保持数据库顺序。
- 私聊历史原来只持续翻平台数据库，TIM 首屏补充请求的后续 cursor 没有进入会话状态。现在平台 cursor 与 TIM cursor 独立保存，向上翻页时并行增量合并，不替换已渲染列表。
- 底部消息角标原来主要依赖页面切换或消息页动作触发。现在前台每 3 秒只请求未读汇总，带单飞保护；后台停轮询并保留现有状态，恢复前台再立即刷新。
- 退出登录会递增运行代次，旧未读请求即使晚返回也不能污染已清空状态。
- `99+` 是角标展示上限，不是只获取 99 条消息；本轮没有改变该展示规则。
