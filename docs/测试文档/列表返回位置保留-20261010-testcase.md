# 列表返回位置保留测试用例

## 范围

热门动态点击头像、详情、话题后返回；同城/关注/同校、知音、话题、理想型、关系和消息列表的同类返回重载问题。保留当前页面会话的记录顺序、已加载页、分页游标与滚动位置；明确切换筛选或主动刷新时才创建新列表。点赞、关注、已读和审核变化仍需更新。

使用真实 React 页面事件回归和共享列表合并/滚动 Hook 测试，正式微信构建。真机 L4 需要可用模拟器或设备会话，缺失时明确记录，不能把 DOM 滚动模拟认作真机验收。

| ID | 场景 | 预期 |
| --- | --- | --- |
| RETURN-01 | 热门加载第二页，滚动后点头像并返回 | 不重拉第一页；已加载记录、顺序、位置不变，继续加载第三页 |
| RETURN-02 | 动态详情中改变点赞/关注后返回 | 更新目标动态，不用第一页替换整列 |
| RETURN-03 | 不同分类切换后返回 | 各自保留已加载数据和滚动位置 |
| RETURN-04 | 知音、话题页面从头像/详情返回 | 列表不清空、不重排，保留位置 |
| RETURN-05 | 理想型加载后续批次后从主页返回 | 保留批次和 nextCursor；充值解锁回执仍处理 |
| RETURN-06 | 关系/私信等已加载多页列表后台同步 | 只更新已显示条目，不丢弃后续页和分页游标 |
| RETURN-07 | 返回后的单条同步失败 | 保留现有内容和滚动偏移 |
| RETURN-08 | 重新进入新页面实例 | 从第一页开始，无跨页面实例缓存 |
| RETURN-09 | 我喜欢的第二页中取消喜欢后返回 | 移除该用户，保留其他已加载记录和位置 |
| RETURN-10 | 悄悄话第二页申请在详情处理后返回 | 仅迁移该申请至已处理，其余记录和游标不丢失 |
| RETURN-11 | 话题详情中隐藏作者后返回 | 移除对应作者动态，不被保留列表重新带回 |

真机补验：热门/关注/同城/同校各加载两页后点头像返回，核对原卡片及屏幕偏移；同样检查知音、理想型、话题、互动、我的动态、关系及消息列表。记录删除或权限变化导致的合法收缩须与普通返回区分。充值解锁回执和快速切换筛选的真机行为也需补验。
