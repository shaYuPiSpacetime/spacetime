## 原因与处理

1. 动态列表逐作者计算资料完整度，每位作者重复读取配置及多类审核记录。跨地域数据库的单次往返被累积为整页等待。改为当前页一次加载计分规则、一次批量读取审核事实；最新头像审核状态和其余有效审核的计分口径保留。
2. 基础资料选项原先查询 16 次，改为一次读取后按字典类型分组；推荐卡片的多类标签改为一次读取。认证计数由单用户 3 次查询合并为 1 次；我的主页复用本次已计算的准入状态。
3. 多个已挂载页面会并发获取相同资料，并重复发布相同状态。只合并同账号、同地址、同参数及同请求头且尚未完成的 GET；完成或失败后立即清除，写操作前后清除在途合并记录，不合并写请求。相同认证和身份状态不再反复写同步存储或触发全局刷新。
4. 我的页面首次进入同时触发两次加载，配置、地区、资产间又存在串行等待。删除重复的初始 effect；配置与资料并行，地区与已准入用户的资产读取并行。千寻已准入用户省去认证引导页基础资料及介绍的读取，仍每次校验准入。

本轮没有增加业务结果的跨请求缓存，没有修改审核、余额、解锁、浏览额度、权限及写入幂等规则。

## 数据库决定与后续边界

- 优化后本次动态列表测得约 126–130 毫秒，正式域名约 137–147 毫秒，原有秒级等待已显著下降。
- 按用户“外网太卡再改本机数据库”的条件，本轮保留现有 RDS 连接，不进行数据库迁移。
- 当前观察不代表跨地域延迟消失；如后续仍有持续慢请求，应以实际慢接口及查询次数复测，再决定迁移，避免仅凭单条 SQL 的延迟判断整页体验。
