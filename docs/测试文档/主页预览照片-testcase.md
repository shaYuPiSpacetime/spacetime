# 主页预览照片 - 增量测试用例

## 范围与依据

反馈第2项：后台有6张相册照片，用户补充的主页预览设计稿要求“自我介绍 → 首张照片 → 我的认证 → 第二张照片”。本次修正共享预览组件的模块顺序，保留全部有效照片及关于我内容。

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| PHOTO-01 | P1 | 本人预览，6张照片，关于我有长内容 | 自我介绍后立即展示首张照片；认证后展示第二张；全部6张顺序正确；关于我保留在相册之后 |
| PHOTO-02 | P1 | 共用公开主页，6张照片 | 与本人预览保持同一内容顺序 |
| PHOTO-03 | P1 | 相册接口返回6条乱序记录 | 真实 `mergeAlbumSlots` 根据 sortOrder 映射为6个有效图片 URL |
| PHOTO-04 | P2 | 0、1、2张照片及包含空白 URL | 只生成实际有效照片，不生成空白大图卡，不丢失最后一张 |
| PHOTO-05 | P2 | 无自我介绍、无认证，但有照片 | 照片仍展示，关于我不能挤到首张照片之前 |

使用实际 TSX 渲染树及相册映射函数验证，不以源码正则代替顺序断言。截图以375×812视口对比修改前/后及空相册，数据为明确标识的本地固定样例，不冒充反馈账号的线上数据。沿用已有资料页回归与定向 ESLint；编译使用 Taro，完整前置门禁存在的参考图缺失继续单独记录。
