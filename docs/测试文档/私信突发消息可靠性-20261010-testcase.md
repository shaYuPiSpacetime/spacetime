# 私信突发消息可靠性测试用例

## 范围

验证私信收到 99+ 消息时的顺序、完整性、历史分页和全局未读数刷新，并回归聊天页首次进入、返回停留、键盘交互及滚动锚点。实现不得通过清空消息列表或重新挂载聊天页来刷新数据，主包不得为未读角标加载 LiteChat SDK。

## 自动化用例

| ID | 优先级 | 场景 | 预期 |
| --- | --- | --- | --- |
| CHAT-BURST-01 | P0 | 将同一秒内的 120 条 TIM 消息按反向批次合并 | 按 TIM sequence 稳定排序，无丢失、无重复 |
| CHAT-BURST-02 | P1 | 平台历史消息没有 TIM sequence，且多条消息时间相同 | 保留后端返回顺序，不使用字符串消息 ID 错误重排 |
| CHAT-BURST-03 | P0 | 首屏后继续向上加载，平台历史和 TIM 历史都还有下一页 | 两个数据源并行各取一页，增量合并并保留首条可见消息锚点 |
| CHAT-BURST-04 | P0 | 首屏 TIM 请求超过首屏等待预算后异步返回 | 保存 TIM cursor/完成状态并补充消息，不清空当前列表 |
| CHAT-BURST-05 | P0 | 应用在前台且收到新私信 | 仅轮询未读汇总，底部消息角标在下一轮刷新中更新 |
| CHAT-BURST-06 | P1 | 未读汇总请求执行时间超过轮询间隔 | 单飞保护阻止请求重入，不并发堆积 |
| CHAT-BURST-07 | P1 | 应用进入后台 | 停止新轮询，保留现有角标，避免隐藏/显示闪烁 |
| CHAT-BURST-08 | P1 | 退出登录时旧未读请求仍在执行 | 旧请求结果不得回写已清空的消息状态 |
| CHAT-BURST-09 | P0 | 运行消息闭环全量静态与行为回归 | 私信、消息中心、举报、红点、启动门禁全部通过 |
| CHAT-BURST-10 | P1 | 微信小程序正式构建与产物检查 | 编译成功；页面注册、开发令牌、分包和包体门禁通过 |

## 真机补验

| ID | 优先级 | 场景 | 预期 |
| --- | --- | --- | --- |
| CHAT-DEVICE-01 | P2 | 一端连续发送 120 条消息，另一端从私信列表进入、向上翻页、进入对方主页再返回 | 首次进入直接定位最新消息；消息无缺失、无乱序；返回停留原位置；无白屏或列表闪烁 |
| CHAT-DEVICE-02 | P2 | 用户停留在非消息 Tab 时收到多条消息 | 底部“消息”角标在 3 秒左右刷新；超过 99 显示 `99+`；进入会话已读后角标下降或消失 |

真机用例需要两台已登录设备或可用微信开发者工具会话以及真实 TIM 消息，缺失环境时记录为跳过，不以 Node/DOM 测试替代原生渲染验收。
