### 10.3 根因与修复证据

- 生产请求 ID `2c43aee...`、`9db464...`、`a417d18...` 的服务端日志均落到 `CommunityServiceImpl.createPost`，异常为 `DataIntegrityViolationException: Data too long for column 'machine_code'`。
- `CommunityPostCreateReq.topicId` 原有 `@NotNull`，服务层又无条件查询和校验话题，导致前后端都无法发布无话题普通动态。
- 修复后，主动态和审核记录仅保存数据库兼容的审核提供方标识；完整多图异步追踪码仍保留到每张图片的审核任务，未丢失回调关联能力。
- 话题为空时不查询话题；话题存在时仍执行“已审核且启用”校验，没有放宽无效话题规则。
- 小程序发布按钮可用态仅依赖正文、发布中状态和图片上传完整性；接口层 `topicId?: number`，请求序列化会省略空值。
