# 千寻互动整体蓝湖还原测试用例

> 日期：2026-08-05  
> 关联技术方案：`docs/技术方案/2026-08-05-千寻互动整体-蓝湖还原-tcdesign.md`  
> 设计基线：`007.png`、`008.png`、`039.png`、`040.png`、`041.png`、`042.png`、`183.png`、`184.png`

## 1. 测试目标

验证“千寻互动”的互动、浏览记录、我的动态及关联话题/知音动态卡完成以下闭环：

1. 页面结构、纵向基线、空状态和卡片密度按蓝湖稿还原。
2. 浏览记录消费真实互动接口，显示真实互动日期、动态日期、性别和动态内容。
3. 评论、点赞、性别、悄悄话统一使用 OSS 图标，不再使用字符占位。
4. 已删除、已屏蔽的动态不出现在个人动态和互动历史中。
5. 关键页面可在微信开发者工具中真实打开且无运行异常。

## 2. 测试层级

| 层级 | 覆盖范围 | 执行方式 |
|---|---|---|
| L2 静态契约 | 接口路径、数据字段保留、图标引用、纵向基线 | Node Test + 项目静态门禁 |
| L3 服务测试 | 我的动态、互动历史对不可见内容的过滤 | JUnit 5 + Mockito |
| L4 运行态 | Tab/筛选切换、真实数据渲染、页面路由、截图 | 微信开发者工具 + miniprogram-automator |
| 构建验证 | 小程序产物及后端回归 | Taro build + Maven test |

## 3. L2 静态契约用例

| 编号 | 场景 | 预期 |
|---|---|---|
| L2-001 | 浏览记录请求 | 使用 `/miniapp/community/me/interactions?type=viewed`，不再使用旧扁平历史接口 |
| L2-002 | 浏览记录字段 | 前端保留 `interactionTime` 与关联 `post`，不得在映射时丢失 |
| L2-003 | 互动日期分组 | 按真实互动日期降序分组，标题格式为 `YYYY年MM月DD日` |
| L2-004 | 卡片日期 | 卡片底部显示动态创建日期 `MM-DD` |
| L2-005 | 性别图标 | `female` 显示女性 OSS 图标，`male` 显示男性 OSS 图标，未知性别不显示错误占位 |
| L2-006 | 评论/点赞图标 | 动态卡、详情、话题、知音统一使用 OSS 评论/点赞图标和激活态 |
| L2-007 | 字符占位门禁 | 千寻相关页面不得出现 `◯`、`♡`、`♥`、`♀`、`♂` 作为功能图标 |
| L2-008 | 页面纵向基线 | 资料区、统计区、白色内容面板分别符合 226/356/430rpx 基线，页面只保留一套导航 |
| L2-009 | 不可见动态 | `deleted`、`blocked` 动态在前端列表过滤，服务端查询同时排除 |

## 4. L3 服务层用例

| 编号 | 场景 | 前置/输入 | 预期 |
|---|---|---|---|
| L3-001 | 查询我的动态 | `mine=true` | 查询条件包含 `status NOT IN (deleted, blocked)` |
| L3-002 | 查询评论过 | 评论记录包含未发布评论或关联不可见动态 | 只返回已发布评论及可见动态 |
| L3-003 | 查询点赞过 | 点赞关联动态已删除或屏蔽 | 不返回该互动项 |
| L3-004 | 查询浏览记录 | 浏览记录关联动态已删除或屏蔽 | 不返回该互动项 |

## 5. L4 微信运行态用例

| 编号 | 页面/操作 | 预期 |
|---|---|---|
| L4-001 | 打开千寻互动 | 单一导航、资料摘要、四项统计和白色内容面板正常 |
| L4-002 | 依次切换评论过/点赞过/解锁过 | 筛选态正确；有数据展示真实卡片，无数据展示对应蓝湖空态 |
| L4-003 | 切换浏览记录 | 显示完整日期分组、作者头像、真实性别图标、正文、图片、动态日期及评论/点赞图标 |
| L4-004 | 检查浏览记录间距 | 内容面板下划线至首个日期、日期至作者行、卡片内部上下间距与 `039.png` 对齐 |
| L4-005 | 清空浏览记录 | 通过右上角操作入口二次确认，成功后显示浏览记录空态 |
| L4-006 | 打开互动内“我的动态” | 不展示 deleted/blocked 数据，状态和卡片图标正确 |
| L4-007 | 打开独立“我的动态” | 与互动内列表口径一致，无重复原生/自定义导航 |
| L4-008 | 从热门动态进入话题 | 经精选话题或动态详情真实入口进入 `pages/qianxun/topic` |
| L4-009 | 打开知音诚意贴/悦目 | 动态卡使用统一 OSS 图标，点赞激活态和未激活态正确 |
| L4-010 | 运行异常监听 | 整段验收过程中无小程序 exception |

## 6. 执行数据与边界

- 微信运行账号使用开发环境固定测试账号 `17366629764` 的现有 Token，仅用于读态验收。
- 运行数据必须来自真实后端接口，不注入页面级 Mock 数据。
- 清空浏览记录属于破坏性业务操作，自动截图只验证入口和渲染，不自动执行清空确认。
- 设计稿未提供的未知性别、接口失败和部分空数据组合，以“不显示错误图标、不覆盖真实错误信息”为验收口径。
