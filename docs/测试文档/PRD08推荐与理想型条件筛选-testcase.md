# PRD-08 推荐与理想型条件筛选测试用例

> 编制日期：2026-08-06  
> 关联技术方案：`docs/技术方案/2026-08-05-PRD08推荐理想型-蓝湖还原-tcdesign.md`  
> 设计基线：蓝湖推荐分组 001～023，共 23 个页面/状态画板

## 1. 测试目标

验证推荐、三天回看、偏好设置、理想型筛选、快照结果、单个/全部解锁、历史解锁、帮助说明、共享用户主页和商业化折扣配置形成以下闭环：

1. 23 个蓝湖页面/状态由 9 条生产路由和共享组件完整承载，不使用整页截图或透明热区。
2. 推荐候选、会员门禁、浏览额度、偏好、理想型条件、价格、折扣、余额和历史均由后端字段驱动。
3. 理想型筛选生成不可变快照；未解锁数据保持脱敏；单个/全部解锁必须先报价再确认。
4. 用户主页和主页预览共用资料组件；未解锁显示“悄悄话”，具备有效沟通权限后显示“私信”。
5. 商业化配置中的批量解锁优惠比例动态参与服务端报价，客户端不计算应付金额。
6. 页面在微信开发者工具 390×844 视口可打开、切换、弹层、分页和回跳，且无小程序异常。

## 3. L1 HTTP 接口用例

> L1 只允许使用部署环境提供的 `API_BASE_URL`、有效 Token、可重置测试用户和可核对余额；不得在脚本中写死账号、Token 或生产数据。

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| L1-001 | 未登录访问 | 不带 Token 请求推荐偏好、理想型元数据 | 返回 401，不泄露候选或价格数据 |
| L1-002 | 查询与保存推荐偏好 | GET 后携带当前 version PUT | 返回新版本；旧 version 再次保存产生版本冲突 |
| L1-003 | 推荐曝光幂等 | 同一 candidateNo、requestId 重复提交 view | 只记录一次曝光、只扣一次额度 |
| L1-004 | 三天回看门禁 | 普通用户和会员分别请求 replay | 普通用户返回门禁；会员返回最近三天去重数据 |
| L1-005 | 理想型快照幂等 | 同一用户、条件和 requestId 重复 search | 返回同一 snapshotNo，不重复生成候选快照 |
| L1-006 | 未解锁隐私 | 查询快照结果 | 未解锁项不包含 candidateNo、昵称、原头像、精确年龄等隐私字段 |
| L1-007 | 单个解锁 | quote 后使用 quoteToken confirm | 原子扣币、写流水和解锁记录，重复 requestId 返回同一结果 |
| L1-008 | 解锁全部折扣 | 调整后台优惠比例后重新 quoteAll | 应付金额由服务端按最新配置计算，前端只展示响应 |
| L1-009 | 余额不足 | 使用余额不足测试用户确认报价 | 不扣币、不产生伪成功记录，返回可识别余额不足错误 |
| L1-010 | 历史与失效 | 查询 search-records、unlocks 三种状态 | 游标稳定；失效记录不返回可继续访问的完整资料 |
| L1-011 | 商业化变更日志 | 修改折扣比例并填写原因 | 中文配置项、变更前、变更后、变更原因均可查询 |

## 8. 数据与执行约束

- 微信运行态使用本地 API 契约 Mock，只验证客户端页面状态、交互和字段消费，不代表部署环境联调。
- L1 需要部署环境 URL、有效 Token、可重置用户、可核对余额和已执行的 065 数据库迁移；缺少时必须标记未执行。
- 解锁确认、余额扣减、批量折扣和变更日志属于写操作，只能在明确的测试数据范围内执行。
- 设计稿中的城市、人物、价格和人数是视觉样例；运行态使用后端动态值时允许文案数据不同，但布局、组件和状态含义必须一致。
