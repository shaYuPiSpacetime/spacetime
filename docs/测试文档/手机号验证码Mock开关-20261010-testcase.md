# 手机号验证码 Mock 开关 - 测试用例

创建日期：2026-10-10。基线：master `0128f209`。测试范围：验证码发送、校验与部署配置；不修改登录页面。

## 实施与测试策略

增加环境开关 `SMS_MOCK_ENABLED`（对应 `sms.mock-enabled`），当前默认 true，保持测试使用固定 0000、不发送短信。false 时使用已配置的 SmsCodeProvider 生成随机四位码并真实发送，成功后才写入 Redis 及频控计数。生产已配置 SMS_PROVIDER=aliyun；关闭 mock 时若通道仍是 MOCK，则明确失败，不能自动降级。随机码使用 SecureRandom。

mock 继续使用现有缓存键；真实码使用独立 `miniapp:auth:sms:real:code:` 命名空间。关闭开关后不接受先前的固定码；两种模式都必须先获取验证码，均按后台策略过期，并在登录成功后消费。频控键仍共用。开关经部署脚本传入后端容器；修改环境后重建容器生效。

策略：L3 业务分支与现有 Provider 测试 + 部署配置门禁 + 当前 mock 模式线上烟测。真实短信对外发送不在本次生产验证范围，用模拟阿里云客户端覆盖请求、发送失败和参数；不临时关闭线上 mock，不向非用户号码发送短信。

## 用例

| ID | 优先级 | 场景 | 期望 |
|---|---|---|---|
| L3-01 | P0 | 开关 true，发送和登录 | 缓存 0000，不调用真实 Provider，成功后消费 |
| L3-02 | P0 | 开关 false，Provider 生成/发送成功 | 随机四位码真实发送，缓存同一码并返回 Provider 编码 |
| L3-03 | P1 | 真实发送失败 | 业务错误，验证码、冷却和每日次数均不新增，不降级为 0000 |
| L3-04 | P3 | 关闭 mock，但 Provider 配成 MOCK | 拒绝发送，不发放验证码 |
| L3-05 | P3 | 关闭 mock 后提交旧 mock 缓存码 | 拒绝登录，不读取或消费旧 mock 缓存 |
| L3-06 | P0 | 真实模式提交有效随机码 | 正常登录，消费真实缓存 |
| L3-07 | P3 | 真实模式提交不匹配/未获取/过期码 | 拒绝登录，不访问用户数据 |
| L3-08 | P3 | 从真实模式切回 mock，提交真实缓存码 | 拒绝登录 |
| L3-09 | P1 | 真实模式登录成功后再次使用同一码 | 第二次拒绝 |
| L3-10 | P2 | Redis 带引号编码、倒计时、日发送额度 | 原有兼容与限流测试通过 |
| M-01 | P1 | 部署配置传递开关，值为非法布尔值或 false+mock | 门禁/部署拒绝；true/false+aliyun 可配置 |
| L1-01 | P0 | 部署后现有用户获取验证码并用 0000 登录 | FIXED 模式可登录，不发送真实短信，不输出 Token |
