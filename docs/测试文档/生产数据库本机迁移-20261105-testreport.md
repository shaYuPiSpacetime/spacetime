- MySQL 容器：`spacetime-mysql-prod`；网络别名 `mysql`，应用连接 `mysql:3306/shikongxiehou_prod`，无任何宿主端口映射。
- 宿主数据目录：`/mnt/data/spacetime-prod/mysql/data`。应用账号仅有生产库权限；root 仅用于本机运维，随机密码保存在受限文件，未进入 Git。
- 容器重建后实例 UUID 与数据保留，已实际验证；使用固定摘要镜像和 `unless-stopped` 重启策略，内存上限 4 GiB，缓冲池 2 GiB。
- 要求安全传输；应用 JDBC 使用 `sslMode=REQUIRED`，远端源库导出使用 CA 和域名验证。
- `innodb_flush_log_at_trx_commit=1`、`sync_binlog=1`；本机二进制日志保留 7 天。
- 每日 04:17 执行一致性备份，包含存储过程、事件、触发器及可恢复的二进制日志位置；本机保留 14 天，异机保留 30 天。
- 异机副本位于原测试服务器的独立备份账号目录。专用 SSH 密钥限定生产来源 IP、固定 SCP 接收命令和目录，无交互 Shell 或转发权限；文件权限 600，目录 700。
- 备份脚本防重入、先写临时文件、成功校验后落盘，异机复制成功后才清理过期本机副本。
- 已实际恢复一份每日备份到临时数据库，151 张表内容校验值全部一致，临时恢复库已删除；异机文件 SHA-256 核对通过。
- 备份为每日异机快照；整台生产服务器及本地二进制日志同时丢失时，恢复点取决于最后一份成功的异机备份，不宣称零数据丢失。

## 回退与恢复

1. 应用版本回退仍必须连接当前本机数据库，不能直接恢复旧 RDS 连接。
2. 如需迁回 RDS，先维护停写，对当前本机数据做新快照，完成反向恢复、兼容检查和逐表校验后再切换；旧 RDS 仅是迁移时刻的快照。
3. 恢复新主机时，先按固定镜像和原大小写/时区配置初始化，恢复完整备份；需要时按备份中的日志位置重放保留的二进制日志。逐表及应用验收后记录新实例 UUID，再允许发布，不复制过期的验收标识。
4. 操作入口：`deploy/scripts/backup-local-mysql.sh`、`deploy/scripts/local-mysql.sh`、`deploy/scripts/migrate-prod-db.sh`；私有配置继续位于服务器 `secrets/prod.env`。
