# 小程序资料评分刷新 - 测试用例

## 范围与方案

评分仍由 `/miniapp/profile/basic` 的 `profileScore` 提供，客户端不计算加分。编辑页首次进入、重新显示和资料保存成功后刷新评分；刷新与其他资料请求分开。复用同时进行的普通读取，保存后的刷新必须重新请求，并忽略旧请求及离开页面后的迟到结果。请求失败保留上次有效分数，合法的 0 分必须显示。

实现仅涉及小程序编辑页及评分 hook，不修改后台评分规则、用户数据和管理端。先实现回归用例，再实现刷新及入口接线，最后执行关联回归和微信小程序构建。

## 策略

轻量模式：使用 Node test + React/jsdom 执行真实 hook 和页面组件，模拟 API 返回与 Taro 生命周期（属于前端单元/组件测试，不冒充真实环境 L4）。无后端变更，不增加 MockMvc/JUnit。真实手机与后台同环境联调单列，需可用环境和登录会话。

## 用例

| ID | 优先级 | 场景与预期 |
|---|---|---|
| SCORE-01 | P1 | 路由传入 87，接口返回 92，评分显示 92；同时发生的首次显示与基础资料加载复用请求。 |
| SCORE-02 | P1 | 隐藏后重新显示，服务端评分改变，重新请求并更新。 |
| SCORE-03 | P1 | 保存后新请求先返回 94，旧请求后返回 87，最终保持 94。 |
| SCORE-04 | P1 | 请求失败保留有效分数；下一次刷新可以成功恢复。 |
| SCORE-05 | P1 | 服务端返回 0 时覆盖旧分数；无效/空值不能把已有评分改成 0。 |
| SCORE-06 | P1 | 页面隐藏/卸载后忽略迟到结果，重新显示不复用离开前的请求。 |
| SCORE-07 | P1 | 实际编辑页的相册/其他资料请求或配置加载失败，独立评分仍更新。 |
| SCORE-08 | P1 | 子页保存通过 profileUpdated 事件回传，编辑页重新获取评分，保留已有字段更新。 |
| SCORE-09 | P1 | 脱单目标/感情状态保存成功后刷新；保存失败不刷新。 |
| SCORE-10 | P1 | 头像、背景、相册新增/替换、语音提交/删除成功后刷新评分。 |
| SCORE-11 | P2 | 既有资料编辑及照片预览回归通过，微信小程序构建通过。 |
| SCORE-12 | P1 | 真实手机与后台连接同一环境：保存资料、返回编辑页，评分与接口一致；异步审核完成后重新进入取得最新分数。 |

## 执行

- 自动：`cd miniapp && node --test scripts/test-profile-score-refresh.cjs scripts/test-profile-edit-closure.cjs scripts/test-profile-preview-photos.cjs`
- 构建：`cd miniapp && npm run build:weapp`
- SCORE-12：真实环境人工/自动化联调，缺少登录与设备连接时明确跳过，不伪造通过。
- 执行结果记录在同目录 `小程序资料评分刷新-testreport.md`。
