## 覆盖结论

- 学历认证通过后，本人资料与他人查看的公开主页均以审核快照为展示真值，并锁定身份、最高学历、学校字段；服务端拒绝绕过修改。
- 学历审核通过时同步学校、学校编码、学历和身份到用户主表。
- 本人编辑页仍可看到待审/驳回稿用于继续编辑；主页预览只展示已生效头像、背景、相册和个人介绍。
- 非 mock 消息页不再使用“学历已通过”“匹配成功”的演示消息兜底。
- `CORE_BLOCKED` 用户在首页和个人页进入统一准入阻断页。
- 手机验证码改为由环境配置的 `SmsCodeProvider` 生成并发送，登录按 Redis 中有效验证码校验。
- LiteChat 不再对未登录实例调用退出；连接超时可重新初始化，并透传 SDK 错误原因。
- “毕业院校”已改为“所属于院校”；“学生”保留为身份，不增加到行业字典。
- “喜欢我的人”头像核对为点赞发起用户 `fromUserId` 的审核通过头像，现有实现正确，无需修改。
- 行业、职业、公司默认均为非必填，学生身份下前端会隐藏并清空就业字段，现有实现正确，无需修改。
- 实名认证通过后，性别和出生日期在资料页显示为不可编辑，服务端拒绝篡改请求。
