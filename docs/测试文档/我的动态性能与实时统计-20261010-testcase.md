# 我的动态性能与实时统计 - 测试用例

日期：2026-10-10。依据：用户反馈首次统计慢、切换互动卡顿、索引维护和数字更新要求，以及 CommunityController/CommunityServiceImpl 和小程序个人区代码。

## 测试策略

无正式技术方案，采用轻量模式；为性能回归追加 L3 JUnit 和 React 运行态测试。L1 使用现有正常登录测试会话，不提取 Redis 凭据、不构造账号或生产写数据。数据库检查使用配置的连接，仅执行只读查询与 EXPLAIN；索引通过幂等迁移和自动部署维护。真机 L4 在有有效设备环境时执行，否则记录跳过。

## 用例

| ID | 优先级 | 场景与预期 |
| --- | --- | --- |
| L3-01 | P0 | summary 使用实时 SQL 聚合，口径保持有效动态、FOLLOW 关系、动态与评论获赞；不加载完整列表。 |
| L3-02 | P1 | 四类互动在 SQL 过滤可见父动态后分页，50 条以内组装当前页；保持 total/current/size 和真实互动时间。 |
| L3-03 | P1 | 评论保留本次正文，同一作者或帖子重复记录不触发逐条用户/头像/字典查询。 |
| L3-04 | P1 | 浏览历史复用分页卡片；空页不查询卡片资料，非法互动类型拒绝。 |
| L3-05 | P1 | 点赞/评论用户名单去重分页，隐藏作者分页且关注状态为真实状态。 |
| UI-01 | P0 | 挂起 meta 和动态列表，summary 仍能独立展示；未取得统计显示占位而非 0。 |
| UI-02 | P1 | 进入互动只请求当前筛选，不请求隐藏栏目；挂起浏览记录后切换点赞仍可完成。 |
| UI-03 | P1 | 点赞、关注、删除、评论、发布成功通知统计刷新，失败不通知；操作前迟到统计不可覆盖操作后值。 |
| UI-04 | P1 | 15 秒可见刷新、返回页刷新、隐藏/卸载停止定时器，缓存不得跨账号回显。 |
| SQL-01 | P1 | 幂等索引迁移挂入部署；EXPLAIN 校验统计、个人动态、四类互动、关注/粉丝、互动用户、隐藏名单。 |
| L1-01 | P0 | 正常会话只读请求个人区所有关联 GET API，响应成功，记录脱敏的响应时间与页数。 |
| L4-01 | P1 | 真实微信设备首次进入/切换、他人互动变化与本人的写操作后数字核对。 |

## L1 数据计划

使用已配置测试登录身份 -> summary、me/posts、四种 me/interactions、view-history、me/follows、hidden-authors；post-interactors 从 me/posts 的首个真实 published 动态发现 ID，没有动态则跳过。仅读取 code/data.stats/data.total/data.records 数量，不输出正文、头像、用户资料或令牌。不执行发布、点赞、删除等生产写操作。
