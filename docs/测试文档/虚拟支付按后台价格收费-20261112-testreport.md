# 虚拟支付按后台价格收费验证及生产发布记录

## 修复范围

- 页面展示价、创建订单金额与微信支付参数统一使用后台生效套餐价；千寻币套餐存在有效优惠价时使用优惠价。
- 旧的 `testAmount`、`forceTestAmount`、`testPayAmount` 属性仅保留配置绑定兼容，不再覆盖金额，避免旧服务器环境变量继续把订单改为 1 元。
- 生产配置默认启用微信虚拟支付。生产部署脚本明确使用虚拟支付正式环境，并清除旧镜像可识别的测试金额变量。
- 管理后台订单页使用“订单金额”，显示支付渠道与渠道交易单号，避免把创建订单误解为已收款；会员购买说明与小程序会员记录区分“微信虚拟支付”。
- 历史订单继续按原订单金额和渠道对账；不修改既有订单、资产或赠送记录。
- 微信商品名称仅允许中英文、数字及 `-_*·`。后台原套餐名“专属2.1折”的英文句点导致微信返回 `672770002`，反复发布失败。本次仅将传给微信的商品名转换为“专属2点1折”，保留后台名称、备注和价格；其他不支持的连续标点转换为间隔号，网关再次校验允许字符。
