# 悄悄话旧输入清理测试用例

## 范围

验证悄悄话弹层常驻以保持信息流滚动顺滑时，不会把上一轮未发送或已发送的输入带到下一轮；同时保证跳转充值页再返回仍保留本轮输入。

| ID | 优先级 | 场景 | 预期 |
| --- | --- | --- | --- |
| WHISPER-DRAFT-01 | P0 | 输入内容后关闭弹层，再次对同一用户发起悄悄话 | 输入框为空，不展示上一次草稿 |
| WHISPER-DRAFT-02 | P0 | 输入内容后关闭弹层，再对另一用户发起悄悄话 | 输入框为空，不串用上一用户草稿或幂等键 |
| WHISPER-DRAFT-03 | P0 | 成功发送后再次发起悄悄话 | 已发送内容被清空 |
| WHISPER-DRAFT-04 | P1 | 输入内容后进入充值页，再返回当前弹层 | 本轮输入保留，余额与发送资格刷新 |
| WHISPER-DRAFT-05 | P0 | 打开、关闭悄悄话弹层 | 弹层继续常驻，仅切换可见性；信息流不重建、不跳顶 |

## 执行方式

- 自动化：`cd miniapp && node --test scripts/test-0901-document-fixes.cjs`
- 构建：`cd miniapp && npx taro build --type weapp`
- 产物门禁：`cd miniapp && npm run postbuild:weapp`
- 真机补验：在信息流与动态详情分别执行关闭重开、切换用户、充值返回和发送成功后的再次打开。
