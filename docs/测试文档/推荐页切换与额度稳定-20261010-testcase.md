# 推荐页切换与额度稳定 - 测试用例

日期：2026-10-10。依据：推荐与理想型页、推荐实际数量角标既有用例及用户本次问题反馈。普通用户默认 10 人、会员默认 20 人，最终以商业化配置为准；周期为北京时间中午 12 点至次日中午 12 点。

| 编号 | 场景 | 期望 |
|---|---|---|
| U-01 | 耗尽后点击推荐、理想型并反复往返 | 主路由保持 pages/recommend/index，只切内容，无整页入栈 |
| U-02 | 同一周期切换底部 Tab，后台刷新返回更多或旧候选 | 共享角标不反弹；新周期或偏好版本变化允许重新计算 |
| U-03 | 分页收集中额度发生变化 | 拒绝发布混合时刻的数据，保留已确认数字 |
| U-04 | 曝光 nextTick 前切到理想型或隐藏页面 | 不执行 view、不消耗未实际展示的推荐额度 |
| U-05 | 曝光失败、跨页或周期变更、重复曝光 | 失败可重试，旧请求不覆盖新队列，同人不重复扣 |
| U-06 | 底部 Tab 普通态和选中态切换 | 两套图标常驻并互斥显示，不通过替换资源触发加载闪烁 |
| L3-01 | 同账号多请求竞争最后一个额度 | 在首次业务读取前锁定用户行，锁持续至事务提交；第二请求看到最新额度并拒绝超额 |
| L3-02 | 额度耗尽后重复浏览同人、浏览新人 | 同人幂等成功，新人拒绝；已浏览人数按候选去重 |
| L3-03 | 普通、会员及配置额度 | 17 人未耗尽 20 人额度；第 20 人后拒绝第 21 人 |
| L1-01 | 指定账号的周期、配置、实际去重浏览数 | 使用既有生产连接只读核对，按周期解释人数；缺少真实连接时跳过 |
| M-01 | 微信体验版推荐卡、等待内容、理想型往返 | 切换自然、无二次整页跳转、角标稳定；真机验证需要实际登录会话 |

执行：Node 真实状态函数回归、小程序生产构建、Java 21 定向服务测试。生产核对不执行 view/like/save，不修改用户额度或浏览记录。
