# 推荐额度单账号重置测试用例

依据：用户要求重置指定账号以复现推荐额度问题；`RecommendBrowseCycle` 与 `RecommendServiceImpl.browseViewsInCycle`。

本次仅重置北京时间当前中午至次日中午周期内、目标账号未删除的 `view` 记录。先备份，再在用户行锁事务内清理；保留其他动作、历史周期、其他账号及会员配置。一份执行标记限制本次操作只能生效一次。

生产执行前，GitHub Actions 使用独立 MySQL 8 数据库运行同一份 SQL。无接口和 UI 改动，L1/L2/L4 不适用；数据库用例属于本次运维专项验证。

| ID | 场景 | 预期 |
| --- | --- | --- |
| DB-P0-01 | 有效 VIP，3 条 view 涉及 2 位不同候选 | 备份并清理 3 条，已用 2，额度 20，恢复 20 |
| DB-P1-02 | 普通账号 | 恢复配置的普通额度 10 |
| DB-P2-03 | VIP 已到期 | 按普通额度恢复 10 |
| DB-P3-04 | 当前周期之外、其他账号、逻辑删除和其他动作 | 全部保留 |
| DB-P2-05 | 成功后新增一条 view，再次运行 | 返回 already_completed，新增记录保留 |
| DB-P3-06 | 目标账号不存在 | 执行失败，不清理记录 |
| DB-P3-07 | 目标账号重复有效命中 | 执行失败，不清理记录 |
| OPS-P0-08 | 生产执行 | 必须读到 completed、remaining_view_rows=0、恢复额度；执行前统计留在运维记录与备份表 |

客户端复现：完全关闭后重新打开体验版，进入推荐；第一张卡曝光会正常扣减一个额度。推荐角标也受可见候选人数限制，因此不一定等于完整浏览额度。
