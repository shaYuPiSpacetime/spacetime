# 推荐回看人数与额度一致测试用例

依据：用户反馈账号 173****9764 的回看显示 29 人，而本轮额度为 20；生产只读审计显示重置后 20 条 view、20 位不同候选，今天旧统计含 11 位无有效 view 的候选。

范围：回看仅以成功记录的 view 确定人数和日期，跳过、详情、心动作为对应浏览的附加状态；推荐动作须先确认当前曝光，快速连点只能提交一次切换。保留近三个北京时间自然日分组，不把三天合计截为 20；额度仍按北京时间中午周期控制。

| ID | 场景 | 预期 |
| --- | --- | --- |
| L3-P0-01 | 20 位有效 view，另有 11 位重置残留 skip/like | 回看只返回 20 位有效曝光候选 |
| L3-P1-02 | 相同日期重复 view/skip/detail | 去重一人，保留有效浏览后的最近动作与跳过标记 |
| L3-P1-03 | 今天只有动作，真实曝光在昨天 | 不新增今天的人数；日期取真实曝光 |
| L3-P2-04 | 旧 skip 早于重置后的新 view | 不将旧 skip 当成本次跳过 |
| L3-P0-05 | VIP 额度 20，连续请求 40 位新候选 | 只允许 20 位；其余拒绝，重试已看候选不重复扣减 |
| JS-P0-06 | 同一渲染周期连续点击跳过或心动 | 仅一个动作请求、一次候选推进 |
| JS-P0-07 | 曝光尚未确认或确认失败 | 不提前写跳过、心动关系或推进下一张 |
| JS-P1-08 | 曝光等待中发生页面刷新 | 旧处理结果不得推进刷新后的队列 |
| REG-P1-09 | 原有回看权限、去重、图标、页内切换及角标测试 | 全部保持通过 |
| OPS-P0-10 | 部署后查询账号与运行状态 | 本轮实际 view 仍最多 20，后端部署成功，体验版上传成功 |

验证采用 Java 21 JUnit 服务、周期与回看权限回归，执行真实 TS 处理函数的 Node 回归以及生产只读聚合审计。接口形态不变，不增加 Controller 用例。当前无有效账号会话，不伪造 L1/L4 登录态；实际页面复现由用户在体验版进行。
