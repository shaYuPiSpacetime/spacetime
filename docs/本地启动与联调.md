# 本地启动与联调

## 下次最快启动

在真实工作目录 `D:\成家立业\spacetime_new` 执行：

```powershell
.\start-backend-dev.cmd
```

或：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-backend-dev.ps1
```

当前 Windows 环境没有 `bash`，所以实际启动用 PowerShell / CMD 脚本。根目录也保留了 `start-backend-dev.sh`，内容按下面这条 Bash 命令口径生成：

```bash
export $(grep -v '^#' backend/.env.local | xargs)
cd backend && mvn spring-boot:run -Dspring-boot.run.profiles=dev -Denforcer.skip=true
```

必须在真实工作目录启动，因为 `backend/.env.local` 是本机私有配置文件，Codex 沙箱路径通常看不到。

## 成功标准

启动成功后必须同时满足：

1. `8080` 端口监听。
2. `GET http://127.0.0.1:8080/health` 返回 `code=200`、`data=ok`。
3. `POST http://127.0.0.1:8080/admin/login` 返回 `code=200`，并且能拿到 token。

本次已验证通过（2026-07-09）：

```text
8080 已监听，PID 22548
/health => code 200, ok
/admin/login => peter 登录成功，tokenSet=true
统一审核 L1 => 95 pass / 0 fail / 0 skip
```

## 配置文件

后端启动依赖：

```text
backend/.env.local
```

该文件被 `.gitignore` 忽略，不要提交真实密码。

必须包含：

| 配置 | 用途 |
| --- | --- |
| `DEV_DB_HOST` / `DEV_DB_PORT` / `DEV_DB_NAME` | 后端连接测试库 |
| `DEV_DB_USER` / `DEV_DB_PASSWORD` | 后端访问测试库账号 |
| `DEV_REDIS_HOST` / `DEV_REDIS_PORT` / `DEV_REDIS_DATABASE` / `DEV_REDIS_PASSWORD` | 登录、缓存、token 链路 |
| `ADMIN_ACCOUNT` / `ADMIN_PASSWORD` | 启动后登录烟测，默认可用 `peter / 000000` |

## 常见问题

### health 成功但登录失败

不算启动成功。`/health` 只证明 Spring Boot 进程起来了，不代表业务数据库和 Redis 已连通。

如果没有读到 `DEV_DB_USER` / `DEV_DB_PASSWORD`，MySQL 可能会使用 Windows 当前用户并报错：

```text
Access denied for user '50449' (using password: NO)
```

处理方式：确认 `backend/.env.local` 在真实工作目录存在，然后用根目录启动脚本启动。

### PowerShell Maven 参数被拆坏

PowerShell 直接执行 Maven 时，`-Dspring-boot.run.profiles=dev` 可能被错误解析。根目录 `start-backend-dev.ps1` 已用引号封装参数：

```powershell
& mvn.cmd "spring-boot:run" "-Dspring-boot.run.profiles=dev" "-Denforcer.skip=true"
```

下次不要手敲长命令，直接执行 `.\start-backend-dev.cmd`。

### Codex 沙箱看不到 env 文件

`backend/.env.local` 是未提交的本机私有文件。普通沙箱命令可能显示文件不存在；需要启动后端、连真实数据库、验证登录时，必须在真实工作目录执行启动脚本。
