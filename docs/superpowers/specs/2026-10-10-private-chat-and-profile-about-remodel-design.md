# 私信体验与外层“关于我”动态展示改造设计

日期：2026-10-10

## 1. 目标与范围

本次同时处理两个相互独立、但都影响移动端体验的问题：

1. 私信聊天页在首次进入、从对方主页返回、键盘弹出及消息补齐时出现闪烁、跳动或滚动位置错误。
2. “编辑资料”页外层的“关于我”卡片没有严格跟随后台字段配置，并且已展示问题与底部推荐问题重复。

本次只改小程序前端的状态组织和展示逻辑。除非实现过程中确认现有接口缺少必需数据，否则不改数据库结构和后端接口。

## 2. 已确认的问题

### 2.1 私信聊天

- 首次进入时，本地数据库历史先显示，腾讯 IM 漫游消息稍后再次合并并替换列表，导致列表高度连续变化和肉眼可见的闪烁。
- 从对方主页返回后，页面重新拉取并替换消息，但没有保存和恢复真实滚动锚点，所以当前位置会跳到顶部或其他位置。
- 从私信列表进入时，期望直接定位到最新消息；当前会经历旧位置、内容补齐、再次滚动等多个中间状态。
- 键盘弹出后的滚动逻辑依赖 `messages.length`，补齐或去重消息也会触发滚动，造成输入时跳动。
- 现有自动化测试主要检查源码文本，无法证明异步数据到达顺序下的真实滚动行为。

### 2.2 外层“关于我”

- 内层“关于我”编辑页已经使用 `usePrd01Store` 中最新的 `config.fieldSettings`，动态显示正常。
- 外层“编辑资料”页使用主页或基础资料响应携带的字段配置快照，可能与内层页面配置不一致。
- 外层的前三个展示项与“补充更多关于我的故事”推荐项来自同一段 `slice(0, 3)`，造成重复。

## 3. 私信改造设计

### 3.1 数据职责

- 本地数据库历史是完整、持久的历史来源，不能因为腾讯 IM 漫游只保留近期数据而被覆盖或截断。
- 腾讯 IM 只作为近期消息补充、实时消息来源和发送通道。
- 合并消息时按 `messageNo`、`timMessageId`、`timMsgKey`、`clientMsgId` 等稳定标识去重，再按业务时间排序。
- 如果一次合并没有产生语义变化，必须返回原数组引用，避免无效渲染和无效滚动。

### 3.2 会话缓存

新增页面外的轻量会话缓存，以 `conversationNo` 为键保存：

- 会话详情；
- 已合并消息列表；
- 本地历史分页游标和是否还有更早记录；
- 是否完成过首屏加载；
- 滚动快照：`scrollTop`、`scrollHeight`、是否接近底部；
- 当前进入意图：从列表进入、从个人主页返回或其他入口进入。

缓存只服务页面切换和短期返回，不替代后端持久化，也不跨登录用户复用。退出登录或会话身份变化时清理。

### 3.3 首屏加载

有缓存时：

- 页面首帧直接使用缓存中的详情和消息，不显示空列表中间态。
- 从个人主页返回时恢复缓存的滚动快照，不重新拉取整段历史。

无缓存时：

1. 并行请求会话详情、本地数据库历史和腾讯 IM 近期历史。
2. 本地历史是主数据，腾讯 IM 结果只补齐近期消息。
3. 在内存中完成首次合并后，一次性提交首屏消息和滚动意图。
4. 为避免腾讯 IM 慢请求拖住页面，设置有限的首屏等待预算；超时后先展示本地历史。腾讯 IM 稍后到达时只做一次原子增量合并，不经过空列表或旧列表中间态。

### 3.4 明确的滚动状态机

滚动不再由 `messages.length` 变化隐式驱动，而由业务事件决定：

| 事件 | 滚动行为 |
|---|---|
| 从私信列表或新入口进入 | 首屏完成后一次性定位到最新消息 |
| 从对方主页返回 | 恢复离开前的滚动位置，不拉取并替换整段历史 |
| 自己发送成功 | 定位到最新消息 |
| 收到新消息且原来接近底部 | 跟随到最新消息 |
| 收到新消息但用户正在看较早内容 | 保持当前位置，可由现有未读提示引导 |
| 向上加载更早历史 | 用追加前后的 `scrollHeight` 差恢复视觉锚点 |
| 键盘从关闭变为打开 | 只执行一次输入区可见性调整 |
| 键盘已打开时消息被补齐或去重 | 不因消息数量变化再次滚动 |

离开聊天页进入对方主页前，记录当前滚动快照；返回时以恢复快照为最高优先级。只有从列表等新入口进入时才默认到底部。

### 3.5 异步和失败处理

- 腾讯 IM 历史加载失败不阻塞本地数据库历史展示，错误提示不清空现有消息。
- 会话详情刷新与消息历史刷新分离；从个人主页返回只刷新必要的用户资料、权限或未读状态。
- 任一异步请求返回后都先做语义合并；结果不变时不更新 React 状态。
- 组件卸载或切换会话后，旧请求结果不得写入新会话。

## 4. 外层“关于我”改造设计

### 4.1 唯一配置来源

- 外层“编辑资料”页与内层“关于我”页统一读取 `usePrd01Store` 中最新的 `config.fieldSettings`。
- 主页或基础资料接口中携带的旧字段配置不能覆盖该最新配置。
- 内层“关于我”页面现有动态展示逻辑保持不变。

### 4.2 展示集合

从同一份“后台配置为展示”的问题列表一次性计算两个互斥集合：

1. 主展示项：优先展示已填写且配置可见的问题；不足时按后台顺序补齐可见问题，最多 3 个。
2. 推荐项：从配置可见、尚未填写且未进入主展示项的问题中取前 3 个。

规则：

- 后台配置为不展示的问题，在外层卡片的主展示项、推荐项和占位文案中都不出现。
- 主展示项和推荐项不得重复。
- 没有可见问题时，整个“关于我”卡片隐藏。
- 没有剩余推荐项时，隐藏分隔线、“补充更多关于我的故事”标题和推荐标签。
- 点击推荐标签直接进入内层页面对应题目，而不是只打开页面顶部。

为避免页面组件继续堆积规则，以上计算放入 `profileAboutPresentation` 领域展示函数，由外层页面消费其结果。

## 5. 测试设计

### 5.1 私信行为测试

新增可注入异步源的会话装配/滚动决策测试，至少覆盖：

- 本地历史先到、腾讯 IM 后到时，首屏不经过空列表并最终保持在最新消息。
- 腾讯 IM 返回重复消息时不产生新数组和二次滚动。
- 从私信列表进入默认到底部。
- 从个人主页返回恢复原 `scrollTop`，不触发整段历史刷新。
- 向上加载历史后保持原消息视觉锚点。
- 键盘只在关闭到打开的转换时触发一次调整，后续消息合并不触发。
- 腾讯 IM 失败时仍展示本地数据库历史。

页面源码静态断言只用于防止关键入口被误删，不能作为滚动体验的唯一验证。

### 5.2 “关于我”展示测试

- 后台配置关闭的问题不出现在主展示项或推荐项。
- 主展示项与推荐项没有交集。
- 已填写的可见问题优先进入主展示项。
- 无剩余推荐问题时，外层隐藏推荐区域。
- 推荐标签携带正确题目标识进入内层页面。
- 内层页面继续使用同一份配置且行为不变。

### 5.3 回归验证

- 执行本次新增单元/行为测试。
- 执行消息相关现有闭环脚本，并修正与新交互契约冲突的旧断言。
- 执行“关于我”动态展示相关测试。
- 执行小程序 TypeScript/构建检查；构建产物不得引入新的包内非 Tab 静态图标。
- 在微信开发者工具实机/模拟器复核两段原视频路径。

## 6. 验收标准

### 私信

- 从私信列表进入后，首屏稳定显示完整消息并直接停在最新消息，不出现先空白、再旧位置、再跳到底部的过程。
- 进入对方主页再返回，停留在离开前阅读的位置。
- 键盘弹出、腾讯 IM 补齐或消息去重期间，消息列表不闪烁、不跳顶。
- 本地数据库中的七天以前历史仍可正常查看。
- 上拉加载历史后当前阅读内容不漂移。

### 外层“关于我”

- 外层严格按照后台最新配置决定是否展示问题。
- 默认主展示最多 3 个，推荐项最多 3 个，且两组不重复。
- 推荐项为空时不展示多余标题、分隔线和空标签。
- 点击推荐项能进入对应题目。
- 内层“关于我”页面保持现有正确行为。

## 7. 非目标

- 不重做私信页面视觉样式。
- 不改变腾讯 IM 的七天漫游策略。
- 不把腾讯 IM 数据当作完整历史来源。
- 不修改内层“关于我”题目编辑逻辑。
- 不在本次顺带提交或清理工作区现有的无关删除、构建缓存和测试产物。
