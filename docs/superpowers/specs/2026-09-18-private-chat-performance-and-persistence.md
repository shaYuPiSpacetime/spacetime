# 私信流畅度与可靠落库设计

## 目标

1. 首次进入私信时直接稳定显示最新一屏，不先显示旧位置再跳动。
2. 上拉历史记录时显示固定高度进度，不改变当前阅读位置。
3. 普通文字私信先写入平台数据库，再由服务端可靠投递到腾讯 IM；TIM 回调只负责最终确认和兜底，不再是消息事实唯一来源。

## 后端设计

- 小程序新增普通私信发送接口，必须携带 `Idempotency-Key`，并与请求体 `clientMsgId` 一致。
- `MessageDomainService` 在一个本地事务中校验会话成员、会话状态、女方先发保护和幂等键，创建 `app_message_record(queued)` 与 `app_message_delivery_outbox(pending)`。
- 事务提交后立即调用现有 Outbox 投递服务；失败时沿用现有重试任务，不删除消息事实。
- TIM REST 投递成功后写回 `tim_message_id`、`tim_msg_key`、`sent_at`，更新会话最后消息。
- TIM 发送后回调若先于 REST 响应到达，优先使用 `CloudCustomData.messageNo` 命中已存在记录并确认映射，避免重复插入。
- 回调控制器对缺少鉴权参数等绑定错误仍返回腾讯回调协议体，禁止落入平台通用 `R` 错误体。

## 小程序设计

- 页面首次加载并行获取会话详情和初始化 IM；详情到达后拉取历史。
- 首屏数据和底部锚点都准备完成前显示固定骨架，避免中间态闪烁。
- 初始加载、历史加载、发送分别使用独立状态；历史进度区域固定高度。
- 上拉前记录首条可见消息，插入旧消息后通过 `scrollIntoView` 恢复锚点，并开启微信滚动锚定。
- 普通发送改为调用后端可靠发送接口；页面仍保持键盘、时间规则和本地即时插入体验。
- 消息合并优先以 `messageNo` / `timMessageId` 去重，兼容服务端返回与 TIM 实时事件先后到达。

## 不变范围

- 不改悄悄话、举报、拉黑、已读规则。
- 不改现有时间展示规则和键盘保持逻辑。
- 不修改腾讯 IM 历史消息作为聊天展示来源的现状。

## 验收

- 首次进入稳定落在最新消息，无旧位置闪现。
- 连续上拉历史时当前阅读消息不跳位，加载失败保留已显示内容。
- 普通发送接口相同幂等键不重复建消息或投递。
- 回调正常、延迟或暂时失败时，数据库均先存在消息记录；最终映射不重复。
