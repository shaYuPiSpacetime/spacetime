# 用户认证、消息与资料一致性修复设计

## 目标

修复已确认的资料审核、消息展示、年龄准入、短信登录和私信连接问题；实名认证通过后锁定性别和出生日期。

## 已确认规则

- 学历认证通过后，学校、学校编码和最高学历以审核快照为准；基础资料接口不得绕过认证直接改写。更新学历只能重新提交学历认证。
- 本人编辑表单可以看到最近一次待审或驳回内容用于修改，但“主页预览”和其他用户看到的主页只能使用已审核生效内容。
- 消息首页只展示后端真实摘要；设计稿模拟数据仅允许显式 `mockScene` 使用。
- `CORE_BLOCKED` 是硬性准入拦截，不能降级成“待认证”页面。
- 生产短信登录使用配置的 `SmsCodeProvider`；mock 环境保留固定测试验证码。
- TIM 未登录错误 `2024` 视为幂等退出，不应阻塞后续登录；连接失败应返回具体错误并允许重新初始化。
- “喜欢我的人”头像继续使用入向点赞记录的 `fromUserId`，当前实现已符合规则，不改业务代码。
- 在校生的行业、职业、公司已是非必填且页面不展示，保留现状；“学生”属于身份，不新增行业字典项。

## 实现边界

1. 后端审核通过时同步学历有效快照到用户公开投影；项目尚未上线，不执行历史数据迁移。
2. 基础资料保存时拒绝修改已认证学历字段；移动端同步显示为不可编辑。
3. 主页预览分别保存“编辑态最新内容”和“预览态有效内容”。
4. 删除非 mock 场景的消息硬编码兜底。
5. 统一小程序硬拦截判断。
6. 恢复短信 Provider 调用和 Redis 真值校验。
7. 加固 LiteChat 初始化生命周期和错误传递。
8. 实名认证有效后，字段配置禁用性别和出生日期，服务端拒绝旧客户端绕过修改。

## 暂缓项

- 无产品规则待确认项；真实短信和腾讯 IM 双账号链路留到上线前联调。
