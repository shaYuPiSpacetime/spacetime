# 官方小助手接入微信原生客服设计

## 目标

将小程序“官方小助手”页面中的客服入口统一接入微信原生客服会话，用户点击后直接进入微信客服对话，不再显示仅包含工作时间的弹窗。

## 范围

- 页面底部固定“联系客服”使用微信原生 `Button openType="contact"`。
- 官方助手消息卡片的 `actionType` 为 `wechat_service` 时，使用同一原生客服入口。
- 小程序消息类型与 Mock 数据统一使用正式协议值 `wechat_service`。
- 删除官方小助手页面中针对客服入口的工作时间弹窗逻辑。

## 非目标

- 不兼容旧值 `customer_service`；项目尚未上线，无历史数据迁移需求。
- 不建设自有客服会话、坐席分配、消息回调或管理后台回复能力。
- 不修改后端、数据库、反馈箱及其他页面的客服入口。

## 实现方案

1. 在官方助手频道页引入 Taro `Button` 组件。
2. 底部客服入口改为真实可见的原生客服按钮，保持现有布局样式。
3. 消息卡片遇到 `wechat_service` 时直接渲染原生客服按钮；其他动作继续使用现有受控跳转逻辑。
4. 将前端消息类型和 Mock fixture 中的 `customer_service` 更新为 `wechat_service`。

## 错误与降级

- 微信客户端负责客服能力的打开与不可用提示。
- 非微信环境下保持页面可渲染，不新增自建客服降级链路。
- 未识别的消息动作继续走现有安全拦截，不作为页面路径执行。

## 测试

- 先增加静态回归测试，验证底部入口和卡片入口均使用 `openType="contact"`。
- 验证代码中不再存在 `customer_service` 或客服工作时间弹窗。
- 运行消息模块现有测试。
- 执行小程序 TypeScript/构建验证，确认 Taro 组件属性合法。
