# 私信本地历史与 TIM 实时消息合并设计

## 目标

- 腾讯 IM 继续承担实时收发和最近漫游，普通发送仍由小程序 LiteChat SDK 直发。
- 平台 `app_message_record` 作为完整历史来源，TIM 七天漫游到期后仍可查看数据库中保留的消息。
- 本地历史先展示，TIM 连接和漫游加载不得阻塞首屏；两路数据按稳定标识去重、按发送时间排序。

## 后端

- 新增 `GET /miniapp/message/conversations/{conversationNo}/messages`。
- 服务端先校验当前用户是会话成员，再按消息记录 ID 倒序游标分页查询已发送消息。
- 返回 `messageNo`、`clientMsgId`、`messageType`、`content`、`direction`、`sentAt`、`sendStatus`、`timMessageId`、`timMsgKey`，不暴露内部用户 ID。
- 游标绑定当前用户和会话号，非法游标返回现有消息参数错误。

## 小程序

- 进入会话时同时发起会话详情、本地历史和 IM 连接；本地历史成功后立即渲染并定位最新消息。
- IM 最近漫游完成后仅补充或刷新本地列表，按 `messageNo`、`timMessageId`、`clientMsgId` 去重。
- 上拉历史只使用本地数据库游标，保留现有滚动锚点和固定高度加载状态。
- 本地历史失败时保留 TIM 漫游兜底；TIM 失败时只要本地历史成功，历史仍正常展示。

## 不变范围

- 不改变普通私信 SDK 直发、键盘保持、失败重试、已读、举报、拉黑和女性保护规则。
- 不新增数据库表，不改变现有消息留存和清理策略。
- 数据库正文已经清理的记录不恢复正文。

## 验收

- TIM 漫游之外但数据库仍有正文的消息可在聊天页上拉查看。
- 首屏不会等待 TIM 连接才显示本地历史。
- 同一消息同时来自本地库与 TIM 时只显示一次。
- 非会话成员不能读取历史，分页游标不能跨用户或跨会话复用。
