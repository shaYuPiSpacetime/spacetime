# 私信 SDK 直发与回调归档设计

## 目标

普通私信恢复由微信小程序内的腾讯 LiteChat SDK 直接发送，避免经过“客户端→业务后端→腾讯 IM”的串行链路；腾讯 IM 的 `C2C.CallbackAfterSendMsg` 继续作为业务数据库归档入口。

## 已确认方案

- 普通文本：客户端 SDK 直发；发送动作不调用业务后端代发接口。
- 悄悄话及系统消息：继续由服务端可靠投递，不改变现有规则。
- 发送交互：输入框立即清空，键盘保持，SDK 创建本地消息后立即显示，允许连续发送。
- 失败重试：复用 SDK 原始消息和 `clientMsgId`；TIM 账号缺失时刷新会话映射后安全重试。
- 后端归档：发送后回调验签、校验 SDKAppID/时间窗，按 `MsgKey` 幂等写库并更新会话和未读数。
- 连接状态：不向用户展示“私信连接中”横条；真实失败通过消息失败状态和轻提示反馈。

## 数据流

1. 页面已完成会话详情和 LiteChat 初始化。
2. 用户发送文本，页面清空输入框并调用 `gateway.sendText`。
3. LiteChat 创建本地消息并通过网关事件立即上屏，然后向腾讯 IM 发送。
4. 腾讯 IM 向接收方实时下发，同时调用后端发送后回调。
5. 后端按 `MsgKey` 幂等归档；回调重复不会重复建消息。

## 异常与可靠性

- SDK 发送失败：气泡标记失败，可点击重试，正文不覆盖用户随后输入的新内容。
- 回调重复：使用 `MsgKey` 和数据库唯一约束幂等。
- 回调暂时失败：依赖腾讯控制台“事件发生之后回调失败重试”；后端返回腾讯协议应答。
- 后端代发接口保留，但不作为普通私信正常发送主链路。

## 验收

- 普通私信页面不调用 `sendConversationMessage`。
- 普通私信使用 `gateway.sendText`，失败使用 `gateway.retry`。
- 键盘不收起、按钮不因网络请求锁死、消息 SDK 本地事件立即上屏。
- 消息模块回归、TIM 回调单测、正式微信小程序构建全部通过。
