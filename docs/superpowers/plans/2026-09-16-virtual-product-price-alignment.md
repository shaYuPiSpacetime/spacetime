# 微信线上道具价格对齐实施计划

**目标：** 会员、千寻币的可售套餐展示价、服务端订单金额和微信线上已发布道具价一致；后台改价不能再次制造不可支付商品。

**方案：** 以用户提供的线上道具清单为当前生产商品基线（`coin_10=99`、`coin_11=268`、`coin_12=428`、`vip_7=0.01`、`vip_8=1`、`vip_10=1000` 元）。公共价格策略按商品 ID 和分金额校验；后台保存、上架及支付下单共用策略。未发布商品不得作为可售套餐。生产数据用单独幂等 SQL 对齐，不伪造微信侧发布状态。

**影响范围：** `backend/` 的商业化配置、套餐列表、订单创建及测试，`frontend/` 的价格编辑提示，`deploy/sql/prod/` 的对齐脚本；小程序前端只消费服务端套餐价。

**成功标准：** 六项截图商品的人民币金额精确换算为分；小程序列表与订单金额一致；后台尝试修改已发布商品价、上架未列入清单的商品会被明确拒绝；现有未提交的小程序体验问题修复仍可构建。

**发布边界：** 用户明确要求价格与微信线上版本保持一致、提交、Push 和发布小程序。`master` Push 会自动触发后台/后端生产部署；092 数据对齐脚本也纳入现有后端迁移工作流。迁移前已只读核对生产库六个 ID、套餐名称与会员时长，且 SQL 内置同样的中断门禁；不单独手工写生产库。小程序默认先上传体验版，不代表正式版审核通过。
