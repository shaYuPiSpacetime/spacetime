# 私信 iOS 连接与已读回执修复计划

## 目标

- 普通 TIM 文本消息使用 TIM 定位字段上报已读，不把 IM ID 冒充平台消息编号。
- 异步归档或历史会话造成的定位失败不在可正常聊天的页面展示误导性红色错误；后端未读状态仍为真值。
- iOS 登录慢或首次超时后可安全重试，不让旧 SDK 实例事件污染新连接。

## 实施与验证

1. 先增加消息定位、已读错误处理和 SDK 登录生命周期的回归用例，并确认旧实现失败。
2. 修正已读请求参数、SDK key 映射及页面提示；不改变审核链路。
3. 延长登录等待上限，超时重试时销毁未就绪实例，并隔离旧实例事件。
4. 运行消息模块测试、TypeScript 检查与定向构建；iOS 真机连接需要用户复测并提供 SDK 错误日志以确认根因。

## 用户追加的问题

5. 给 LiteChat basic 注册历史消息插件，首屏从云端拉取历史；避免首屏响应覆盖同时收到的新消息。
6. 私信气泡展示本地时间；连续发送时保留输入焦点和键盘。
7. 后台普通私信入库依赖腾讯 IM 发送后回调，测试库只读核验回调落库情况；普通模式 IM 链接需核验微信合法域名，不能用调试模式当验收依据。
8. 解锁按请求 ID 查服务端日志，排除表结构与余额问题；未定位具体异常前不触碰扣币事务。
