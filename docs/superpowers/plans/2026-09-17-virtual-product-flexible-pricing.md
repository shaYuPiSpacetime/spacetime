# 会员与千寻币灵活改价实施计划

**目标：** 后台允许随时录入会员、千寻币的新价格，同时避免微信虚拟支付因商品 ID 或价格不一致而失败。

**已确认约束：** 微信 `wx.requestVirtualPayment` 要求 `productId` 已发布，`goodsPrice` 与微信道具价格一致；新道具发布后约 10 分钟才可能生效。现有代码将六个价格写死在前后端，生产 092 SQL 在每次后端部署时重跑并覆盖运营价格。

**方案：** 用户已确认允许服务端自动创建、发布微信新商品。先停止已执行的 092 SQL 重复执行；后台保存新报价后，旧商品保持可售；服务端上传、发布新商品并确认生效后，原子切换生效价与支付商品 ID。发布失败时保留旧价，不让不可支付价格进入小程序。

**影响范围：** `deploy/` 迁移链路、`backend/` 套餐配置与微信商品发布、`frontend/` 商业化管理页。小程序套餐页使用服务端报价，通常无需额外改价逻辑。

**成功标准：** 后台可输入任意合法正价；保存新报价不立即破坏当前支付；新商品生效后，小程序展示价、订单金额和微信商品价一致；多次改价和失败重试不覆盖或重复发货历史订单；后续部署不会重置运营价格。

**授权边界：** 本轮只要求修改功能，未要求提交、Push、生产部署或实际修改微信商品。任何生产数据库或微信商品写入须在实现与验证完成后另行确认发布。
