# 生产数据库迁入本机实施计划

**目标：** 将生产 `shikongxiehou_prod` 从跨地域 RDS 迁到现有生产机内部，使历史小程序版本无需重新提审即可使用低延迟连接。

**架构：** 生产 MySQL 使用官方固定摘要镜像、Docker 私网、宿主持久化目录和独立数据库账号；测试继续使用原 RDS。保留原生产库和切换前备份，部署流水线识别本机数据库，禁止意外初始化空生产库。

**技术栈：** Docker、MySQL、Spring Boot、Shell、现有 GitHub Actions。

**需求依据：** 2026-11-05 用户明确要求迁移，原因是当前提审为历史小程序版本，客户端性能改动需要之后审核发布。

## 约束与核验重点

- 仅修改生产数据库连接及所需部署、备份配置；不修改小程序包、DNS、测试数据库或业务数据语义。
- `master` 同步后实施；不提交业务导出、密码、密钥或私有配置。
- 源库当前为 MySQL 8.0.36、151 张 InnoDB 表、约 515 MB、1 个存储过程，无视图、触发器和事件。
- `lower_case_table_names=1`、字符集、排序规则、时区和自增下限保持兼容；新实例先演练完整恢复和应用读取。
- 正式切换前暂停生产后端及其定时任务，再执行最终一致性导出和校验，避免遗漏新写入。
- MySQL 不发布任何宿主端口，root 仅本地管理；应用账号只拥有生产库权限。
- 数据目录、配置缺失时，后续流水线必须失败，不能生成空库继续发布。
- 切换后如已发生新写入，禁止直接切回旧 RDS；须停写、反向同步并校验后再回退。
