# 消息 15 稿全 Mock 蓝湖还原实施计划

> 日期：2026-07-14
> 设计基线：蓝湖项目“时空邂逅0625”最新 15 张消息稿
> 逻辑视口：375×812
> 当前交付边界：小程序全 Mock 页面、领域适配层、接口契约与验收证据；不实现后端、数据库和腾讯云 IM SDK。

## 1. 目标与交付标准

1. 以 15 张蓝湖稿为唯一视觉基线，使用 6 个业务路由承载 15 个可交互状态。
2. 页面只依赖 `messageService` 与 `MessageImGateway`，默认 `MINIAPP_MESSAGE_PROVIDER=mock`，未来切换真实接口或 LiteChat 时不修改页面组件与领域类型。
3. 15 个状态均能由真实可见组件交互到达；`mockScene` 只用于自动截图时稳定复现。
4. 所有非底部静态图标必须来自蓝湖 2x 原稿精确裁切，并经 OSS 清单引用；不得用近似图标、整页背景图、透明热区或截图按钮。
5. 375×812 每稿可控视觉差异清零、还原度不低于 97%；补充 414×896 响应式检查。
6. 输出可直接被后端实施引用的单数路径接口契约，形成 Mock fixture、前端领域类型、后端 DTO 与未来 LiteChat 数据源的闭环。

## 3. 实施任务

### 阶段 A：设计基线与静态门禁

- 保存 15 张完整 2x 原稿到仅供验收的参考目录，登记 Design ID、文件 SHA-256 与设计尺寸。
- 建立设计 token、组件映射、切图清单和状态到路由映射。
- 先编写失败的静态门禁，校验 15 个 ID、6 个路由、禁止蓝湖 CDN/参考目录/整页截图、禁止透明点击层。
- 从原稿无缩放、无格式转换裁切头像、YO 标识、私信气泡、助手喇叭、系统铃铛、时间线标识和会员标识；记录源坐标、尺寸与 SHA-256。
- 使用现有 OSS 上传和校验脚本生成 `ossIcons.ts`，底部 Tab 图标继续使用包内资源。

### 阶段 B：Mock 领域层（TDD）

- 先为领域模型、发送失败重试、悄悄话状态机、已读和可见性隐藏写失败测试。
- 建立 `MessageHome`、`ConversationSummary`、`ChatMessage`、`WhisperRecord`、`OfficialChannelMessage` 等统一类型。
- 建立 `messageService` Provider 与 `MessageImGateway`；Mock 实现支持历史、发送、失败、以原 `clientMsgId` 重试和已读。
- 使用独立 Zustand store 保存跨页面 Mock 状态；小程序重新启动时恢复 fixture，不持久化为跨启动业务数据。
- 隐藏单条或全部只改变当前用户列表可见性，不改变悄悄话业务状态，也不删除审计记录。

### 阶段 C：逐组视觉闭环

1. 消息首页：双入口、喜欢我的人、助手、系统消息、普通私信列表与认证兼容态。
2. 悄悄话列表：双 Tab、左滑删除、全部删除确认、已处理/待处理分区。
3. 悄悄话详情：过期、匹配、解除、申请编辑与 60 字限制。
4. 私信列表与聊天：真实输入框、原生键盘、回复、失败重发、已读。
5. 官方频道：官方小助手、系统消息、真实操作入口。

每完成一组立即执行：运行截图 → 与蓝湖叠图/像素差异 → 输出差异清单 → 修复可控差异 → 记录评分。不得先铺完全部页面再集中返工。

### 阶段 D：接口与验收闭环

- 形成 `/miniapp/message/*` 单数路径契约；每个端点定义请求、`R<T>`、分页、权限、错误码、幂等和 Mock/LiteChat 映射。
- 更新腾讯云 IM 技术方案对新契约的引用；将旧 `/miniapp/messages/*` 标记为废弃口径。
- 执行静态门禁、ESLint、TypeScript、OSS 资源校验、`build:weapp`、微信开发者工具自动化和两种视口截图。
- 验收报告逐稿记录原稿、运行图、差异、修复轮次和评分；任一稿低于 97% 时保持“未通过”。

## 4. TDD 场景

| 场景 | 预期 |
| --- | --- |
| Provider 默认值 | 未配置时使用 `mock`；仅接受 `mock/real` |
| 发送文本 | 先产生 `sending`，随后进入 `sent` 或 `failed` |
| 失败重发 | 沿用原 `clientMsgId`，不追加重复业务消息 |
| 悄悄话创建 | 同一 `Idempotency-Key` 返回同一结果，不重复扣费/创建 |
| 悄悄话回复 | 合法状态进入 `replied/matched`，非法终态拒绝流转 |
| 单条隐藏 | 仅当前用户列表不可见，详情审计记录仍存在 |
| 批量隐藏 | 仅隐藏当前筛选范围，不能等价为拒绝或撤销 |
| 已读 | 会话与首页未读汇总同步归零 |
| 长文本 | 服务端契约返回 `contentMaxLength=60`，前端按该值限制 |
| 启动重置 | 重新启动恢复初始 fixture |

## 6. 明确不在本轮实现

- Spring Boot Controller、Service、DAO、Mapper、数据库表与迁移脚本。
- 腾讯云 IM 应用配置、UserSig 服务、回调 Controller、LiteChat SDK 依赖和真实消息发送。
- 已完成的心动、会员、千寻币页面视觉改造。

## 7. 完成定义

- 15 个 Design ID、6 个业务路由与 15 个运行状态一一对应。
- 所有状态可由真实交互到达，自动化可用 `mockScene` 稳定复现。
- 页面不直接依赖 fixture、HTTP 或 LiteChat SDK 对象。
- 非底部静态图标全部经 OSS 清单引用，切图来源和哈希可追溯。
- 规定命令与自动化交互通过；15 张 375×812 评分均不低于 97%，414×896 不破版。
- 三份新文档及两份旧方案引用更新完成，后端可以直接引用接口契约实施。
