# 关系反馈与互动链路小程序闭环实施计划

> 日期：2026-08-04
> 基线：`02-关系反馈与互动链路`、`2026-07-16-关系反馈与互动链路-mobile-api-handoff.md`
> 方法：测试驱动开发（红 → 绿 → 重构），完成后按 `code-test` 流程更新测试用例与独立测试报告。

## 目标

把“喜欢我的、最近访客、互相喜欢、匹配弹窗、单人解锁、公开资料页”做成真实接口驱动的闭环：不使用假数据或 URL 参数伪造会员状态，展示权限只服从后端 `displayStatus/accessMode`，所有确认型写操作具备失败留场、可重试和幂等保护，并通过后端测试、小程序静态门禁、类型检查、构建及微信开发者工具运行态自动化验证。

## 约束

- 不改动与本任务无关的用户未提交文件；尤其避免覆盖现有 `app.config.ts`、`ProfileServiceImpl.java` 修改。
- 小程序自动化只连接本地 Mock API；默认构建仍固定使用正式 API 地址，测试地址必须由显式 E2E 环境变量启用。
- 非底部 Tab 图标不新增本地/远程混用；本任务优先复用现有图标和真实组件。
- 测试结果只写入 `testreport.md`，测试设计写入 `testcase.md`。

## 任务一：先建立关系链路状态机与错误契约测试

**文件**

- 新增：`miniapp/scripts/test-relation-feedback-flow.cjs`
- 新增：`miniapp/src/domain/relationFeedbackFlow.ts`
- 修改：`miniapp/src/services/request.ts`
- 修改：`miniapp/src/constants/config.ts`
- 修改：`miniapp/package.json`

**红灯测试**

Node 测试至少覆盖：

1. `displayStatus=BLUR` 时不暴露昵称、头像等强身份字段，URL 参数不能改变该结论。
2. 徽标 `0 -> 隐藏`、`1..99 -> 原数`、`>=100 -> 99+`。
3. 解锁同一次报价只能生成一个 `requestId`，重复点击复用该值；新报价才生成新值。
4. 匹配弹窗只有 `ack` 成功后才能执行关闭或跳转动作。
5. E2E API 覆盖仅在 `MINIAPP_E2E_MODE=true` 且地址为 localhost/127.0.0.1 时生效。
6. `request` 抛出的错误保留后端 `code`，页面不再依赖文案正则判断业务错误。

**最小实现接口**

```ts
export interface ApiBusinessError extends Error {
  code?: number
  httpStatus?: number
}

export function formatBadge(count: number): '' | string
export function isIdentityVisible(displayStatus: 'CLEAR' | 'BLUR'): boolean
export function createUnlockAttempt(quoteNo: string): {
  quoteNo: string
  requestId: string
}
```

`resolveApiBaseUrl` 只接受本地回环地址的 E2E 覆盖；非法测试地址直接回退固定正式地址，防止测试构建误连任意服务。

## 任务二：重构喜欢/访客主页为真实数据状态机

**文件**

- 修改：`miniapp/src/pages/community/index.tsx`
- 修改：`miniapp/src/services/relation.ts`
- 视复用需要新增：`miniapp/src/components/RelationStatePanel/index.tsx`

**红灯测试**

在 `test-relation-feedback-flow.cjs` 和静态门禁中先断言：

- 源码不存在 `fallbackLikes/fallbackVisitors`、默认人数、`member` URL 权限覆盖、硬编码金币价格。
- 喜欢列表首次请求不带 `snapshotCursor`；首屏完成后再确认已读；确认失败允许重试。
- 翻页复用首次返回的 `readCursor`；下拉刷新丢弃旧游标并建立新快照。
- 访客按“今天/昨天/更早”分组，页面不存在一期隐藏访客运营入口。
- 接口失败保留最近一次真实数据，显示错误态和重试入口；无历史数据时显示独立空态。

**实现状态**

```ts
type LoadState = 'idle' | 'loading' | 'ready' | 'empty' | 'error'

interface LikesSnapshot {
  items: RelationCard[]
  snapshotCursor?: string
  nextCursor?: string
  acknowledged: boolean
}
```

- 首次渲染通过 `Taro.nextTick` 后调用 `markLikesRead(readCursor)`；只有成功才置 `acknowledged=true`。
- 清晰卡片进入真实公开资料页；模糊卡片只进入解锁流程。
- 访客卡片传递 `scene=VISITOR`、`source=RECENT_VISITOR`，喜欢卡片传递对应喜欢场景。
- `accessMode=BLOCKED` 渲染准入阻断；正常用户仅渲染后端返回的“全量已解锁 + 最新锁定窗口”，不在端内重新推导权限。

## 任务三：封闭单人解锁与匹配弹窗写操作

**文件**

- 修改：`miniapp/src/pages/community/index.tsx`
- 修改：`miniapp/src/pages/heart/mutual.tsx`
- 修改：`miniapp/src/components/AppTabBar/index.tsx`

**红灯测试**

- 首层解锁确认框不发请求；“只看 ta”才请求报价。
- 报价金额完全取自响应；报价已解锁时刷新列表，不再扣费。
- 同一报价重复点击只提交一次，失败重试仍复用相同 `requestId`。
- `5001` 等业务码按接口语义处理，不通过错误文案猜测。
- 匹配弹窗 `markMatchPopupRead` 失败时保持弹窗可见，成功后才进入公开资料或私聊页。
- 互相喜欢页具备准入、加载、空、错误、分页状态，不显示静态“4 人”。
- 心动 Tab 徽标遵循 `formatBadge`。

**实现顺序**

1. 写失败测试并确认红灯。
2. 加入 `submitting` 防重复锁和稳定解锁尝试对象。
3. 把匹配弹窗关闭、资料跳转、聊天跳转统一封装成 `ackThen(action)`。
4. 列表成功后刷新徽标；0 不渲染徽标节点。

## 任务四：补齐公开资料接口与访问上报时序

**后端文件**

- 新增：`backend/src/main/java/com/spacetime/miniapp/dto/response/PublicProfileVO.java`
- 新增：`backend/src/main/java/com/spacetime/miniapp/service/MiniappPublicProfileService.java`

- 新增：`backend/src/test/java/com/spacetime/miniapp/service/MiniappPublicProfileServiceImplTest.java`

**小程序文件**

- 修改：`miniapp/src/services/profile.ts`
- 修改：`miniapp/src/pages/heart/user.tsx`

**红灯测试**

- 非法目标、关闭/异常账号、自身访问、黑名单关系不能返回公开资料。
- 公开头像、背景、相册和自我介绍走审核后公开投影，不返回原始未审字段。
- 返回 `liked/matched/canEnterConversation` 供页面决定按钮状态。
- 小程序只有在资料主体请求成功后上报访问；同一次页面访问失败重试复用同一 `eventNo`。

**接口**

```java
@GetMapping("/public/{userId}")
public R<PublicProfileVO> getPublicProfile(@PathVariable Long userId) {
    return R.success(publicProfileService.getPublicProfile(getCurrentUserId(), userId));
}
```

页面加载顺序固定为：生成/复用本次 `eventNo` → 拉取公开资料 → 成功渲染主体 → `reportVisit`；资料请求失败不产生访问记录。喜欢/取消喜欢复用真实关系 API；可聊天时导航到现有私聊页并传递目标用户和匹配标识。

- 新增截图：`docs/验收报告/截图证据/2026-08-04-关系反馈与互动链路-小程序闭环/*.png`

**自动化场景**

1. 喜欢页：清晰/模糊卡片、徽标、首屏已读、空态、失败重试、翻页快照。
2. 访客页：分组、清晰资料跳转、模糊单人解锁、取消无副作用、重复确认仅一次。
3. 匹配弹窗：确认失败留场、重试成功后资料/聊天跳转。
4. 互相喜欢：真实列表、分页、空态、准入阻断。
5. 公开资料：加载成功后访问上报；资料失败不访问上报；喜欢状态切换。

Mock 服务为每次请求记录方法、路径、请求体和调用次数，自动化结束时对副作用次数作精确断言并输出截图证据。
