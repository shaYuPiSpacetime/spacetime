# 后台赠送与认证奖励实施计划

目标：后台按用户赠送 VIP 天数、千寻币；资料及认证达标后按后台额度给本人一次性奖励。

## 边界与方案

- 在 master 实现，保留无关未跟踪文档。不创建付费订单，不改累计充值金额，不批量补发历史资产。
- 新增赠送台账，保存幂等键、操作者、原因、币余额及会员到期时间前后值；资产与台账同事务，千寻币复用现有流水。
- 会员从当前有效到期时间顺延，否则从发放时间起算。重复请求返回原台账，参数不同拒绝。
- 商业化配置新增认证奖励额度，默认 0（关闭）；每用户固定幂等键，改配置或重复审核不能重复领取。
- 用户已确认：资料填写完成，且实名、头像、学历三项认证均通过后，每人奖励一次。客户端不能决定奖励资格或数量。

## 实施顺序

1. 新增赠送台账实体、DAO、Mapper、迁移及权限；先补关键用例，再实现公共入账服务和后台接口。
2. 接入商业化配置、资料保存与审核通过触发；不影响邀请人奖励。
3. 用户详情增加赠送表单与历史记录；配置页增加奖励额度。
4. 编译后端和管理端，检查事务、幂等、权限及默认关闭；按用户要求不运行测试套件，不代真实用户发放。
5. 同步远端、只提交本轮文件、Push，核对两环境部署及本次小程序独立目录上传结果。

## 关键核对

- 零数、负数、小数、整数溢出及空原因不入账。
- 网络重试不重复发放；相同请求号不同参数不能静默成功。
- 会员延期不截短既有期限；赠送不伪造收入。
- 未完成认证、关闭奖励、重复审核均不新增奖励。
- 数据库迁移先于服务发布，前端赠送成功后刷新资产与记录。

## 本轮验证与发布边界

- 后端源码和测试源码编译成功（Java 21，`mvn -DskipTests package`），没有运行新增业务用例。
- 管理端构建成功；构建命令隐式运行了仓库原有的知音配置及用户导入前置检查，没有额外启动全量测试。
- 小程序重新构建成功，89 页注册与无开发 Token 门禁通过。
- 未执行真实用户赠送、扣款或修改现网奖励额度；默认额度为 0。发布结果记录到本次 `.runtime/weapp-release-*/发布校验记录.md`。
