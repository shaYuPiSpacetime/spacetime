# 心动与访客空状态图实施计划

> 执行约束：按 TDD 的“失败门禁 → 最小实现 → 回归验证”顺序完成；复用仓库已有高清切图和 OSS 地址，不新增包内静态图引用。

## 目标

- “对我心动”无数据时展示 `empty-heart.png` 对应的 OSS 图片，文案为“暂时没有对我心动人员”。
- “访客”无数据时展示 `empty-following.png` 对应的 OSS 图片，文案为“暂时还没有访客”。
- 两张空态插画使用全宽容器水平居中，插画与文案组合在导航和底部操作区之间垂直居中，正常空态不展示“重新加载”。
- 加载态、错误态和重试交互保持不变。

## 实施步骤

1. 在 `miniapp/scripts/validate-relation-feedback-miniapp-closure.mjs` 增加静态门禁，校验两处精确文案、两张独立 OSS 图、水平/垂直居中及空态无重试按钮；先运行并确认失败。
2. 在 `miniapp/src/pages/community/index.tsx` 引入 `miniappOssIcons`，为首屏内容建立纵向 flex 布局，让空态撑满导航与底部操作区之间的剩余高度；重试按钮仅允许错误态渲染。
3. 运行关系反馈领域测试、静态闭环门禁、OSS 资源校验和小程序构建，确认无回归。
4. 在 `docs/验收报告/` 记录设计基线、素材映射、验证证据和已知限制。

## 验收标准

- 两个空态使用不同且与参考截图一致的插画。
- 文案逐字匹配用户要求。
- 图片使用 `mode="aspectFit"`，不拉伸、不裁切，且不出现在加载或错误状态。
- 两张图片水平居中，插画与文案组合在首屏可用区垂直居中；空数据状态没有“重新加载”，错误态仍可重试。
- OSS URL 可访问，专项门禁和小程序构建通过。
