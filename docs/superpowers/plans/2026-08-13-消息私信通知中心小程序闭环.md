# 消息、私信与通知中心小程序闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 依据 `2026-07-31-消息、私信与通知中心-mobile-api-handoff.md`，将小程序消息首页、普通私信、悄悄话、助手/系统通知、未读同步和举报改造成可连接真实后端与腾讯云 LiteChat 的完整闭环。

**Architecture:** 平台 HTTP 负责资格、业务状态、白名单、未读真值和悄悄话编排，LiteChat 仅负责普通私信的会话、历史、文本发送及 TIM 已读。页面只消费稳定的领域模型；SDK 原始消息、UserSig 和聊天正文不得进入持久化状态或日志。Mock 仅保留在显式设计验收场景，生产默认使用真实 Provider。

**Tech Stack:** Taro 4.1.9、React 18、TypeScript 5.6、Zustand 5、`@tencentcloud/lite-chat@4.4.2`、Node Test、Playwright、Spring Boot 3.4 后端契约。

## Global Constraints

- 普通私信发送、历史、会话和 TIM 已读只能调用 LiteChat SDK，平台 HTTP 不得新增正文发送或历史接口。
- 悄悄话创建与回复只能调用平台 HTTP，由服务端 REST 投递；客户端不得用 SDK 直发悄悄话。
- 首版仅支持纯文本和 Unicode Emoji；图片、语音、视频、文件、贴纸等富媒体一律不提供入口。
- `conversationNo`、`whisperNo`、消息编号、游标等标识统一按字符串处理；游标保持不透明。
- 消息角标只使用后端 `messageUnreadCount`，禁止客户端加减猜测；0 隐藏，1～99 原数，超过 99 显示 `99+`。
- `accessMode=restricted` 时清除并隐藏真实私信与悄悄话，只展示平台允许的安全系统消息。
- 未知枚举和未知协议版本必须安全降级为只读并触发完整刷新，不得默认允许发送或跳转。
- UserSig 只保存在内存；距离过期不足 10 分钟刷新；无有效旧凭证且接口返回 30023 时进入只读态。
- 禁止记录消息正文、UserSig、原始 SDK 消息对象或带凭证请求。
- 禁止恢复忽略、取消、批量隐藏、邀请响应、通知详情、全部已读等已删除能力。

export function formatMessageBadge(count: number): string {
  if (!Number.isFinite(count) || count <= 0) return ''
  return count > 99 ? '99+' : String(Math.floor(count))
}

export function normalizeConversationState(value: unknown): ConversationStatus {
  return value === 'active' || value === 'blocked' || value === 'invalid' ? value : 'invalid'
}
