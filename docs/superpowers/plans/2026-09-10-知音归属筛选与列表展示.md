# 知音归属筛选与列表展示实施计划

> **供智能体执行：** 必须使用 `test-driven-development`，按任务逐项完成红—绿—重构。

**目标：** 让管理后台内容管理可以按“心灵搭子 / 时空站台”筛选并在列表、详情中展示归属，同时修复已发布心灵搭子内容因运营手机号名单为空而不展示的问题。

**架构：** 保持现有 `community_post` 与 `sincere_post` 数据模型不变。时空站台继续由 `post_type=sincere_post` 判定；心灵搭子继续由私有配置 `community.soulmate_source_phones` 对应作者判定，后台服务将该规则派生为稳定字段 `zhiyinSection`，不向前端暴露完整手机号名单。

**技术栈：** Java 21、Spring Boot 3.4、MyBatis-Plus、React 18、TypeScript、Vite、JUnit 5、Playwright、MySQL 8。

## 全局约束

- “心灵搭子”只展示后台配置手机号对应账号发布的 `community_post`。
- “时空站台”只对应 `sincere_post`，发布权限仍由启用的后台工作人员身份控制。
- `admin/` 与 `miniapp/` 不互相依赖；共用稳定业务编码，展示文案从社区 Meta 返回。
- 手机号配置继续保持 `COMMUNITY_PRIVATE`、`public_visible=0`，列表接口只返回派生模块编码。
- 不在仓库提交生产手机号或用户隐私数据；生产修复使用已核验内容在服务器内关联作者完成。

- [ ] **步骤 2：在查询前解析心灵搭子作者集合并应用筛选**

```java
Set<Long> soulmateAuthorIds = resolveSoulmateAuthorIds();
if (section == SOULMATE && soulmateAuthorIds.isEmpty()) {
    return emptyPostAdminPage(req);
}
wrapper.eq(section == STATION, CommunityPost::getPostType, "sincere_post")
       .eq(section == SOULMATE, CommunityPost::getPostType, "community_post")
       .in(section == SOULMATE, CommunityPost::getAuthorId, soulmateAuthorIds);
```

}
