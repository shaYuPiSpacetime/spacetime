# PRD-05 推荐与社区全链路闭环实施计划

> **执行要求：** 按任务逐项采用 TDD（红 → 绿 → 重构），完成后运行 `verification-before-completion` 全量门禁。

**目标：** 以“定稿：05”正式 PRD 为业务规则，以静态 Demo 为管理后台视觉基线，完成数据库、后端、管理后台和小程序社区真实数据闭环；PRD-03 消息域保持冻结。

**架构：** 社区领域继续使用单体六层架构；`common` 承载实体、DAO、Mapper、内容安全、准入治理和 Outbox，`admin` 与 `miniapp` 只依赖 `common`。管理后台复用正式全局壳，小程序保留现有蓝湖 UI。外部消息只写社区事件 Outbox，不实现 PRD-03 消费端。

**技术栈：** Java 21、Spring Boot 3.4、MyBatis-Plus、MySQL 8、Redis、React 18、TypeScript、Vite、Tailwind、Taro、Playwright。

---

## 硬边界

- 不修改消息页面、消息 Store、腾讯 IM、消息服务实现及消息表。
- 不信任客户端提交的聊天正文、聊天对象或举报上下文；聊天解析器不可用时失败关闭。
- 所有可运营显示名、下拉项、举报原因、处罚周期和提示文案来自字典/配置接口；代码只固化稳定业务 code 与状态迁移规则。
- 不复制静态 Demo 的独立侧栏和顶栏；业务页从 Demo 的标题、统计区开始映射。
- 数据库只迁移开发库，执行前备份，执行后复跑验证幂等和数据守恒。
