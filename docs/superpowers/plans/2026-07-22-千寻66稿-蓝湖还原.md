# 千寻 66 稿蓝湖 1:1 还原实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use test-driven-development task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在微信小程序中把蓝湖千寻区域 66 张稿件映射为 11 个可运行页面组，并以分包、真实组件、截图差异和包体积门禁完成交付。

**Architecture:** 5 个 Tab 页面留在主包，新增社区内容页面统一放入 `pages/qianxun` 分包；消息、会员、千寻币继续复用已有分包。成家首页使用真实社区接口，自动化只通过开发环境 QA storage 固化难以人工触发的上传/失败状态，生产构建忽略该状态。

**Tech Stack:** Taro 4.1.9、React 18、TypeScript 5.6、微信小程序、自定义 TabBar、Node 静态门禁、miniprogram-automator。

## Global Constraints

- 蓝湖源为项目“时空邂逅0625”，固定 66 个 UUID，不依赖可变列表序号。
- 新增非 Tab 页面不得进入主包；主包构建目标小于 1.5MiB。
- 底部 Tab 图标以外的新增静态图标必须使用 `miniappOssIcons` OSS URL。
- 不使用整屏设计图、透明热区、`opacity: 0` 控件或自绘微信胶囊。
- 总体还原度 >=95%，关键首屏 >=97%。
- 保留用户已有 `docs/需求文档/B同学分工明细.md` 修改。
