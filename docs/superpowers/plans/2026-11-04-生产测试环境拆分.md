# 生产与测试环境拆分实施计划

**目标：** 将生产应用迁至 `47.117.142.161`，测试保留 `112.124.59.146`；生产数据库使用 `shikongxiehou_prod`，配置独立流水线和两个后台域名。

**架构：** 复用现有 Docker、ACR、RDS 和应用代码。MySQL 在现有 RDS 中复制独立生产库，通过校验证书的加密连接访问；生产 Redis 使用 Docker 私网独立实例、密码认证、AOF 与 RDB 持久化。敏感配置仅保存在服务器受限目录。

**技术栈：** Alibaba Cloud Linux、Docker、Nginx、MySQL 8、Redis、GitHub Actions。

**需求依据：** 2026-11-04 当前会话的服务器迁移、数据库 `_prod` 副本、生产流水线、后台 DNS 和生产免密登录要求。

## 约束与核验重点

- 只在 `master` 修改和推送，不提交密码、私钥、业务数据或本机私有配置。
- 原库保留；最终复制前停止旧后端写入，避免快照之后遗漏新增数据。
- 测试环境与生产环境分离数据库、缓存、容器和部署目录；测试不自动执行历史订单退款、商品同步及消息补偿任务。
- 仅修改 `admin`、`test-admin` 的业务解析；官网 `www` 和主域名现指向第三台服务器，本次不改其解析。
- 新服务器应用、证书、API 验证通过后切 DNS；旧地址保留到新生产的转发，兼容 DNS 缓存。
- 回退不能把已有生产新数据丢弃：切换后回退应用版本，继续使用生产库；恢复旧库须先核对迁移后的写入。
