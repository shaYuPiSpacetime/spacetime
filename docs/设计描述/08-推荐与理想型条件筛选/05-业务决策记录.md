# PRD-08 业务决策记录

> 日期：2026-08-05  
> 状态：已确认，可进入实施  
> 事实源：`PRD-08_用户确认口径.md`、`PRD-08_模块公共定义.md`、蓝湖 23 稿设计基线

## 1. 方案选择

| 方案 | 做法 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| 最小方案 | 直接复用通用资产解锁，客户端提交目标用户 ID 和价格 | 改动少 | 无快照归属校验、价格可被客户端影响、无法安全“解锁全部” | 不采用 |
| 平衡方案 | 新增偏好、快照、快照候选、浏览记录四表；复用现有用户资料、关系、商业化和资产流水；服务端报价确认 | 业务闭环、可审计、可回滚，新增面可控 | 需要完整接口和迁移 | 采用 |
| 完整算法方案 | 增加推荐模型、运营策略、异步召回、独立管理后台 | 可扩展 | 超出一期、与固定条件筛选口径冲突 | 本期不做 |

## 2. 已确认决策

### ADR-08-01：23 稿是视觉基线，不是业务事实源

- 设计的颜色、尺寸、层级、组件位置和状态关系用于 UI 验收。
- 认证筛选、固定价格、未解锁明文资料、失效记录明文资料等冲突按正式 PRD 修正。
- 每个业务状态必须由真实组件和接口数据生成，不把整页设计图作为背景。

### ADR-08-02：用户主页与主页预览共享

- 抽取一个无路由依赖的资料展示组件，输入统一 `ProfileDisplayModel`。
- 本人预览、推荐详情、理想型已解锁详情复用同一显隐函数、区块组件和视觉样式。
- 页面壳只负责顶部导航、来源场景和底部动作，不复制资料区。

### ADR-08-03：通信模式由服务端决定

| 状态 | `communicationMode` | 主按钮 |
|---|---|---|
| 无有效解锁 | `WHISPER` | 悄悄话 |
| 理想型解锁有效 | `PRIVATE_MESSAGE` | 私信 |
| 已匹配 | `PRIVATE_MESSAGE` | 私信 |
| 解锁过期/退款/失效 | 重新按有效关系计算 | 不信任客户端缓存 |

客户端只渲染服务端返回值；`canEnterConversation` 在兼容期由该枚举派生，后续删除布尔推断。

### ADR-08-04：批量折扣使用“优惠百分比”

- 配置键：`commercial.ideal.batch.discount.percent`。
- 接口字段：`idealBatchDiscountPercent`。
- 合法范围：0–100；默认 10。
- 应付金额：`ceil(originalCost × (100 - percent) / 100)`。
- 选择向上取整，避免产生小数千寻币及少收；分摊尾差加到最后一条有效记录。
- 帮助文案根据百分比动态展示“9折（优惠10%）”，0 表示无优惠，100 表示免费但仍写审计记录。
- `ideal_user_unlock.unitPrice` 是单个和批量报价的唯一单价来源；`ideal_batch_unlock` 仅作为批量流水场景标识，不维护第二套价格算法。

### ADR-08-05：“解锁全部”以快照为边界

- 对象集合为当前 `snapshotNo` 下实时有效、未解锁、可访问的全部候选。
- 服务端重新校验归属、快照有效期、候选状态、阻断关系、认证和既有解锁。
- 候选数大于 `idealBatchMax` 时拒绝报价，不静默截断；用户需缩小筛选条件。
- 报价有效期暂定 5 分钟；候选、价格、折扣或配置版本变化即失效。

### ADR-08-06：推荐与理想型复用基础偏好

- `targetCityCodes/minAge/maxAge` 只存一份。
- 推荐可在开关开启时扩展邻接城市；理想型执行时强制关闭扩展但不清除保存开关。
- 高级偏好保留但只有 `advanced_filter` 权益有效时参与查询。

### ADR-08-07：快照保存业务 ID，不向未解锁端暴露候选 ID

- 数据库保存 `candidate_user_id` 便于服务端联结，接口对未解锁项仅返回不可反查的 `itemNo`。
- `itemNo` 只在快照内有效，不能作为公开用户 ID 使用。
- 清晰主页只在有效解锁后返回公开资料入口。

## 4. PRD-07 推广裂变联动影响

- 推荐页只读取三项认证结果，不新增认证奖励事件；头像、实名与学历奖励仍由原审核通过事务触发。
- 理想型筛选、报价、扣币消费不触发“首次千寻币充值”奖励。
- 用户从余额不足页完成首次充值时，仍由支付成功事务触发 `first-coin:{orderNo}`；PRD-08 不重复发事件。
- 从会员引导完成首次会员支付时，仍由支付成功事务触发 `first-vip:{orderNo}`。
- 事件幂等继续使用 PRD-07 的事件键、奖励幂等键和数据库唯一键；本模块不得补发或伪造成功事件。

## 5. 暂不阻塞实施的缺口

- 蓝湖没有独立 `/pages/ideal/records/index` 视觉稿：先按历史列表 Token 实现业务闭环，不计入 23 稿还原分。
- 城市邻接、学校层级和标签稳定 code 不完整时，对应能力按 PRD 降级或禁用，不以自由文本猜测。
- 正式隐私政策更新属于上线门禁，不阻塞本地开发，但发布前必须完成。
- 当前小程序消息服务仍使用 Zustand Mock，仓库没有真实私信/悄悄话 Controller；主页可以先完成通信模式与入口切换，但在真实消息接口落地前不得宣称消息收发闭环。
