## 1. 背景与目标

本方案把已冻结的 PRD 转成可开发、可测试、可追踪的工程设计。实现范围包括管理后台前后端、移动端后端接口、Provider 抽象、状态机、权限审计、表设计和后续 95% 达标验收口径。

移动端不实现前端代码，只提供后端接口与对接文档。管理后台实现必须 1:1 还原已同步后的静态 Demo `admin.html`，覆盖页面、字段、按钮、弹窗、状态、异常态、控件形态、详情形式、分页统计、反馈提示和交互链路，并在后续测试报告中留证据。

## 4. 总体架构

| 层 | 设计 |
|----|------|
| 后端技术栈 | Java 21、Spring Boot 3.4、MyBatis-Plus、MySQL、Redis |
| 后端分层 | `Controller -> Service -> ServiceImpl -> DAO -> DAOImpl -> Mapper` |
| 后端模块边界 | `admin/` 和 `miniapp/` 不互相依赖，共享实体、枚举、DAO、Provider、状态机放 `common/` |
| 返回规范 | Controller 返回精确 `R<T>`，分页使用 MyBatis-Plus `Page<T>` |
| 管理后台权限 | Admin API 全部使用 `@RequirePermission`，敏感查看/导出/下载记录审计 |
| 管理后台前端 | React 18 + TypeScript + Vite + Tailwind，API 放 `frontend/src/api/`，页面放 `frontend/src/pages/`，路由放 `frontend/src/router/` |
| 移动端 | 仅实现后端接口；接口契约见独立 handoff 文档 |

现有代码、旧技术方案和旧测试用例只作为仓库现状盘点对象，不作为本需求的正确依据。后续实现必须按本轮冻结 PRD、本轮技术方案和重新生成的测试用例重写；旧版本中已有同名接口、页面、表或测试时，也必须逐项核查，不得默认复用。

### 5.3.3 字段定义与索引

表结构约定：
- 数据库引擎统一 `InnoDB`，字符集统一 `utf8mb4`。
- 业务表继承 `BaseEntity`：`id BIGINT AUTO_INCREMENT PRIMARY KEY`、`create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`、`update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`、`created_by BIGINT NULL`、`updated_by BIGINT NULL`、`deleted TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0=正常，1=已删除'`。
- 本需求未要求数据库字段加密存储：真实姓名、身份证号、手机号、实名时绑定手机号按业务明文字段入库；页面/API/导出按权限、脱敏、二次确认和审计控制展示。`*_hash` 字段仅用于查询、去重、导入校验，不替代原值存储。
- `audit_source` 按 PRD 只允许 `MACHINE`、`MANUAL`；本地开发或联调使用 mock Provider 时，业务审核来源仍按机审写 `MACHINE`，是否 mock 仅记录在 `external_provider_task.mocked`。
- 下列表格只列本需求新增/调整字段与新增业务表字段；已有字段未列出时按现有表结构保留。

## 5.4 状态机

| 状态 | 进入条件 | 退出条件 | 移动端展示 | 后台展示 |
|------|----------|----------|------------|----------|
| `NOT_CERTIFIED` | 用户未提交认证/审核材料 | 用户提交材料 | 未认证/去认证 | 未认证 |
| `NOT_SUBMITTED` | 图片/文字未提交 | 用户提交图片/文字 | 未提交 | 未提交 |
| `PENDING` | 用户提交且需人工审核，或机审需复核 | 审核通过/驳回 | 审核中 | 待审核、待人工复核 |
| `APPROVED` | 机审通过或人工通过 | 用户重新修改对应内容 | 已通过 | 审核通过-机审/人工审核 |
| `REJECTED` | 机审驳回或人工驳回 | 用户重新提交 | 已驳回，展示原因 | 审核驳回-机审/人工审核 |
| `VOICE_PENDING` | 用户提交 10-60 秒语音介绍且音频安全检测未完成 | 音频机审通过/驳回 | 本人侧显示处理中；对外隐藏新语音，已有旧通过语音继续展示 | 后台详情仅展示状态和机审信号，不提供人工审核按钮 |
| `VOICE_APPROVED` | 微信音频内容安全机审通过 | 用户删除或重新提交 | 对外展示 `voiceIntroUrl` 与 `voiceIntroDuration` | 后台详情展示已通过和 Provider 留痕 |
| `VOICE_REJECTED` | 微信音频内容安全机审失败 | 用户重新录制/上传 | 对外隐藏；本人侧展示失败原因并提示重录 | 后台详情展示驳回原因和 Provider 留痕 |
| `EXPIRED` | 学历/实名材料超期或规则变更 | 用户重新提交 | 已失效，重新认证 | 已失效 |
| `CORE_BLOCKED` | 三重认证未全部通过、账号冻结、资料未达标 | 全部条件满足 | 核心功能拦截页 | 核心准入未开放 |
| `CORE_ALLOWED` | 账号正常 + 三重认证通过 + 配置规则通过 | 状态变化或冻结 | 核心能力可用 | 核心准入已开放 |

状态流转规则：
- 实名通过后才允许学历认证进入有效审核；未实名时提交学历返回 `EDUCATION_REALNAME_REQUIRED`。
- 头像/实名/学历三项全部 `APPROVED` 且账号 `NORMAL`，核心能力才可开放。
- “稍后再说”只允许进入白名单/非核心能力，不更新 `CORE_ALLOWED`。
- 修改头像、资料图片、开放性文字后，对应审核记录重置为 `PENDING` 或 `NOT_SUBMITTED`，不影响其他认证项。
- 命中海外/国家/港澳台地址时返回 `REGION_NOT_SUPPORTED`，不写入用户资料。

## 5.5 Provider 抽象

| Provider | 接口 | 默认实现 | 降级 |
|----------|------|----------|------|
| 实名三要素 | `RealNameVerifyProvider.verify(realName, idCard, phone)` | `MockRealNameVerifyProvider` 返回成功并记录 `mocked=1` | 失败进入人工审核 |
| 学历核验 | `EducationVerifyProvider.verify(req)` | `MockEducationVerifyProvider` 返回 `PENDING_MANUAL` | 人工审核兜底 |
| 图片安全/人像 | `MediaSafetyProvider.check(mediaUrl, mediaType)` | `MockMediaSafetyProvider` 返回安全 | 不确定进入人工复核 |
| 语音安全 | `AudioSafetyProvider.check(voiceUrl, duration)` | `MockAudioSafetyProvider` 返回安全并记录 `mocked=1` | Provider 不可用时保持 `VOICE_PENDING`，不对外展示新语音；机审失败直接 `VOICE_REJECTED` |
| 文本安全 | `TextSafetyProvider.check(content)` | `MockTextSafetyProvider` 返回安全 | 不确定进入人工复核 |
| 短信 | `SmsProvider.verify(phone, code)` | 开发环境 mock 成功 | 生产未配置则拒绝登录 |
| 定位/地区 | `LocationProvider.resolve(code)` | 本地中国大陆行政区字典 | 非中国大陆返回不支持 |

Provider 调用都写入 `external_provider_task`，用于后台详情展示机审信号和后续测试证据。`mocked=1` 只表示本次 Provider 调用由 mock 实现返回，业务审核来源不记录 mock 值；mock 成功的机审结论仍按 `audit_source=MACHINE` 写入业务审核记录。

### 5.6 语音介绍存储与展示流程

语音介绍是音频本体链路，不等同于开放性文字审核。首版没有单独的后台人工语音审核页面，不做语音转文字，也不允许用“语音转写文字审核通过”替代音频安全通过。

| 步骤 | 后端处理 | 数据落点 | 对外展示规则 |
|------|----------|----------|--------------|
| 1. 上传音频 | 移动端先完成文件上传并拿到 `voiceUrl`，再调用 `/miniapp/profile/voice-intro` | 文件服务/对象存储保存音频文件 | 未提交前不展示 |
| 2. 提交语音介绍 | 校验 `duration` 必须为 10-60 秒，校验 `voiceUrl` 非空 | 新增 `app_user_voice_intro_record`，状态 `VOICE_PENDING` | 本人侧显示处理中；对外不展示新语音 |
| 3. 触发机审 | 调用 `AudioSafetyProvider.check(voiceUrl, duration)`，生产对接微信音频内容安全，开发默认 mock 成功 | `external_provider_task` 记录请求/响应/是否 mock；结果回写语音记录 | Provider 未完成时继续 pending |
| 4. 机审通过 | 将当前记录置为 `VOICE_APPROVED/current_effective=1`，同用户旧有效语音置为 `current_effective=0` | 同步更新 `app_user.voice_intro_url`、`voice_intro_duration`、`voice_intro_audit_status`、`voice_intro_record_id` | 对外展示语音 URL 与时长 |
| 5. 机审失败 | 将当前记录置为 `VOICE_REJECTED` 并保存 `reject_reason/machine_signal_json` | 不覆盖旧的已通过语音；无旧语音时 `app_user.voice_intro_*` 为空或 rejected 快照 | 对外隐藏；本人侧提示失败原因并引导重录 |
| 6. 删除语音 | `/miniapp/profile/voice-intro` DELETE 清空当前有效记录 | 当前记录 `current_effective=0`，`app_user.voice_intro_*` 清空 | 对外不展示 |
| 7. 转文字边界 | 本期不接入语音转文字，不生成或展示语音转写文本 | 无本期落库字段；如后续新增需另行确认 `SpeechToTextProvider` 和表字段 | 不展示语音文字，只展示播放器和时长 |

实现约束：
- 语音介绍不进入资料图片审核列表，不进入开放性文字人工审核动作链路，不新增后台人工语音审核页面。
- 语音介绍本期只做播放和音频安全机审，不做语音转文字、不展示转写文本、不把语音转写放入开放性文字审核。
- 新提交语音在通过前不能替换旧的已通过语音，避免用户资料出现空窗或未审内容曝光。
- Provider 不可用、超时或返回不确定时保持 `VOICE_PENDING`，后续由定时任务重试；超过配置时长仍未完成则本人侧提示处理中，不对外展示。
- 移动端详情接口必须同时返回 `voiceIntroUrl`、`voiceIntroDuration`、`voiceIntroAuditStatus`、`voiceIntroRejectReason`，前端据此展示通过、处理中、失败重录状态。
