## 1. 背景与目标

本方案把已冻结的 PRD 转成可开发、可测试、可追踪的工程设计。实现范围包括管理后台前后端、移动端后端接口、Provider 抽象、状态机、权限审计、表设计和后续 95% 达标验收口径。

## 5.3 数据库与表设计

以下表设计为本轮重新设计的统一待确认项，确认后再进入测试和实现。设计原则：不按每个审核类型各建一张表，而是按“审核记录、审核历史”承载业务闭环，Provider 调用作为支撑留痕；每个用户、每种审核类型允许多条记录；默认无记录，不生成“未提交”审核记录。

### 5.3.1 复用、改造与依赖表

| 表 | 处理 | 字段/索引 | 审计/逻辑删除 | 说明 |
|----|------|-----------|---------------|------|
| `app_user` | 复用并清理 | 删除 `avatar、photos、profile_bg_image、about_me、hope_they_know`；不保存审核状态、审核记录 ID、当前有效内容等快照 | 继承 `BaseEntity` | 仅承载账号和基础资料；审核内容、三重认证、核心准入、资料可见性均从 `app_user_audit_record` 实时派生 |
| `app_config` | 复用 | 使用 `config_group=PRD01_ACCESS`、`PRD01_PROFILE_FIELD`、`PRD01_UPLOAD`、`PRD01_AUDIT` | 继承 `BaseEntity` | 配置项继续用已有通用配置能力 |
| `content_operation_log` | 复用 | `bizType=PRD01_*`，记录配置变更、审核、敏感查看、导入导出 | 继承 `BaseEntity` | 不额外造通用操作日志表 |
| `external_provider_task` | 复用/缺失补建 | Provider 类型、业务记录 ID、请求/响应快照、调用状态、是否 mock、调用时间 | 继承 `BaseEntity` | 外部 Provider 调用留痕，不属于审核业务主表；若现有库无同等表再补建 |

| 表 | 关键字段 | 索引 | 审计/逻辑删除 | 说明 |
|----|----------|------|---------------|------|
| `app_user_audit_record` | `user_id`、`audit_group`、`audit_type`、`status`、`audit_source`、`provider_task_id`、材料/文本/语音/实名字段、`reject_reason`、`expired_reason`、`submit_time`、`audit_time`、`auditor_id` | `idx_audit_user_type_time(user_id, audit_type, submit_time)`、`idx_audit_type_status(audit_type, status, deleted)`、`idx_audit_source_status(audit_source, status, deleted)` | 继承 `BaseEntity` | 统一承载实名、头像、学历、相册、背景图、开放文字、语音介绍审核记录；后台审核列表从这里取 |

### 5.3.3 字段定义与索引

表结构约定：
- 数据库引擎统一 `InnoDB`，字符集统一 `utf8mb4`。
- 业务表继承 `BaseEntity`：`id BIGINT AUTO_INCREMENT PRIMARY KEY`、`create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`、`update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`、`created_by BIGINT NULL`、`updated_by BIGINT NULL`、`deleted TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0=正常，1=已删除'`。
- 本需求未要求数据库字段加密存储：真实姓名、身份证号、手机号、实名时绑定手机号按业务明文字段入库；页面/API/导出按权限、脱敏、二次确认和审计控制展示。`*_hash` 字段仅用于查询、去重、导入校验，不替代原值存储。
- `audit_source` 按 PRD 只允许 `MACHINE（机审）`、`MANUAL（人工审核）`；本地开发或联调使用 mock Provider 时，业务审核来源仍按机审写 `MACHINE（机审）`，是否 mock 仅记录在 `external_provider_task.mocked`。
- 下列表格只列本需求新增/调整字段与新增业务表字段；已有字段未列出时按现有表结构保留。

枚举值中文对照：

| 字段/枚举 | 英文值 | 中文含义 |
|----------|--------|----------|
| `audit_group` | `CERTIFICATION`、`MEDIA`、`TEXT`、`VOICE` | 认证审核、媒体/图片审核、开放文字审核、语音介绍审核 |
| `audit_type` | `REAL_NAME`、`AVATAR`、`EDUCATION`、`ALBUM_PHOTO`、`PROFILE_BG`、`ABOUT_ME`、`HOPE_THEY_KNOW`、`PROFILE_QA`、`VOICE_INTRO` | 实名认证、头像认证、学历认证、相册照片、资料背景图、关于我、希望 TA 了解、资料问答开放回答、语音介绍 |
| `status` / `to_status` / `from_status` | `PENDING`、`REVIEWING`、`APPROVED`、`REJECTED`、`EXPIRED` | 待审核、审核中、已通过、已驳回、已失效 |
| `audit_source` | `MACHINE`、`MANUAL` | 机审、人工审核 |
| `mocked` / `deleted` | `0`、`1` | 否、是；逻辑删除字段中 `0=正常`、`1=已删除` |
| 核心准入接口派生值 | `CORE_BLOCKED`、`CORE_ALLOWED`、`NON_CORE_ONLY` | 核心准入未开放、核心准入已开放、仅非核心能力可用；不落认证快照表 |
| `app_user_audit_history.action` | `SUBMIT`、`MACHINE_START`、`MACHINE_PASS`、`MACHINE_REJECT`、`MANUAL_APPROVE`、`MANUAL_REJECT`、`MANUAL_EXPIRE`、`SYSTEM_EXPIRE` | 提交、机审开始、机审通过、机审驳回、人工通过、人工驳回、人工失效、系统失效 |
| `operator_type` | `USER`、`ADMIN`、`SYSTEM`、`PROVIDER` | 用户、管理员、系统、第三方 Provider |
| Provider 调用 `status` | `PENDING`、`SUCCESS`、`FAILED`、`TIMEOUT` | 待调用/待回调、成功、失败、超时 |

#### app_user 使用约束

`app_user` 不保存头像、相册、资料背景图、关于我、希望 TA 了解，也不增加审核状态、审核记录 ID、当前有效资料 URL、核心准入快照等冗余字段。账号状态、手机号、昵称、性别、现居地、学校、专业、学历等基础资料沿用主表；审核结果不回写 `app_user`。

三重认证状态、核心准入、资料背景图、语音介绍、相册照片、开放性文字展示均从 `app_user_audit_record` 实时查询派生：
- 本人侧状态：按 `user_id + audit_type` 查最新提交记录。
- 头像对外/业务：只看最新头像记录是否 `APPROVED（已通过）`。
- 其他认证/内容对外/业务：按 `audit_type + status=APPROVED + submit_time/id` 查询最近已通过记录；相册按多条已通过记录展示。
- 无记录：接口派生未认证/未提交/不展示，不写库。

## 5.4 状态机

| 状态 | 进入条件 | 退出条件 | 移动端展示 | 后台展示 |
|------|----------|----------|------------|----------|
| 无记录 | 用户从未提交该审核类型 | 用户提交材料/内容/语音 | 认证类展示未认证/去认证；内容类不展示 | 列表无记录 |
| `PENDING` | 用户提交后等待机审或人工审核 | 进入机审/人工处理中，或直接通过/驳回/失效 | 本人侧统一展示审核中 | 列表待审核；行操作仅详情 |
| `REVIEWING` | 机审、第三方或人工审核处理中 | 通过/驳回/失效 | 本人侧统一展示审核中 | 列表审核中；行操作仅详情 |
| `APPROVED` | 机审通过或人工通过 | 用户重新提交、后台失效 | 已通过；对外按生效规则展示 | 列表已通过；详情可通过/驳回/失效 |
| `REJECTED` | 机审驳回或人工驳回 | 用户重新提交 | 已驳回，展示原因 | 列表已驳回；详情可通过/驳回/失效 |
| `EXPIRED` | 后台人工或系统规则标记失效 | 用户重新提交 | 已失效，展示原因 | 列表已失效；详情可通过/驳回/失效 |
| `CORE_BLOCKED` | 三重认证未全部通过、账号冻结、资料未达标 | 全部条件满足 | 核心功能拦截页 | 核心准入未开放 |
| `CORE_ALLOWED` | 账号正常 + 三重认证通过 + 配置规则通过 | 状态变化或冻结 | 核心能力可用 | 核心准入已开放 |

状态流转规则：
- 实名通过后才允许学历认证进入有效审核；未实名时提交学历返回 `EDUCATION_REALNAME_REQUIRED`。
- 头像看最新头像记录，实名/学历按业务生效记录判断；三项均通过且账号 `NORMAL`，核心能力才可开放。
- “稍后再说”只允许进入白名单/非核心能力，不更新 `CORE_ALLOWED`。
- 修改头像、资料图片、开放性文字、语音介绍后新增审核记录，不回写旧记录状态；相册按单张生效，背景图/文字/语音按最近有效记录生效。
- 后台审核列表只展示审核记录；列表行操作仅详情，详情内统一通过、驳回、失效。
- 命中海外/国家/港澳台地址时返回 `REGION_NOT_SUPPORTED`，不写入用户资料。

| 文本安全 | `TextSafetyProvider.check(content)` | `MockTextSafetyProvider` 返回安全 | 不确定时记录为 `REVIEWING` 或转人工来源处理 |
| 短信 | `SmsProvider.verify(phone, code)` | 开发环境 mock 成功 | 生产未配置则拒绝登录 |
| 定位/地区 | `LocationProvider.resolve(code)` | 本地中国大陆行政区字典 | 非中国大陆返回不支持 |

Provider 调用都写入 `external_provider_task`，用于后台详情展示机审信号和后续测试证据。`mocked=1` 只表示本次 Provider 调用由 mock 实现返回，业务审核来源不记录 mock 值；mock 成功的机审结论仍按 `audit_source=MACHINE` 写入业务审核记录。

### 5.6 语音介绍存储与展示流程

语音介绍是音频本体链路，不等同于开放性文字审核。首版没有单独的后台人工语音审核页面，不做语音转文字，也不允许用“语音转写文字审核通过”替代音频安全通过。语音介绍不单独建 `app_user_voice_intro_record`，统一写入 `app_user_audit_record(audit_type=VOICE_INTRO)`。

| 步骤 | 后端处理 | 数据落点 | 对外展示规则 |
|------|----------|----------|--------------|
| 1. 上传音频 | 移动端先完成文件上传并拿到 `voiceUrl`，再调用 `/miniapp/profile/voice-intro` | 文件服务/对象存储保存音频文件 | 未提交前不展示 |
| 2. 提交语音介绍 | 校验 `duration` 必须为 10-60 秒，校验 `voiceUrl` 非空 | 新增 `app_user_audit_record`：`audit_group=VOICE`、`audit_type=VOICE_INTRO`、`status=PENDING/REVIEWING`、`media_url=voiceUrl`、`duration` | 本人侧显示审核中；对外不展示新语音 |
| 3. 触发机审 | 调用 `AudioSafetyProvider.check(voiceUrl, duration)`，生产对接微信音频内容安全，开发默认 mock 成功 | `external_provider_task` 记录请求/响应/是否 mock；结果回写统一审核记录和审核历史 | Provider 未完成时继续 `REVIEWING` |
| 4. 机审通过 | 将当前记录置为 `APPROVED`，不回写旧记录 | 不回写 `app_user`；移动端资料接口按 `VOICE_INTRO + APPROVED + submit_time/id` 查最近可播放语音 | 对外展示语音 URL 与时长 |
| 5. 机审失败 | 将当前记录置为 `REJECTED` 并保存 `reject_reason/machine_signal_json` | 不覆盖旧的已通过语音；无旧有效语音时查询结果为空 | 对外隐藏；本人侧提示失败原因并引导重录 |
| 6. 删除语音 | `/miniapp/profile/voice-intro` DELETE 将最近已通过语音置为 `EXPIRED` | 写审核历史或资料操作审计；不保存额外生效标记 | 对外不展示该条语音 |
| 7. 转文字边界 | 本期不接入语音转文字，不生成或展示语音转写文本 | 无本期落库字段；如后续新增需另行确认 `SpeechToTextProvider` 和表字段 | 不展示语音文字，只展示播放器和时长 |

实现约束：
- 语音介绍不进入资料图片审核列表，不进入开放性文字人工审核动作链路，不新增后台人工语音审核页面。
- 语音介绍本期只做播放和音频安全机审，不做语音转文字、不展示转写文本、不把语音转写放入开放性文字审核。
- 新提交语音在通过前不能替换旧的已通过语音，避免用户资料出现空窗或未审内容曝光。
- Provider 不可用、超时或返回不确定时保持 `REVIEWING`，后续由定时任务重试；超过配置时长仍未完成则本人侧提示审核中，不对外展示。
- 移动端详情接口必须同时返回 `voiceIntroUrl`、`voiceIntroDuration`、`voiceIntroAuditStatus`、`voiceIntroRejectReason`，前端据此展示审核中、已通过、已驳回、已失效和重录入口。
