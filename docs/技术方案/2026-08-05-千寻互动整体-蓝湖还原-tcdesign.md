## 1. 目标与范围

本次恢复千寻互动主页面及其关联动态卡的视觉和数据闭环，重点解决浏览记录间距、日期、性别图标、评论图标、点赞图标及真实接口消费问题。

页面范围：

- 千寻互动：评论过、点赞过、解锁过。
- 浏览记录。
- 互动内“我的动态”和独立“我的动态”。
- 动态详情、话题动态卡、知音诚意贴中的同类性别/评论/点赞图标。

不改变社区后端表结构，不新增本地 Storage 业务事实，不修改已有登录和资料认证流程。

## 3. 真实接口映射

| UI | 接口 | 必须消费的字段 |
|---|---|---|
| 个人资料与统计 | `GET /miniapp/community/me/profile-summary` | `stats.postCount/followingCount/followerCount/receivedLikeCount` |
| 评论过 | `GET /miniapp/community/me/interactions?type=commented` | `interactionTime`、`post` |
| 点赞过 | `GET /miniapp/community/me/interactions?type=liked` | `interactionTime`、`post` |
| 解锁过 | `GET /miniapp/community/me/interactions?type=unlocked` | `targetUserId/nickname/avatar/description` |
| 浏览记录 | `GET /miniapp/community/me/interactions?type=viewed` | 浏览时间 `interactionTime`、动态 `post` |
| 清空浏览记录 | `DELETE /miniapp/community/me/view-history` | 成功后清空页面状态 |
| 我的动态 | `GET /miniapp/community/me/posts` | `content/images/status/createTime/commentCount/likeCount` |

浏览记录不再用 `GET /miniapp/community/me/view-history` 直接渲染，因为该返回值只包含动态卡，不能表达真实浏览时间。后端现有 `type=viewed` 已从浏览记录表读取 `viewedAt` 并返回 `interactionTime`，无需新增接口。

## 4. 数据与组件设计

### 4.1 展示模型

互动记录保留服务端 `interactionTime` 与 `post`，按本地自然日分组：

- 分组标题：`YYYY年MM月DD日`。
- 动态卡日期：`MM-DD`，取动态 `createTime`。
- 服务端时间为空时归入“日期未知”，但不伪造当天日期。

评论过和点赞过渲染完整动态卡；解锁过仍渲染用户关系行。

### 4.2 共享图标组件

新增 `QianxunCommunityIcons.tsx`：

- 性别图标：`qianxunGenderFemale` / `qianxunGenderMale`；未知性别不显示。
- 评论图标：`qianxunComment`。
- 点赞图标：未点赞 `qianxunLike`，已点赞或累计获赞 `qianxunLikeActive`。
- 图标使用真实 `Image`，数字独立布局；不使用 `◯`、`♡`、`♥`、`♀`、`♂` 或 CSS 近似图标。

### 4.3 共享发布状态标签

新增 `QianxunPostStatusBadge`，供互动内“我的动态”和独立“我的动态”共用：

- `pending_manual` 在前端固定展示“审核中”，优先覆盖服务端可能返回的旧 `statusName`。
- `rejected` 在前端固定展示“发布失败”，优先覆盖服务端可能返回的“已驳回”。
- 两种状态均按蓝湖主画板使用 88rpx × 48rpx；待审态为 6rpx 圆角、`#F8F9FB` 底色，失败态为 8rpx 圆角、`#EF0000` 底色，文字均为 20rpx。
- 状态标签位于 130rpx 日期列，并固定在 48rpx 日期行下方 20rpx；正文行数变化不再改变标签位置。
- 正文、图片、话题与互动统计位于右侧内容列，三个点放在操作行首位，与正文左边缘对齐，不再用前置弹性占位推向右侧。

### 4.4 发布失败弹窗

新增 `QianxunPublishFailureDialog`，供互动内“我的动态”和独立“我的动态”共用：

- 点击可见的“发布失败”标签时阻止卡片事件冒泡，并展示失败原因弹窗。
- 弹窗消费 `auditRemark || statusMessage`，缺失时使用配置中心的 `publish_rejected_default`，不伪造审核原因。
- 列表不再渲染大段红色失败原因；原因只在用户主动点击后展示。
- 弹窗遮罩、620rpx × 538rpx 容器、书本失败插画和 520rpx × 68rpx 确认按钮均按蓝湖失败态画板实现。

## 5. 交互与可用性

- 三个主面板保持挂载，通过 `visibility` 切换，避免 Tab 切换丢状态。
- 浏览记录更多按钮绑定真实 ActionSheet，选择“清空浏览记录”后再次确认。
- 动态卡点击进入真实动态详情。
- 评论/点赞图标在只读列表中不制造虚假按钮；在详情页真实动作外层保留至少 88rpx 点击区域。
- 图片缺失时整个图片区不渲染，不显示空框。

## 6. 设计缺口与边界

- 蓝湖日期使用文本，没有日期图标，因此不新增日历近似资源。
- 当前 OSS 已有 64×64 原始性别、评论、点赞图标，按 32rpx 运行满足 2× 像素密度。
- 发布失败书本插画已从蓝湖 MCP 原始预览按 360×252 无损 PNG 落盘并上传 OSS，运行时按 180rpx × 126rpx 显示。
- 获赞大插画没有可安全放大的 2× 独立素材；本次只统一累计获赞的已有布局与小图标，不把 64×64 小图强行放大为主插画。
- 若真实账号某个状态无数据，运行截图以蓝湖空态验收；数据状态由静态模型测试和其他真实有数据状态共同覆盖。
