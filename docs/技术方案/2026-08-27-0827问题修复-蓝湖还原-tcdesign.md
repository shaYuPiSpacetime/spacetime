# 2026-08-27 小程序 08.27 问题修复技术方案

## 1. 范围

- 问题来源：`08.27 bug.docx` 中的 7 项小程序问题。
- 页面范围：发布动态、千寻同城/热门动态、动态详情、编辑资料与主页预览、基本资料认证、我的页面。
- 后端范围：悄悄话发送前置校验、生产环境动态图片上限配置。
- 设计基线：蓝湖“发布动态”画板 41（`aa76bc38-aeb9-486a-a455-6168b6674464`）及“上传照片（最多9张）”画板 46（`23747d78-e5e1-4530-8edc-c7218676c86e`）。

## 2. 根因与修复

| 问题 | 根因 | 修复 |
|---|---|---|
| 只能连续选择 1 张图片 | 系统选图互斥锁覆盖了整个异步上传过程；线上配置还可能被误设为 1 | 系统选择器返回后立即释放互斥锁，图片后台最多 3 路并发上传；客户端收敛为最多 9 张；生产迁移恢复配置为 9 |
| 自己的动态仍显示关注/悄悄话 | 动态卡片未比较当前登录用户与作者 | 同城/热门列表和详情页识别本人动态，隐藏关注、申请认识和悄悄话入口 |
| 悄悄话跳独立页并提示接收方准入未开放 | 社区入口跳转旧编写页；后端把发送方三重认证规则错误地对称应用到接收方 | 社区页内直接展示扣费/免费权益弹窗并完成预检查、发送；接收方只校验账号正常，三重认证只约束发送方 |
| “关于我”未显示 | 主页预览可见内容模型没有透传 `aboutMe` | 统一清洗标题和内容，新增“关于我”预览卡片 |
| 编辑资料导航随内容滚动 | 顶部导航放在 `ScrollView` 内 | 导航移出滚动容器，编辑态和预览态只滚动内容区 |
| 在校生仍显示行业和公司 | 身份显隐只过滤职业、年收入 | 非职场人统一隐藏并清空行业、职业、公司、年收入 |
| 点击“三重认证”无弹窗 | 认证徽章仅展示，无独立点击事件 | 增加可见认证详情弹窗，展示头像、实名、学历三项状态并支持关闭 |

## 3. 蓝湖图标还原

蓝湖 MCP 返回了 1500×3248 的完整“发布动态”设计图，但该画板 `totalSlices=0`，没有可直接下载的切图。按流程登记素材缺口后，从原始 PNG 像素坐标无损裁切工具栏图标：

| 图标 | 原图坐标 | 运行尺寸 | 资源键 |
|---|---|---|---|
| 照片 | `x=50,y=3110,w=96,h=80` | 48×40rpx | `qianxunComposePhoto` |
| 视频 | `x=206,y=3110,w=96,h=80` | 48×40rpx | `qianxunComposeVideo` |
| 表情 | `x=362,y=3110,w=80,h=80` | 40×40rpx | `qianxunComposeSmile` |

源文件保存在 `miniapp/src/assets/qianxun/compose-toolbar/`，通过项目既有无损上传脚本上传 OSS，运行态仅引用 `miniapp/src/constants/ossIcons.ts`，没有使用截图热区或字符图标冒充交互控件。

## 4. 悄悄话链路

```text
点击他人动态的悄悄话
  -> 当前页打开弹窗
  -> precheck（发送方认证 + 接收方账号正常 + 计费报价）
  -> 展示免费权益或千寻币金额
  -> 输入正文并携带报价令牌、幂等键发送
  -> 成功提示并关闭弹窗
```

接收方被冻结、注销或不存在时仍拒绝发送；只取消了错误的“接收方也必须完成发送方关系准入”条件。
