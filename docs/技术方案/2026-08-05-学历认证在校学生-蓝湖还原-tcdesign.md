# 学历认证在校学生蓝湖还原与异常修复技术说明

## 1. 范围与基线

- 设计基线：`docs/需求文档/需求文档-正式版/定稿：01-用户准入与资料认证初始化/移动端/ui图/三重认证-学历认证在校学生.png`、`三重认证-学历认证在校学生(1).png`、`三重认证-学历认证在校学生-信息填写即资料上传.png`。
- 页面基线：750×1678；资料卡起点 500rpx，高度 725rpx；提交按钮 1258rpx；协议 1382rpx；客服位于协议下方。
- 同轮修复：管理后台评论列表请求异常、心动页匹配弹层覆盖底部 Tab。

## 2. 根因

1. 学历提交按钮使用 `fixed + safe-area`，脱离蓝湖内容坐标并覆盖协议/客服区；学生空材料态误用 148rpx 小上传格，资料卡缺少设计稿的纵向留白和背景分割。
2. 评论列表在没有任何父评论时使用 `Map.of()`，再执行 `get(null)`，触发请求 ID `3738c2f0004d4dacb081df92fbfc9a03` 对应的 `NullPointerException`。
3. 匹配弹层层级 21000，高于底部 Tab 的 9999；全屏遮罩直接吞掉 Tab 点击，回执等待期间表现为卡死在心动页。

## 3. 实现约束

- 学历页保留真实输入、上传、协议和提交组件，不使用设计截图或透明热区。
- 学生空材料态使用 640×306rpx 上传区；有材料态使用 148×148rpx 缩略图网格。
- 学历提交按钮改为页面内绝对定位，并按“资料卡 → 提交 → 协议 → 客服”顺序渲染。
- 评论关联数据统一通过空 key 安全读取；缺少父评论、回复用户或动态时返回空关联，不中断整页。
- 关系业务弹层保持回执成功后再关闭，但层级降至 9000；底部 Tab 始终处于 9999，用户可随时退出当前页。

## 4. 验收门禁

- 后端：一级评论且 `parentCommentId=null` 的列表回归；全量 Maven 测试。
- 小程序：学历关键坐标、背景高度、上传态、DOM 顺序静态门禁；关系弹层与 Tab 层级门禁；正式构建。
- 微信运行态：匹配弹层存在时点击“我的”必须完成 `switchTab`；学历页按设备宽度换算核对资料卡、按钮、协议和客服坐标，并监听运行异常。
