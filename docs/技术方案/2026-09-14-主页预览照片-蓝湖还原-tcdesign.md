# 主页预览照片顺序修复

## 设计基线与范围

- 来源：本任务用户提供的 `codex-clipboard-a5b61d5e-8f62-41ae-85b0-b8c04a54f32d.png`；后台截图显示6张相册照片。
- 目标：`ProfilePreviewPage` 的照片排列；沿用本人预览与公开主页的共享组件。不是整页重新还原。
- 可确认的设计顺序：标签、自我介绍、第一张相册、我的认证、第二张相册。截图后半部分不完整，不推测其他设计尺寸。
- 复用现有颜色、字体、700rpx卡宽、20rpx间距、32rpx圆角及图片组件；没有新增图标或交互控件。

## 代码与数据核对

`GET /miniapp/profile/albums` 返回本人未失效的相册记录；编辑资料按 sortOrder 映射6个槽位，把有效 URL 传给共享预览组件。显隐层只移除空白 URL，没有截断6张照片。实际线上响应和图片网络状态未取得，不宣称已复现线上完全缺图。

当前实现把关于我插在自我介绍与第一张照片之间，长内容会推迟照片出现。将关于我移动到全部照片之后，保留原有第一/第二张照片与认证、歌曲的穿插，以及剩余照片遍历。

## 验证与限制

先用实际组件和相册映射函数构造6张图片、长关于我的回归，确认旧代码顺序断言失败，再调整模块顺序。用 Playwright 渲染实际内容组件的 HTML 适配结果，记录375×812局部截图；这是结构验证，不是微信真机、完整页面或生产接口验收。
