# 基础准入后五 Tab 未认证状态蓝湖还原技术方案

## 1. 范围与状态定义

- 端：微信小程序，默认设计视口 375×812。
- 用户前置条件：已登录，且性别、年龄、身份、学历、地址等基础准入资料已完成。
- 服务端状态：沿用 `AccessStatus.coreAccessStatus=NON_CORE_ONLY`，不新增平行状态。
- 页面范围：千寻、心动、推荐/理想型、消息、我的，以及能触发关注/私信的公开主页、话题列表和动态详情。
- 认证完成态：`CORE_ALLOWED`；基础资料未完成态：`CORE_BLOCKED`，维持原流程。

## 4. 组件与实现约束

- 共享弹窗：`miniapp/src/components/UnverifiedCertificationModal.tsx`，遮罩、底部渐变面板、插画、标题、说明和可见“立即认证”按钮均为真实组件。
- 共享认证路由：`navigateToPendingVerification()` 并发获取基础资料、认证、自我介绍状态，再由 `resolveVerificationOnboardingRoute` 计算下一步骤。
- 前端只依据服务端 `coreAccessStatus` 判定，不从资料字段自行推断认证通过。
- 推荐异性过滤继续由 `RecommendServiceImpl` 依据当前用户性别选择相反性别，前端不复制筛选规则。
- 未认证消息页不初始化 IM 会话运行时，不请求核心消息列表；官方小助手和系统消息保留可见。
- 所有认证按钮与点击区域一致，禁止透明热区；非底部静态图标继续使用 OSS 常量。

## 5. 验证方案

- 专项静态门禁：`npm run validate:unverified-menu-states`。
- 相关回归：登录未认证、PRD-08 推荐、消息、千寻社区、关系反馈。
- 代码质量：变更文件 ESLint。
- 编译：Taro 微信小程序构建；若本机系统配置库阻塞编译，登记环境问题且不得以旧 `dist` 作为新产物。
