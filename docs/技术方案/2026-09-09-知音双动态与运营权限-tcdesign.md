# 知音双动态与运营权限技术方案

## 1. 设计基线

- 视觉基线：现有“时空站台”动态卡片，包括作者头像与资料、关注、正文、图片、话题、评论、申请认识、点赞和更多操作。
- 统一要求：“心灵搭子”和“时空站台”必须渲染同一列表组件与同一卡片组件；不得复制两份相似 JSX。
- 合法差异：Tab 名称、请求数据源、空态文案，以及受权限控制的发布入口。
- 当前差异：心灵搭子仍是双列用户照片墙；时空站台是动态卡片列表，两者数据结构、交互和布局均不一致。

## 2. 业务口径

| 场景 | 内容来源 | 谁能发布 | 展示范围 |
|---|---|---|---|
| 心灵搭子 | `community_post` 普通动态 | 平台小程序用户沿用现有普通动态发布链路 | 仅后台配置手机号对应作者的已发布动态 |
| 时空站台 | `sincere_post` | 手机号同时属于启用后台工作人员账号的小程序用户 | 全部已发布时空站台内容 |

工作人员以 `sys_user.status=ENABLED` 且手机号与当前 `app_user.phone` 精确一致判定。后端是权限真源，小程序只消费 `stationPublishAllowed` 布尔值。

## 3. 配置与隐私

- 配置键：`community.soulmate_source_phones`。
- 存储：`app_config`，`config_group=COMMUNITY_PRIVATE`，`config_type=JSON`，`public_visible=0`。
- 校验：JSON 数组或后台逐行输入；去首尾空白、去重；每项满足 `^1[3-9]\\d{9}$`；最多 50 项。
- 查询：服务端将配置手机号计算 SHA-256，再用 `app_user.phone_hash` 索引定位作者；查询参数、响应与日志均不输出明文手机号。
- 小程序 Meta 只返回 `capabilities.stationPublishAllowed`，不得返回私有配置组。

## 4. 接口

- 新增 `GET /miniapp/community/soulmate-posts?page=1&size=20`：返回 `Page<CommunityPostCardVO>`。
- 保留 `GET /miniapp/community/posts?postType=sincere_post`：时空站台数据源。
- `POST /miniapp/community/posts`：当 `contentType=sincere_post` 时增加工作人员校验，未通过返回明确业务错误。
- `GET /miniapp/community/meta`：增加 `capabilities.stationPublishAllowed`。

## 5. 数据流

心灵搭子：后台保存手机号列表 → 私有配置 → 服务端 SHA-256 → 匹配小程序作者 ID → 查询已发布普通动态 → 统一动态卡片。

时空站台：小程序请求能力 → 当前小程序手机号匹配启用工作人员 → 有权限时展示发布按钮 → 发帖接口再次强校验 → 进入原有机审/人工审核状态机 → 统一动态卡片。

## 6. 兼容与回滚

- 旧 `/yuemu` 与心动接口暂时保留，避免旧体验版请求失败；新版本不再调用。
- 不改历史帖子类型，不做数据搬迁。
- 手机号配置缺失或为空时，心灵搭子返回正常空页，不扩大到全量动态。
- 工作人员手机号缺失或未匹配时，时空站台发布失败关闭；浏览不受影响。
- 回滚客户端不会破坏后端兼容；回滚配置只需将手机号列表保存为 `[]`。

## 7. 验收标准

1. 两个 Tab 的列表和卡片 DOM/组件来源相同，视觉尺寸与互动位置一致。
2. 心灵搭子结果作者集合严格等于有效配置手机号匹配到的账号集合。
3. 普通小程序用户不能发布 `sincere_post`，匹配启用工作人员账号的用户可以发布。
4. 后台可逐行编辑手机号，非法号码、重复号码和超过 50 项均有确定处理。
5. 小程序接口和日志不泄露配置手机号。
6. 后端测试、前端构建、小程序构建和生产运行验证均通过。
