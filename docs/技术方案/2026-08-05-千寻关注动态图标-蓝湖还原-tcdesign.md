# 千寻关注动态图标蓝湖还原技术方案

## 1. 目标与范围

- 目标：将千寻「成家」关注信息流复用的动态卡片中，性别、悄悄话、评论、点赞图标按蓝湖 66 稿 1:1 还原。
- 范围：仅修改共享动态卡 `QianxunFamilyPage/CommunityCard` 的图标资产、尺寸和间距；不改动接口、文案和既有点击链路。
- 复用关系：关注、同城、热门共用 `CommunityCard`，因此本次修复会同时消除三个信息流场景中的同类偏差。

## 2. 设计基线

- 蓝湖项目：千寻 66 稿。
- 权威画板：`d1e7f6eb-fab0-409d-8046-42e6c5fa8ce9`，名称「千寻-成家-同城全」。
- 本地原图：`docs/验收报告/截图证据/2026-07-22-千寻66稿/蓝湖基线/178.png`。
- 原图规格：1500×14524 PNG，SHA-256 `616775894c5361de638b3b943ae643f0e2c701d9bfaeae16c76924853fafdeed`。
- 选用原因：关注态的有内容卡与同城/热门复用同一组件；该画板同时包含女性/男性、悄悄话、评论、点赞未点亮/点亮状态，是本次最完整的卡片状态基线。

## 3. 根因

当前实现没有消费设计资产：

- 性别由系统字体字符 `♀/♂` 绘制；
- 悄悄话由两层圆形和 `YO` 文本拼接；
- 评论由字符 `◯` 近似；
- 点赞由字符 `♡/♥` 近似。

这些字符受微信字体、字重和行盒影响，线宽、轮廓、渐变、基线均无法与设计稿一致。

## 4. 切图与组件映射

原图按 4× 设计像素存储；运行态 750rpx 对应 1500px，因此切图像素除以 2 即为运行 rpx。

| 资产 | 原图裁切框（x, y, w, h） | 运行尺寸 | 状态 |
| --- | --- | --- | --- |
| `gender-female.png` | 497, 606, 64, 64 | 32×32rpx | 女性 |
| `gender-male.png` | 495, 2296, 64, 64 | 32×32rpx | 男性 |
| `whisper.png` | 98, 2030, 104, 104 | 52×52rpx | 悄悄话/私信通用 |
| `comment.png` | 1074, 2048, 64, 64 | 32×32rpx | 评论 |
| `like-active.png` | 1264, 2050, 64, 64 | 32×32rpx | 已点赞 |
| `like.png` | 1264, 4040, 64, 64 | 32×32rpx | 未点赞 |

切图保持 PNG 原始像素，不缩放、不转换格式、不增加 CDN 图片处理参数。非底部图标通过既有 `assets:upload-icons` 原字节上传 OSS，运行代码只引用 `miniappOssIcons`。

## 5. 实现约束

1. 图标必须使用真实 `Image` 组件，不允许字符、CSS 描边或透明热区替代。
2. 性别为空时仍不渲染图标，不改变服务端口径。
3. 点赞状态继续由 `post.liked` 驱动，只切换 OSS 图片地址。
4. 悄悄话、评论、点赞的父级点击事件保持不变。
5. 图标可见区域与点击区域一致，现有操作行触控范围不缩小。

## 6. 验收标准

- 静态门禁：六项 OSS key 全部存在；页面使用 `Image`；源码不再出现 `♀/♂/◯/♡/♥` 或拼装 `YO` 图标。
- 资产门禁：六张源图存在、尺寸和 SHA-256 稳定，上传脚本按原字节处理。
- 构建门禁：`npm --prefix miniapp run build:weapp` 退出码为 0。
- 运行态：375×812 微信截图中，图标轮廓、点亮状态、尺寸、间距和垂直基线逐项对照基线；关键首屏目标还原度不低于 97%。
