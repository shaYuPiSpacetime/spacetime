# 心动单人解锁充值页蓝湖还原技术方案

## 1. 范围

- 设计名称：千寻币-充值。
- 蓝湖 ID：`ffa585ea-0136-407a-9930-ae8c26da0128`。
- 端与视口：微信小程序，设计稿 750×1624。
- 入口：心动单人解锁弹窗“只看ta(100 Q)”。
- 新路由：`/pages/coins/unlock-recharge?sourceScene=likes_unlock_one`。
- 不修改：`/pages/coins/index` 的“我的-千寻币”通用资产页。

## 2. 根因

当前社区页把 `likes_unlock_one` 场景直接导航到 `/pages/coins/index`。通用页面包含余额卡、千寻币用途等资产中心结构，但蓝湖单人解锁稿要求先展示“Ta也喜欢了你”的关系情境，再展示本次消耗、余额和充值套餐，因此路由级场景被错误合并。

## 3. 设计基线

| 区块 | 蓝湖基线 |
| --- | --- |
| 页面背景 | 淡蓝灰横向渐变，750×1624 |
| 导航 | 176rpx，自定义返回，标题“千寻币” |
| 情境头像 | 中间约 200rpx、两侧 120rpx，白色描边；蓝色“97年/本科”气泡 |
| 主文案 | “Ta也喜欢了你!”、“解锁后立即和ta配对聊天”，深蓝居中 |
| 资产行 | 左侧“本次消耗 100 币”，右侧“余额 0 币” |
| 充值卡 | 700×338rpx 白卡，标题“充值千寻币”，右上“充值须知” |
| 默认套餐 | 3000 币、¥268.00、热销推荐、8.9折 |
| 底部操作 | 664×98rpx 蓝色“立即充值”；协议为《时空邂逅充值协议》 |

## 4. Token 与组件映射

| 设计元素 | 实现 |
| --- | --- |
| 主蓝 | `#2876FF` / 项目 `LANHU_BLUE` |
| 深蓝文字 | 项目 `LANHU_NAVY` |
| 背景 | 项目 `LANHU_SOFT_BG` |
| 导航 | `LanhuNav`，只复用基础导航能力 |
| 头像 | 现有 `heart-person-blur.webp`，独立 `Image` |
| 金币图标 | `miniappOssIcons.coinGold` |
| 支付数据 | `useCoins`，视觉页面不复用通用 CoinsPage |

## 5. 数据与异常

- 余额、真实套餐、支付继续来自后端接口。
- 请求失败或套餐为空时使用蓝湖视觉基线套餐，ID 为负数。
- 负 ID 只用于防止中部空白，点击充值不创建真实订单。
- 未勾选协议时显示独立可见确认层；支付中、取消、失败沿用 hook 状态语义。

## 6. 验收门禁

- 静态门禁必须阻止社区页继续引用 `/pages/coins/index?sourceScene=likes_unlock_one`。
- 微信运行态点击“只看ta”必须进入 `pages/coins/unlock-recharge`。
- 首屏必须包含头像情境、消耗/余额、套餐卡、充值按钮和协议。
- 关键首屏目标还原度不低于 97%。
