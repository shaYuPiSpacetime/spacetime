# 认证强引导四步闭环蓝湖还原技术方案

## 1. 目标

未认证用户点击“立即完善”后，严格按“基本资料 → 添加头像 → 自我介绍 → 三重认证”续传；中途返回千寻页时，根据接口真实完成状态展示“未认证-填完部分资料”及勾选状态。认证页面的字段、枚举、状态标签和认证文案全部读取接口运行态配置，不在页面写死业务值。

蓝湖基线：项目“时空邂逅0625”，重点稿件为：

| 稿件 | 蓝湖索引 | 画布 |
| --- | ---: | --- |
| 未认证 | 130 | 375×812 |
| 未认证-填完部分资料 | 122 | 375×812 |
| 认证-基本资料 | 78 | 375×915 |
| 认证-添加头像 | 58 | 375×839 |
| 认证-自我介绍 | 76 | 375×839 |
| 认证-三重认证 | 75 | 375×839 |

## 2. 根因

1. 千寻入口曾按二元条件直接跳“我的认证”，而“我的认证”和“三重认证”共用同一页面，因此跳过头像、自我介绍。
2. 头像、自我介绍、三重认证脱离四步 `VerificationShell`，导致进度条和蓝湖外壳丢失。
3. 首页仅首次挂载加载，子页面返回后不刷新，因此部分资料状态和勾选不能同步。
4. 自我介绍状态误用聚合开放文本状态会被“关于我”等内容污染，必须读取自我介绍详情接口。
5. 文案接口缺 key 时页面直接渲染空字符串；需要完整运行态门禁阻断业务内容渲染。

## 3. 状态机

| 条件 | 下一页 |
| --- | --- |
| `basicProfileCompleted !== true` | `/pages/verification/basic` |
| 基本资料完成，头像未提交/驳回/过期 | `/pages/verification/avatar` |
| 头像已提交，介绍未提交/驳回/过期 | `/pages/verification/intro` |
| 头像、介绍均已提交 | `/pages/verification/triple` |

首页三项勾选：

- 基本资料：`basicProfileCompleted === true`。
- 头像简介：头像与自我介绍均为已提交状态；驳回、过期和未提交不勾选。
- 三重认证：`verifyLevel >= 3`。

## 4. 数据与动态配置

- 基本资料：`GET/PUT /miniapp/profile/basic`，字段显隐、必填、标签和枚举来自 `fieldSettings` 与 `profile-options`。
- 头像：头像来源从 `profileOptions.avatarSource` 读取；选图、裁剪、OSS 直传、提交审核沿用真实接口。
- 自我介绍：`GET/POST /miniapp/profile/introduction`，本人读取最新提交及审核状态。
- 三重认证：`GET /miniapp/verify/status`，状态中文读取 `auditStatus` 字典。
- 认证文案：由 `prd01.copy.rules` 下发，客户端完整校验 88 个认证 key；缺失、禁用或空值时不渲染空控件。
- 数据库迁移：`051_prd01_verification_onboarding_copy.sql` 仅追加缺失 key，不覆盖后台已有配置，可重复执行。

## 5. UI 映射

- 四步统一使用 `VerificationShell`：顶部导航、标题说明、四段进度卡、背景和底部按钮共用同一几何基线。
- 进度卡：`left=25rpx`、`top=382rpx`、`width=700rpx`、`height=156rpx`，轨道宽 `620rpx`。
- 部分完成卡：`left=25rpx`、`top=458rpx`、卡高 `168rpx`、间距 `20rpx`。
- 三重认证卡：头像、实名、学历状态均由接口渲染；已通过显示蓝色勾选，其他状态显示字典标签。
- 返回：四步主页面返回千寻页，千寻页通过 `useDidShow` 重新查询并显示最新部分完成态。

## 6. 防回归

- 状态机、部分资料判断、勾选映射、四步外壳和返回路径均纳入 `test-verification-onboarding-flow.cjs`。
- 认证运行态 88 个 key、全部认证字典和页面入口隔离纳入构建前门禁。
- 构建后校验 58 个页面各自 `Page=1`、共享脚本 `Page=0`、全局 `App=1`。
- 微信开发者工具以 375×812 生成运行态截图；禁止用整页设计图承载交互控件。
