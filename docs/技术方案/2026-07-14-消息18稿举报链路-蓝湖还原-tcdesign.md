## 3. 设计基线

### 3.1 我申请的详情

- 延续消息详情页白底、自定义导航、用户资料、气泡卡片和时间线结构。
- 顶部事件为“过期自动拒绝 / 超时未处理，系统自动拒绝 / 05/16 08:00”。
- 第二节点为“发起申请 / 05/09 07:59”，区别于申请我的状态的“收到申请”。
- 底部固定主按钮“申请认识”。

### 3.2 举报操作面板

- 点击卡片右下可见“举报”组件后显示遮罩与底部操作面板。
- 操作面板顶部圆角 16px；“举报”与“取消”各高约 60px，中间 10px 浅蓝灰分隔。
- 点击遮罩或“取消”关闭；点击“举报”进入举报表单。

### 3.3 举报表单

- 页面背景 `#f2f2f2`，导航标题为“举报”。
- 举报原因共 8 项，只允许单选；选中项使用 `#2876ff` 蓝底和白字。
- 描述输入上限 400 字，实时显示字数。
- 上传区域为可见真实组件，默认显示 OSS 摄像机图标与“上传材料”；本轮 Mock 选择本地图片后仅做预览，不伪装真实上传完成。
- 提交时必须已选择原因；成功后切换到结果页。

### 3.4 提交成功

- 页面背景 `#f2f2f2`，导航标题和内容标题均为“提交成功”。
- 蓝色圆形成功标识使用 CSS 绘制，不新增静态图片。
- “平台违规行为处罚细则”作为可见链接组件；后端/规则页未提供，本轮点击提示待接入。
- “知道啦”返回消息详情或消息首页。

## 6. 状态流

```text
悄悄话详情
  -> 点击举报
  -> 举报操作面板
      -> 取消/遮罩：回到详情
      -> 举报：进入举报表单
          -> 未选原因：停留并提示
          -> 选择原因 + 可选描述/图片
          -> 提交中禁用重复点击
          -> Mock 提交成功
          -> 提交成功页
              -> 知道啦：返回详情；无页面栈时回消息首页
```

## 7. 缺口登记

- 蓝湖接口可返回 4 张新增稿高清图与少量圆角 token，但图层树、尺寸标注和切图信息返回 `Unknown`；本轮以 1500×3248 原图按 4:1 映射到 375×812 视口，不把缺失图层信息视为已补齐。
- 真实举报 API、举报原因字典、图片上传接口、规则页 URL 均未提供；本轮保持 Mock，不能宣称真实联调完成。
- 设计仅展示一格上传入口，未明确附件上限、大小和格式；本轮 UI 只选择一张图片，不扩展业务规则。
