# 敏感词 AC 工具包与内存评估

日期：2026-09-08。为方案评估开展的独立实验，未接入业务代码、未启动 Spring Boot 服务、未连接数据库，也不代表敏感词功能已实现或验收通过。

## 工具包

采用现成 Java 库 `com.hankcs:aho-corasick-double-array-trie:1.2.3` 进行实验。工具包从 Maven Central 下载，并与同源 SHA-1 校验文件核对。无需自行重写 AC 算法；业务仍需实现词库维护、规范化、索引刷新和审核接入。

## 输入与测量方式

- 数据：用户提供的 Vocabulary.7z，与方案中已记录的 SHA-256 一致。
- 读取 76,702 条分类记录，按 Java NFKC + Locale.ROOT 小写聚合，实际得到 51,085 个匹配词。
- 环境：本机 Windows，Microsoft OpenJDK 21.0.11，G1 GC，`-Xms32m -Xmx256m`。
- 索引挂载的数据包含规范化词、代表性原词、分类位图及模拟记录 ID 数组；没有加载完整业务实体或数据库连接池。ID 仅用于独立容量模拟，没有写入业务数据库。
- 单份大小：通过 Java Instrumentation.getObjectSize 遍历索引的可达对象，按对象身份去重计量。该值包含数组、词条对象、字符串及分类/ID 信息，不包含 JVM 本身、线程栈、元空间和其他业务缓存。
- 构建峰值：每 2 ms 采样 MemoryMXBean 的整个独立进程堆使用量，涵盖文件读取、解码、规范化、构建和词典键核对。采样可能漏掉更短瞬时峰值，不作为严格内存上限。
- 第二次构建期间保留旧索引，模拟更新时新旧快照同时存在。两次构建后均核对全部词典键能取回对应值且能够命中。

## 结果

1 MiB = 1,048,576 字节；1 GiB = 1,024 MiB。

| 指标 | 测量值 | 约合 GiB |
| --- | ---: | ---: |
| 单份索引及挂载词条信息 | 14.26 MiB | 0.014 |
| 单份加载完成、GC 后整个测试进程堆占用 | 16.69 MiB | 0.016 |
| 首次读取及构建的采样堆峰值 | 118.04 MiB | 0.115 |
| 保留旧索引、重建新索引的采样堆峰值 | 120.71 MiB | 0.118 |
| 两份索引及挂载词条信息 | 28.52 MiB | 0.028 |
| 测试进程堆上限 | 256 MiB | 0.25 |

两次构建均正常完成，本次未出现 OOM。实测表明这批词库在此现成实现下，单份稳定索引为十几 MiB，构建时的临时内存明显更高。本实验不是服务器 RSS 测量，也不是整个业务应用的容量测试。

原始字节数据：`docs/test-artifacts/sensitive-word-ac-memory-20260908.json`。
实验输入及测量程序：`tmp/ac-memory-probe-20260908/`。该目录只是评估材料，不属于业务实现。

## 应用内存判断

当前仓库 backend/Dockerfile 将 JAVA_OPTS 留给部署时传入，未由本次只读核对确认线上实际 Xmx、容器上限和业务堆余量。因此不能依据本次实验保证线上不会 OOM，也不能认为整个 Spring Boot 应用只需 256 MiB。

实施阶段先按本功能额外预留约 256 MiB 堆余量作为初步容量预算，再在真实服务中验证数据库加载方式、正常业务并发和重建峰值。该预算属于基于本次实验的工程估算，不是严格上限或已验证的生产配置。每实例共享一份当前索引，最多单个重建任务，及时释放旧索引及加载临时对象；不按请求重复构建。

普通词库查询、加载或索引构建失败仍按已确认规则跳过本地检查并继续微信。JVM 真正发生 OutOfMemoryError 或进程被容器终止时，不能保证依靠“跳过审核”继续运行，需要通过容量验证避免。
