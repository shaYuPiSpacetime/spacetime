# 小程序多页面蓝湖还原与悄悄话扣币技术方案

## 1. 目标与设计事实

本轮覆盖心动空态、未认证入口、推荐/理想型、编辑资料/主页预览和动态详情。视觉事实源优先级为：蓝湖稳定画板 UUID、仓库设计基线、真实运行截图。新增理想型空态画板为 `ab329c25-1c09-4540-95cd-cdd5645413ba`。

动态详情点击“申请认识”对应 `YO悄悄话-弹窗`（`b6a20f6e-e57f-4835-8efd-9383f4e4c1f5`、`8864096b-eea3-4a23-b988-bdbb750ed2db`）；`动态详情-申请认识旁边的弹窗` 是三点菜单，不作为发送弹层。

## 2. 前端实现约束

- 微信原生胶囊和状态栏不自绘；顶部按钮以 `getMenuButtonBoundingClientRect` 映射出的 `menuLeft/menuTop/menuHeight` 为安全边界。
- 推荐两个按钮、理想型一个按钮均放在胶囊左侧，保留至少 12rpx 间距；禁止固定写死 470/520/535rpx。
- 理想型空态由 378rpx 星空头图、白色内容区、`qianxunEmptyFollowing` 插画、空态文案、浮动筛选按钮和 `AppTabBar` 组成。
- 非底部静态图标继续通过 `miniappOssIcons` 使用 OSS 公网地址；底部 Tab 图标保持包内资源。
- 编辑页和主页预览圆头像共用 `profileAvatar/avatarUrl`，统一 `aspectFill`、圆角与白色描边；主背景图仍按 `profileBackground → 相册首图 → 头像` 回退。
- 标签组件宽度由文本和内边距自然撑开，容器可换行；页面卡片不设置会裁切多行标签的固定高度。
- 动态详情悄悄话弹层是可输入、可关闭、可提交的真实组件，不允许使用整图或透明热区模拟。

## 3. 悄悄话接口与事务

### 3.1 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/miniapp/message/whispers/precheck` | 返回目标资料摘要、1–60 字约束、场景单价、免费次数、余额和可发送状态 |
| POST | `/miniapp/message/whispers` | 携带 `Idempotency-Key` 创建悄悄话并完成权益/扣币事务 |

费用只从 `app_coin_scene_config.scene_code=whisper` 读取。蓝湖上的“100”是示例，不进入客户端常量。

### 3.2 数据表

`app_whisper` 保存不可枚举 `whisper_no`、发送方、接收方、来源动态、内容、费用、支付方式、幂等键、状态和有效期。唯一键为 `(sender_user_id, idempotency_key)`；同键同请求返回首次结果，同键不同目标或内容报冲突。

### 3.3 事务顺序

1. 校验发送方和接收方状态、不能给自己发送、动态作者与目标一致。
2. 按发送方和幂等键查询已有记录。
3. 锁定 `app_user_asset`。
4. 优先扣减 `today_free_whisper_remain`；否则校验场景价格和余额并原子扣币。
5. 插入 `app_whisper`；付币时插入 `app_user_coin_log`，业务场景为 `whisper`。
6. 更新最近消费时间并提交事务。

真实 IM 触达仍属于 PRD-03 Outbox/LiteChat 完整模块；本轮保证发送记录、费用、资产和流水在本项目数据库内闭环，不在客户端伪造扣费结果。

## 4. 错误与交互

- 预检查不可发送：弹层仍可展示目标资料，但发送按钮禁用并显示服务端原因。
- 余额不足：服务端返回资产错误，小程序提示并保留已输入内容，不产生记录或流水。
- 重复点击：客户端复用同一幂等键；服务端返回首次结果，不重复扣次数或千寻币。
- 内容为空或超过 60 字：客户端阻止提交，服务端再次校验。

## 5. 验收门禁

- 主视口 375×812，补充视口 390×844。
- 推荐、理想型、未认证入口和悄悄话弹层关键首屏还原度不低于 97%；其余整体不低于 95%。
- 小程序新增闭环测试、相关既有回归、TypeScript 检查、后端定向 JUnit 和完整 Maven 测试均通过。
