# 消息 15 稿后端接口契约

> 版本：v1.0
> 日期：2026-07-14
> 当前状态：契约已冻结，后端待实现；小程序当前由 Mock Provider 对齐本契约。
> 适用前缀：消息业务统一为 `/miniapp/message/*`，旧 `/miniapp/messages/*` 不再实施。

## 1. 契约目标与边界

本契约是消息 15 稿从 Mock 切换到真实后端、再接入腾讯云 LiteChat 的唯一业务口径。页面领域类型不得依赖数据库实体、MyBatis 对象、腾讯 SDK 消息对象或腾讯回调原始结构。

本契约约束：

1. 小程序业务接口均要求本项目登录态，响应使用精确 `R<T>`。
2. 普通私信正文历史与发送由客户端 `MessageImGateway` 对接 LiteChat；本契约不提供 `/send-text`，避免双发送链路。
3. 后端会话状态接口用于体验预检，腾讯“发单聊消息之前回调”仍是未来普通私信的最终授权边界。
4. 悄悄话创建、回复、忽略和撤销由后端业务事务控制；创建必须携带 `Idempotency-Key`。
5. 删除/全部删除只改变当前用户的列表可见性，不等于拒绝、撤销、逻辑删除业务记录或物理删除审计数据。
6. 当前 Mock 返回 `contentMaxLength=60`。旧 PRD 出现的 200/500 字为待确认差异；产品确认前，前后端均按 60 执行。

## 2. 通用协议

### 2.1 请求头

| 请求头 | 必填 | 说明 |
| --- | --- | --- |
| `X-Auth-Token` | 小程序接口必填 | 本项目登录令牌，由统一鉴权处理 |
| `Idempotency-Key` | 创建悄悄话必填 | UUID/ULID，最大 64 字符；同一用户同一业务动作稳定复用 |
| `X-Request-Id` | 建议 | 客户端链路 ID，不承担业务幂等 |
| `Content-Type` | 有 body 时必填 | `application/json` |

### 2.2 `R<T>`

```ts
interface R<T> {
  code: number // 200 表示成功；其余值遵循 ResultCodeEnum/消息业务错误码
  msg: string
  data: T | null
}
```

成功示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

业务错误返回 `R<null>`。沿用当前项目约定：Token/权限拦截器分别设置 HTTP 401/403；Controller 参数与业务异常由统一异常处理器返回 `R<T>`，调用方以数值 `code` 分支。未知异常的请求 ID继续放在 `msg` 中，不新增未在现有 `R<T>` 声明的字段。

### 2.3 分页

页码分页用于本地业务列表：

```ts
interface PageQuery {
  page?: number // 默认 1，最小 1
  size?: number // 默认 20，范围 1..50
}

interface PageVO<T> {
  records: T[]
  total: number
  size: number
  current: number
  pages: number
}
```

排序必须稳定，默认 `eventTime DESC, id DESC`。分页响应不得暴露数据库 ID。普通聊天历史分页由未来 LiteChat Gateway 使用 SDK 游标，不经过本契约。

### 2.4 时间、金额与业务号

- 时间统一返回 ISO 8601、带时区，例如 `2026-07-14T14:33:00+08:00`。
- 千寻币为整数，字段后缀 `CoinAmount`，不得使用浮点数。
- `conversationNo/messageNo/whisperNo/reportNo` 为不可枚举业务号；Controller 不接收数据库自增 ID。
- 文本以 Unicode code point 计数，首尾空白按业务规则归一化后校验。

## 5. 首页与会话接口

### 5.1 `GET /miniapp/message/home`

请求：无 query。登录必需；未认证用户可请求，但 `verified=false`，返回认证兼容内容。

响应：`R<MessageHome>`。

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "verified": true,
    "entries": [
      {"type":"whisper","title":"悄悄话","subtitle":"有人想认识你","unreadCount":3,"previewAvatars":["https://..."]},
      {"type":"private","title":"私信","subtitle":"查看全部私信","unreadCount":2,"previewAvatars":[]}
    ],
    "rows": [],
    "unreadSummary": {"total":7,"whisper":3,"private":2,"assistant":1,"system":1,"likedMe":0}
  }
}
```

- 分页：无；首页只返回首屏固定入口和受控数量行。完整私信列表使用会话接口。
- 权限：本人数据；不可传 userId 查询他人。
- 幂等：只读。
- 错误：`MESSAGE_HOME_UNAVAILABLE`。
- Mock：`messageHome`，对应首页 Design ID `626cd513...`。
- 未来来源：本地固定业务入口、认证状态和官方频道投影，与 LiteChat 会话摘要/未读聚合；必须批量查询，禁止 N+1。

### 5.2 `GET /miniapp/message/unread-summary`

请求：无。响应：`R<UnreadSummary>`。

- 分页：无。
- 权限：本人未读。
- 幂等：只读。
- 错误：`UNREAD_SUMMARY_UNAVAILABLE`。
- Mock：`unreadSummary`，所有已读/隐藏操作后同步重算。
- 未来来源：本地官方频道、悄悄话读取进度与 LiteChat 会话未读合并；`total` 按产品角标规则计算并在服务端统一封顶。

### 5.3 `GET /miniapp/message/conversations`

Query：`page/size`，可选 `state=active|closed`。响应：`R<PageVO<ConversationSummary>>`。

- 排序：`pinned DESC, lastMessageTime DESC, conversationNo DESC`。
- 权限：只返回当前用户参与的会话；未认证按业务规则返回 403 或空列表，不泄漏对方资料。
- 幂等：只读。
- 错误：`VERIFICATION_REQUIRED`、`CONVERSATION_LIST_UNAVAILABLE`。
- Mock：`conversations`，对应私信列表 Design ID `aabf0ea4...`。
- 未来来源：本地会话状态/对方公开资料与 LiteChat 会话摘要合并。若 LiteChat 暂不可用，返回显式降级信息，不伪造最新消息。

### 5.4 `GET /miniapp/message/conversations/{conversationNo}/state`

请求：路径参数 `conversationNo`。响应：`R<ConversationState>`。

- 分页：无；不返回聊天正文。
- 权限：仅会话成员；路径业务号必须与当前用户关系匹配。
- 幂等：只读。
- 错误：`CONVERSATION_NOT_FOUND`、`CONVERSATION_FORBIDDEN`、`CONVERSATION_CLOSED`。
- Mock：`conversationStates[conversationNo]`。
- 未来来源：MySQL 会话状态 + Redis 短期权限快照；最终发送权限仍由腾讯消息前回调裁决。

### 5.5 `POST /miniapp/message/messages/read`

请求：

```json
{
  "conversationNo": "CV202607140001",
  "throughMessageNo": "MSG202607140099",
  "readAt": "2026-07-14T14:33:00+08:00"
}
```

响应：`R<UnreadSummary>`。

- 分页：无。
- 权限：只允许会话成员更新自己的读取进度。
- 幂等：读取游标只前进不回退；重复消息号不重复减少未读。
- 错误：`CONVERSATION_NOT_FOUND`、`MESSAGE_NOT_IN_CONVERSATION`、`READ_POSITION_CONFLICT`。
- Mock：`readState`，更新会话与首页未读。
- 未来来源：本地读取进度，同时调用 LiteChat 已读上报；局部失败必须可重试，不将未上报伪装为成功。

## 6. 悄悄话接口

### 6.1 `GET /miniapp/message/whispers`

Query：

| 字段 | 必填 | 枚举/约束 |
| --- | --- | --- |
| `direction` | 是 | `received/sent` |
| `section` | 否 | `pending/handled/all`，默认 `all` |
| `page/size` | 否 | 通用页码 |

响应：`R<PageVO<WhisperRecord>>`。

- 排序：`updatedAt DESC, whisperNo DESC`；只返回当前用户 `visible=true` 的投影。
- 权限：本人接收或发送的记录。
- 幂等：只读。
- 错误：`INVALID_WHISPER_DIRECTION`、`WHISPER_LIST_UNAVAILABLE`。
- Mock：`whispers`，覆盖申请我的、我申请的与删除后的列表。
- 未来来源：本地悄悄话记录、用户可见性投影和对方公开资料；不从 LiteChat 历史反推业务状态。

### 6.2 `GET /miniapp/message/whispers/{whisperNo}`

响应：`R<WhisperRecord>`。

- 分页：无。
- 权限：仅发送方或接收方；即使当前列表已隐藏，只要合规/产品规则允许仍可通过已有业务链路读详情，不能越权枚举。
- 幂等：只读。
- 错误：`WHISPER_NOT_FOUND`、`WHISPER_FORBIDDEN`。
- Mock：`whispers[whisperNo]`，覆盖过期、匹配、解除和申请编辑四种详情视图。
- 未来来源：本地悄悄话、状态事件表、账务摘要与公开资料。

### 6.3 `POST /miniapp/message/whispers/precheck`

请求：

```json
{
  "targetUserNo": "U202607140002",
  "scene": "profile|message_home|recommendation"
}
```

响应：

```ts
interface WhisperPrecheckResult {
  allowed: boolean
  reasonCode: string | null
  reasonText: string | null
  contentMaxLength: number // 当前 60
  coinAmount: number
  free: boolean
  coinBalance: number
  cooldownUntil: string | null
}
```

- 分页：无。
- 权限：登录、认证、账号正常；目标用户存在且允许被申请。
- 幂等：只读，不预扣币、不占用次数。
- 错误：`VERIFICATION_REQUIRED`、`TARGET_USER_NOT_FOUND`、`WHISPER_COOLDOWN`、`WHISPER_NOT_ALLOWED`。
- Mock：`whisperPrecheck`，固定 `contentMaxLength=60`，币价按 fixture。
- 未来来源：认证、账号、关系、冷却、会员权益、千寻币余额、内容配置和风控。

### 6.4 `POST /miniapp/message/whispers`

请求头：`Idempotency-Key` 必填。请求：

```json
{
  "targetUserNo": "U202607140002",
  "content": "想认识你，可以聊聊吗？",
  "scene": "profile"
}
```

响应：`R<WhisperRecord>`。

- 分页：无。
- 权限：登录、认证、账号正常，通过关系/冷却/风控/余额校验。
- 幂等：键作用域为“当前用户 + 创建悄悄话”；同键同请求返回首次结果，同键不同 payload 返回 `IDEMPOTENCY_KEY_REUSED`。超时重试必须复用原键。
- 状态：创建成功为 `pending`；扣费、记录、Outbox 必须在本地事务边界内保持一致。
- 错误：`IDEMPOTENCY_KEY_REQUIRED`、`IDEMPOTENCY_KEY_REUSED`、`CONTENT_EMPTY`、`CONTENT_TOO_LONG`、`INSUFFICIENT_COIN`、`WHISPER_COOLDOWN`、`CONTENT_RISK_REJECTED`。
- Mock：`whisperCreate`，同键缓存首次结果；不真实扣款，但同步减少 Mock 余额。
- 未来来源：本地资格与资产事务、悄悄话表、Outbox，事务后由腾讯 IM REST API 发送业务消息。发送失败按补偿规则处理，不能重复扣费。

### 6.5 `POST /miniapp/message/whispers/{whisperNo}/reply`

请求：

```json
{
  "content": "好呀，很高兴认识你",
  "expectedVersion": 3
}
```

响应：`R<WhisperRecord>`。

- 权限：仅接收方；当前状态允许回复；账号与认证正常。
- 幂等：相同当前状态与相同内容重复提交返回已完成结果；`expectedVersion` 防并发流转。
- 状态：`pending -> replied -> matched`；匹配事务失败时不得返回伪匹配成功。
- 错误：`WHISPER_NOT_FOUND`、`WHISPER_FORBIDDEN`、`WHISPER_STATE_CONFLICT`、`CONTENT_TOO_LONG`、`MATCH_CREATE_FAILED`。
- Mock：`whisperTransitions.reply`，产生匹配成功详情并开放会话。
- 未来来源：本地状态机、匹配关系事务、会话服务与 Outbox/IM REST 消息。

### 6.6 `POST /miniapp/message/whispers/{whisperNo}/ignore`

请求：`{"expectedVersion":3}`。响应：`R<WhisperRecord>`。

- 权限：仅接收方，且当前可忽略。
- 幂等：已为 `ignored` 时返回当前结果；其他终态返回冲突。
- 状态：`pending -> ignored`，按配置生成 `cooldownUntil`。
- 错误：`WHISPER_FORBIDDEN`、`WHISPER_STATE_CONFLICT`。
- Mock：`whisperTransitions.ignore`。
- 未来来源：本地状态机和冷却配置；不通过删除可见性实现。

### 6.7 `POST /miniapp/message/whispers/{whisperNo}/cancel`

请求：`{"expectedVersion":3}`。响应：`R<WhisperRecord>`。

- 权限：仅发送方，且记录仍为 `pending`。
- 幂等：已为 `cancelled` 返回当前结果；已回复/匹配/过期返回冲突。
- 状态：`pending -> cancelled`；是否退款以账务配置和发送结果为准，必须留下流水。
- 错误：`WHISPER_FORBIDDEN`、`WHISPER_STATE_CONFLICT`、`WHISPER_COMPENSATION_PENDING`。
- Mock：`whisperTransitions.cancel`。
- 未来来源：本地状态机、账务/补偿记录和必要的官方通知；不是物理删除。

### 6.8 `DELETE /miniapp/message/whispers/{whisperNo}/visibility`

请求：无 body。响应：`R<{ hidden: true }>`。

- 权限：仅当前用户自己的列表投影。
- 幂等：重复隐藏保持 `hidden=true`。
- 语义：只隐藏当前用户列表；不得修改 `WhisperState`，不得触发拒绝/撤销/退款，不得物理删除业务与审计记录。
- 错误：`WHISPER_NOT_FOUND`、`WHISPER_FORBIDDEN`。
- Mock：`whisperVisibility[viewer][whisperNo]=hidden`。
- 未来来源：独立用户可见性记录或等价投影。

### 6.9 `POST /miniapp/message/whispers/visibility/batch-hide`

请求：

```json
{
  "direction": "received",
  "section": "handled",
  "whisperNos": []
}
```

响应：`R<{ hiddenCount: number }>`。

- 规则：`whisperNos` 非空时仅隐藏列出的本人记录；为空时按 `direction + section` 隐藏当前筛选范围。`direction` 必填，防止误删所有 Tab。
- 权限：只能影响当前用户投影。
- 幂等：只统计从可见变为隐藏的数量，重复调用 `hiddenCount=0`。
- 语义：与单条隐藏相同，不修改业务状态、不退款、不删除审计。
- 错误：`INVALID_WHISPER_DIRECTION`、`BATCH_SCOPE_REQUIRED`、`WHISPER_FORBIDDEN`。
- Mock：`whisperVisibility.batchHide`，对应全部删除确认稿 `955469c9...`。
- 未来来源：用户可见性投影批量更新，事务内校验归属。

## 7. 官方频道与安全接口

### 7.1 `GET /miniapp/message/channels/{channel}/messages`

路径：`channel=assistant|system`。Query：`page/size`。响应：`R<PageVO<OfficialChannelMessage>>`。

- 排序：`publishedAt DESC, messageNo DESC`，客户端按日期分组展示。
- 权限：本人可见范围；内部运营定向消息不能泄漏给其他用户。
- 幂等：只读。
- 错误：`INVALID_CHANNEL`、`CHANNEL_MESSAGE_UNAVAILABLE`。
- Mock：`channelMessages.assistant/system`，对应 `798b68f9...` 与 `ff867af1...`。
- 未来来源：本地官方消息投影；可由业务后台/任务创建并经 IM REST API 触达，但页面查询以本地投影为准。

### 7.2 `POST /miniapp/message/channels/{channel}/read`

请求：

```json
{"throughMessageNo":"SYS202607140099"}
```

响应：`R<UnreadSummary>`。

- 权限：本人读取进度；`channel` 仅允许 `assistant/system`。
- 幂等：游标只前进；重复调用不重复减未读。
- 错误：`INVALID_CHANNEL`、`CHANNEL_MESSAGE_NOT_FOUND`、`READ_POSITION_CONFLICT`。
- Mock：`channelReadState`，同时刷新首页未读。
- 未来来源：本地官方频道读取进度；不依赖客户端 SDK 已读回执。

### 7.3 `POST /miniapp/message/report`

请求：

```json
{
  "clientReportId": "01J2REPORT0001",
  "targetType": "conversation_message|whisper",
  "conversationNo": "CV202607140001",
  "messageNo": "MSG202607140099",

  "reason": "harassment|fraud|pornography|personal_info|other",
```

- 未来来源：本地举报、必要消息副本和审计；后台按 RBAC 查看，敏感原文访问必须留痕。

## 8. IM 凭证与腾讯回调

### 8.1 `GET /miniapp/im/credentials`

响应：

```ts
interface ImCredential {
  sdkAppId: number
  imUserId: string
  userSig: string
  expireAt: string
}
```

- 分页：无。
- 权限：登录、账号正常；`imUserId` 与当前项目用户稳定绑定。
- 幂等：只读；临近过期可刷新签发，但不能重复创建 IM 账号。
- 错误：`IM_ACCOUNT_DISABLED`、`IM_CREDENTIAL_UNAVAILABLE`。
- Mock：Mock Provider 不调用；Mock Gateway 使用本地身份。
- 未来来源：本地 IM 账号映射与后端 UserSig Provider。SecretKey 只存在服务端私有环境变量，响应和日志不得泄漏 SecretKey。

### 8.2 `POST /internal/tencent-im/callback/{callbackPathToken}`

该端点不是小程序接口，不使用 `X-Auth-Token` 或通用 `R<T>`；必须按腾讯云回调协议返回腾讯要求的 JSON 结构。路径令牌存于私有环境变量，文档和日志不得记录真实值。

首期允许命令：

| `CallbackCommand` | 责任 | 幂等键 |
| --- | --- | --- |
| `C2C.CallbackBeforeSendMsg` | 普通私信最终授权 | 同一请求上下文只裁决，不落重复业务消息 |
| `C2C.CallbackAfterSendMsg` | 必要消息副本、业务索引、发送结果 | `SDKAppID + MsgKey` |
| `C2C.CallbackAfterMsgReport` | 本地读取进度同步 | `SDKAppID + CallbackCommand + MsgKey/读取游标` |

- 权限：HTTPS；校验不可猜测路径令牌、`SdkAppid`、命令白名单、请求方法、体积和频率；不虚构腾讯未提供的签名头。
- 错误：非法令牌直接网关拒绝；未知命令返回明确拒绝；业务拒发按腾讯协议返回非零 `ErrorCode` 与稳定原因。
- Mock：页面 Mock 不模拟公网回调；Gateway 单元测试只模拟授权/发送结果事件。
- 未来来源：腾讯云原始回调，本地账号映射、Redis 权限快照、消息副本与审计。
- 安全：日志只记录命令、腾讯消息标识、耗时、结果码与脱敏账号，不打印 UserSig 或正文。

## 10. 状态机、幂等与事务规则

### 10.1 悄悄话状态机

允许转换：

- `pending -> replied -> matched`
- `pending -> ignored`
- `pending -> expired`
- `pending -> cancelled`

`matched/expired/cancelled` 为终态；`ignored` 是否在冷却结束后恢复可申请由新业务记录处理，不直接复活旧记录。可见性不参与状态机。

### 10.2 创建事务

1. 锁定“当前用户 + Idempotency-Key”。
2. 校验认证、目标关系、冷却、频率、内容和余额。
3. 同一事务完成权益/千寻币处理、悄悄话记录与 Outbox。
4. 事务提交后发送 IM REST 消息。
5. 可重试失败由 Outbox 重试；需退款时使用唯一补偿流水。
6. 任意重试不得重复创建、扣币或发送逻辑重复消息。

### 10.3 私信失败重试

客户端首次发送生成稳定 `clientMsgId`。失败消息重发更新原 `ChatMessage` 的 `sendStatus`，不得生成新 `clientMsgId`；腾讯消息后回调以 `SDKAppID + MsgKey` 去重，`clientMsgId` 只做客户端关联。

## 12. 后端实现约束

- 分层保持 `Controller -> Service -> ServiceImpl -> DAO -> DAOImpl -> Mapper`。
- Miniapp Controller 返回上述精确 `R<T>`，不得返回 `R<Object>`、Map 或数据库实体。
- 公共消息实体与服务放在 `common/`；`miniapp/` 和 `admin/` 不得相互 import。
- 业务表继承 `BaseEntity` 审计字段并使用逻辑删除；消息可见性与业务逻辑删除分离。
- 管理后台查询和举报处理使用既有 `@RequirePermission` 与 RBAC。
- 列表聚合批量查询，禁止按会话/悄悄话逐条查用户产生 N+1。

## 13. 合同测试最小集合

1. 所有接口成功和错误响应符合 `R<T>`，腾讯回调除外。
2. 页码边界、稳定排序、连续翻页无重复/漏项。
3. 用户 A 不能读取/隐藏/已读用户 B 的会话与悄悄话。
4. 同一 `Idempotency-Key` 重试不重复创建和扣币；同键不同 payload 返回冲突。
5. 同一失败私信重试复用 `clientMsgId`。
6. 单条/批量隐藏不改变 `WhisperState`、不退款、不删除审计。
7. `contentMaxLength=60` 时 60 个 code point 成功、61 个失败。
8. 已读游标只前进，首页/列表/Tab 未读一致。
9. 未知 `channel`、非法枚举、伪造业务号和越权均被拒绝。
10. 回调重复投递以腾讯事件键幂等，普通日志无正文、UserSig 或 SecretKey。

## 14. 版本迁移

- 新实现只发布 `/miniapp/message/*`。
- 旧设计文档中的 `/miniapp/messages/home`、`/miniapp/messages/conversations`、`/miniapp/messages/send` 等复数路径为废弃口径，不作为兼容接口实现。
- 若已有外部调用方依赖旧路径，必须先登记调用量、给出迁移窗口和明确下线日期；不得让新旧路径长期承载不同语义。
- 契约字段的新增应保持向后兼容；枚举新增时客户端按未知状态降级，删除/改名必须提升契约版本。
