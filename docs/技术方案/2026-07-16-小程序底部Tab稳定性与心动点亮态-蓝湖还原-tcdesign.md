# 小程序底部 Tab 稳定性与心动点亮态蓝湖还原技术方案

## 范围与基线

- 页面范围：小程序全局自定义底部 TabBar，覆盖千寻、心动、推荐、消息、我的五个入口。
- 设计来源：蓝湖项目“时空邂逅0625”，页面“心动-对我心动未开通会员”（设计 ID：`d8b96542-0e30-42e8-9a6a-d3f331928673`）。
- 目标视口：蓝湖原图 1500×3248，对应小程序 375×812；底部图标保留 4x 像素密度。
- 验收阈值：底部栏关键交互与点亮态不低于 97%。

## 根因证据

1. 心动点亮态当前引用 `tab-work-active.svg`，文件内容实际是公文包图形；蓝湖基线是心电爱心黑色线框与右上蓝色圆形高光。
2. 自定义 TabBar 使用模块级 `pendingActiveKey` 覆盖当前路由；快速连续点击时会并发触发多个 `switchTab`，旧页面生命周期回调还能清理或覆盖新目标状态，最终表现为页面乱跳和点亮态回退。
3. 跳转失败只回滚组件状态，未同步清理模块级 pending 状态，后续页面仍可能读取错误目标。

## Token 与组件映射

| 设计元素 | 项目落点 |
|---|---|
| 心动普通态 | `src/assets/icons/tab-work.png`，80×70 PNG |
| 心动点亮态 | 从蓝湖原图坐标 x=396、y=3054 无损裁切 80×70 PNG |
| 点亮文字 | `#333333`、20rpx、500 |
| 未点亮文字 | `#999999`、20rpx |
| 导航互斥 | `AppTabBar` 同步 `useRef` 锁，单次只允许一个 `switchTab` |
| 路由真值 | `getCurrentPages()` 当前路由；仅保留最后一次已确认的 Tab，不保留跨页面 pending 目标 |

## 实现与验证

1. 先扩充静态门禁，确保错误素材、并发跳转和跨页面 pending 状态能够稳定失败。
2. 从蓝湖 4x 原图无损提取心动点亮态，保留包内资源。
3. 导航开始前同步加锁，成功后由真实路由确认选中态；失败时回滚，最终释放锁。
4. 构建开发固定登录产物，在微信开发者工具中依次点击五个 Tab，并补充快速连续点击回归。
5. 输出截图证据、差异清单与验收评分。
