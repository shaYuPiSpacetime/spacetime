## 3. 本轮修正

1. 统一普通私信和悄悄话的腾讯云 TIM 职责，删除平台自建普通私信发送、历史和已读游标口径。
2. 明确平台和 TIM 均不做本期日常文本内容审核，举报仍走 PRD-05 平台接口。
3. 修正普通私信未读算法，只统计平台返回的有效 TIM 会话映射，避免隐藏或失效会话污染角标。
4. 将悄悄话回复改为状态迁移和唯一会话复用，补齐 TIM 与 MySQL 不能物理同事务时的幂等、补偿和半状态隐藏策略。
5. 对齐 PRD-02 的匹配事务边界及 PRD-05 的聊天举报上下文字段。
6. 将后台正文访问限制为有效案件证据，删除全局正文查看能力；没有正式风控案件事实源时保持 fail closed。
7. 统一一期 7 个有效页面和移动端接口清单，并修正公共定义审计示例中的旧 `/api/app/...` 路径。
8. 将旧 Mock、旧蓝湖方案和 2026-07-14 接口契约标记为历史归档。
9. 按 2026-08-07 最终确认，将普通私信、悄悄话申请和回复的完整明文统一写入 `app_message_record.content_text`；普通移动端和管理后台接口均不返回正文或内容摘要，举报案件从主表优先固化证据。
10. 按 2026-08-10 确认保留 14 张表，并修正三项结构问题：正文到期只清空 `content_text` 且保留消息事实；删除悄悄话表重复 TIM 字段；为 Inbox 临时载荷增加禁止正文、终态清空和到期清理规则。

## 4. 保留边界

当前口径是 TIM 漫游消息至少保留 180 天，按每条消息发送时间计算；平台消息主表同时保存完整日常
聊天明文。关系解除、拉黑或注销后，正文立即退出普通产品入口并隔离保留 180 天，再由合规清理任务
把消息主表 `content_text` 置空并记录 `content_cleared_at`；消息编号、状态、来源及唯一 TIM 映射继续
保留。举报证据按案件留存规则独立保存。普通查询、搜索、导出和日志均不得访问正文列。
