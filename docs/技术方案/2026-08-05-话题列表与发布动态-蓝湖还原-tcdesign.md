# 2026-08-05 话题列表与发布动态蓝湖还原技术方案

## 1. 范围

- 小程序页面：`/pages/qianxun/topics`、`/pages/qianxun/compose`。
- 设计基线：千寻 66 稿 `031.png`（社区话题列表）、`013.png`（发布动态默认态）、`020.png`（单图态）、`191.png`（话题选中态）及 `分组总览-06-publish.png`。
- 目标视口：设计稿 375×812；运行态补充验证 390×844。
- 本次不改变社区接口、图片上传、草稿和发布审核协议。

## 2. 根因

`topics.tsx` 已绘制统一 `NativeNavigation`，但缺少 `topics.config.ts`。页面继承 `app.config.ts` 的系统标题“成家立业”，微信同时渲染系统返回箭头，最终与页面的“社区话题”标题和统一返回箭头叠加。

发布动态页的主要偏差来自展示层：工具栏以 `▧`、`▻`、`☺` 字符代替设计图标；空白态提前显示加图方块；工具栏显示蓝湖不存在的 `0/9`；运行配置加载后自动选择第一个话题，导致默认态无法呈现“添加话题”。

## 3. 设计基线与组件映射

| 设计元素 | 基线 | 实现落点 |
|---|---|---|
| 二级页导航 | 单返回箭头、居中业务标题、原生胶囊由微信绘制 | `NativeNavigation` + `navigationStyle: 'custom'` |
| 默认正文区 | 占位文案“记录生活，展现真实的你”，空白态无加图方块 | `Textarea` + 条件图片网格 |
| 图片网格 | 3 列、圆角图片、右上关闭；已有图片且不足上限才显示加图 | `UploadImage[]` + View 图形加号/关闭 |
| 话题胶囊 | 蓝色圆形 `#`、添加态箭头、选中态关闭 | `TopicChip` + `TopicTrailingIcon` |
| 底部工具栏 | 图片、视频、表情三个线性图标；图片/视频含蓝色点缀 | `ComposePhotoIcon`、`ComposeVideoIcon`、`ComposeSmileIcon` |
| 发布按钮 | 禁用灰、可发布蓝 | 保留现有 `canPublish` 状态 |

图标全部由可见 `View` 图形组成，点击区域与真实图标容器一致；未使用整页截图、透明热区、字体符号或蓝湖远程资源。

## 4. 实施

1. 新增 `miniapp/src/pages/qianxun/topics.config.ts`，设置 `navigationStyle: 'custom'`。
2. `compose.tsx` 不再从 `runtime.topics[0]` 自动选择默认话题，只恢复路由带入或服务端草稿中的话题。
3. 空白态隐藏加图方块；有图且未达上限时显示真实加号组件。
4. 用线性图形组件替换图片、视频、表情、删除字符图标，移除图片数量计数。
5. 为关键图标补充稳定 `id`/`data-role`，用于微信运行态验收。

## 5. 回归门禁

- `miniapp/scripts/validate-qianxun-topic-demo-closure.mjs`：配置、默认态、图标与禁止字符占位检查。
- `miniapp/scripts/verify-topic-list-compose-ui-runtime.cjs`：编译产物导航配置、两个页面根节点、发布工具图标和截图证据。
- 正式构建：`npm --prefix miniapp run build:weapp`。

## 6. 风险控制

- 不改接口 payload、上传流程、草稿防抖与发布状态机。
- 服务端已有草稿时仍按产品规则恢复；因此运行截图使用单图草稿态，同时默认空白态由源码门禁锁定。
- 工作区其他关系反馈改动保持原样，不纳入本次修改。
