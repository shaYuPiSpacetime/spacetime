# PRD-07 邀请首页 UI 还原技术说明

> 日期：2026-07-27  
> 范围：PRD-07 普通用户移动端邀请首页及静态 Demo  
> 设计基线：`docs/静态Demo/07-推广裂变与邀请奖励/设计基线/PRD-07-01-移动端邀请首页-UI基线.png`

## 1. 目标与边界

本次以用户确认的 UI 稿为唯一视觉基线，更新普通用户邀请首页的需求文档和静态 Demo。邀请记录页、邀请规则 H5、分享弹层、校园代理二维码和管理后台不重构，只保证既有导航继续可用。

首页删除普通用户二维码、邀请码、保存二维码和“千寻币能做什么”；新增注册奖励解释、全量阶梯进度和最近邀请记录。阶梯人数与金额均读取已发布规则，设计稿中的 5/+50、10/+100、20/+200 只是当前演示数据。

## 2. 页面结构映射

| 设计区块 | 运行态组件 | 数据来源 | 交互 |
|---|---|---|---|
| 紫色活动主视觉 | `.ui-invite-hero` | 固定运营文案 | 无 |
| 人物插画 | 裁切 `<img>` | 已确认 UI 基线中的非交互插画区域 | 无 |
| 邀请注册得千寻币 | `.ui-reward-card` | 完成注册奖励配置 | 立即邀请、活动说明 |
| 邀请进度 | `.ui-progress-card` | 首页聚合接口与当前阶梯配置 | 无 |
| 邀请记录 | `.ui-record-card` | 最近三条成功邀请 | 查看全部 |
| 邀请规则 | `.ui-rules-card` | 固定业务口径摘要 | 活动说明进入规则 H5 |
| 分享弹层 | 复用 `.mobile-sheet` | 分享上下文 | 微信好友、朋友圈、复制链接 |

## 3. 数据模型

静态 Demo 使用以下首页结构模拟 `/api/promotion/invite/home`：

```js
{
  registerReward: 20,
  successCount: 10,
  rewardTotal: 330,
  currentLadderCount: 10,
  maxLadderCount: 20,
  ladders: [
    { count: 5, amount: 50, achieved: true },
    { count: 10, amount: 100, achieved: true },
    { count: 20, amount: 200, achieved: false }
  ],
  recentInvites: []
}
```

生产接口不得写死档位数量、阈值和金额；客户端按数组完整渲染，以最大启用阈值计算总进度。最近邀请最多展示三条，更多记录由记录页承接。

## 4. 状态与降级

| 状态 | 首页表现 | 可执行操作 |
|---|---|---|
| 正常 | 展示汇总、全量阶梯和最近三条记录 | 邀请、规则、查看全部 |
| 加载中 | 卡片骨架占位，避免旧数据闪烁 | 返回 |
| 无邀请记录 | 汇总与阶梯仍展示，记录卡显示空态 | 立即邀请 |
| 网络错误 | 展示错误卡和重试，保留页面框架 | 重试 |
| 分享不可用 | 首页数据正常；点击立即邀请时复制邀请链接 | 复制后 Toast |

邀请规则 H5 的缓存与不可用态沿用现有定义，不属于首页视觉重构。

## 5. 视觉与资产策略

- 页面宽度以现有 390px 演示机型为基准，使用紫色渐变、白色圆角卡片和浅紫标题签。
- 标题、数字、按钮、进度线、图标和链接全部使用真实 DOM/CSS，不将交互控件烘焙进图片。
- 由于原始插画切图未单独提供，人物部分从已确认基线图中以 `<img>` + `overflow:hidden` 方式裁切，只承担非交互装饰；后续拿到无损原图时可等位替换。
- 最近邀请头像使用项目内已有无损图片，不新增外部 URL 或敏感信息。

## 7. 验收

1. 首页不存在普通用户二维码、邀请码、保存二维码和千寻币用途区。
2. 注册奖励、累计成功、累计到账、全量阶梯、最近三条记录均由 Mock 数据渲染。
3. “立即邀请”“活动说明”“查看全部”可用，分享不可用时能复制链接。
4. 加载、空记录、网络错误和分享不可用状态可切换。
5. 静态门禁、浏览器脚本和 `git diff --check` 通过；验收报告保存截图证据与差异结论。
