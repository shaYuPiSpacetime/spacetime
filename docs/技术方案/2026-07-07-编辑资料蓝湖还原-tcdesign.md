# 编辑资料蓝湖还原技术方案

## 设计原则

1. 蓝湖整页图只进入 `.lanhu-ref` 做视觉参考，运行页面必须组件化。
2. 页面数据继续走 `lanhuDemo` 结构化 mock，后续接后台只替换数据来源。
3. 从编辑资料跳出的页面使用 `Taro.navigateBack` 返回，失败才兜底回编辑资料页。
4. 静态脚本先约束路由、页面源码证据和资产清单，再做实现。

## 页面改造

- `/pages/verification/my-certification`：新增我的认证页，复用三项认证切图，展示头像、实名、学历认证结果。
- `/pages/profile/edit`：更新认证入口改为我的认证；语音介绍改为页内底部弹窗，覆盖录制、播放、完成、退出、删除、删除成功状态。
- `/pages/profile-edit/about`：增加顶部 tab，`topic=meet` 仅作为初始 tab。
- `/pages/profile-edit/tags`：顶部分类 tab、三列标签墙、底部已添加面板。
- `/pages/profile-edit/songs`：搜索框、歌曲列表、添加成功轻提示，不再 `redirectTo`。

## 数据与资产

- `lanhuDemo.json` 总数更新为 93，补齐两张“切图”参考稿记录。
- 语音相关 route 改为 `/pages/profile/edit?voice=...`。
- “我的认证” route 改为 `/pages/verification/my-certification`。
- 全量参考库固定在 `miniapp/.lanhu-ref/lanhu-full-2026-07-07/`。

## 静态门禁

- `validate-lanhu-full-assets.mjs` 校验 93 张参考图和报告文件。
- `validate-profile-guest-ui-coverage.mjs` 校验 profile、语音弹窗和我的认证映射。
- `validate-verification-profile-ui.mjs` 禁止旧弹窗、旧语音独立页入口和破坏返回栈的 profile-edit redirect。
- `validate-lanhu-demo-data.mjs` 校验 93 张 manifest 与注册路由。
