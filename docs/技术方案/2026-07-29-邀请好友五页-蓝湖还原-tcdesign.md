# 邀请好友五页蓝湖还原技术方案

> 日期：2026-07-29  
> 范围：`miniapp/src/pages/promotion/`  
> 设计源：蓝湖项目“时空邂逅0625”中的“邀请好友”组  
> 结论：保留接口和业务逻辑，重构三个小程序路由的视觉层与记录展示模型。

## 2. 现状差异与处理结论

| 区域 | 现状 | 蓝湖要求 | 处理 |
|---|---|---|---|
| 首页主视觉 | 旧插画、字号偏小、背景层次不同 | 指定扁平人物插画、描边主标题、纵向紫色渐变 | 重构 |
| 首页卡片 | 高度、圆角、标题帽、间距均不同 | 350 宽双层白卡、12 圆角、固定区块高度 | 重构 |
| 首页状态 | 仅通用空态 | 独立无记录稿和完成 20 人后续阶梯稿 | 数据驱动补齐 |
| 邀请记录 | 四筛选、关系卡片、展开明细 | 紫色汇总头+扁平奖励时间流 | 重构展示层，保留分页/刷新 |
| 活动说明 | 通用 H5 卡片 | 白底深蓝原生说明页 | 重构容器，保留 H5/缓存链路 |
| 业务接口 | 已实现 | 继续使用真实数据 | 保留 |

因此不推翻 PRD-07 服务和归因实现，只重写视觉组件树、SCSS 和记录页数据适配。

## 3. 页面数据映射

### 3.1 邀请首页

- `registerReward`：奖励卡“获得 N 千寻币”。
- `successCount`：累计邀请成功。
- `paidRewardTotal`：累计到账。
- `progressCurrent/progressMax/ladders`：进度标题、轨道和三个或更多动态档位。
- `recentRecords`：最多三条首页邀请记录；空数组渲染蓝湖空态插画。
- `shareContext`：微信分享和复制链接降级，不进入视觉硬编码。

“完成 20 人”画板只作为达成阶段样例。运行时不写死 20/40 或 25/30/40；当后台发布这些后续阶梯时，由返回数组自然呈现。

### 3.2 邀请记录

记录页并行读取：

- `getInviteHome()`：顶部汇总；
- `getInviteRecords()`：分页关系与 `rewardItems`。

展示前转换为扁平行：

1. 注册基础奖励使用好友头像/昵称；
2. `ladder_bonus` 使用独立礼物图标和“额外奖励”标题；
3. 其他奖励事件使用服务端 `eventLabel`；
4. 金额、时间、状态全部来自接口，不写死蓝湖样例。

### 3.3 活动说明

- 优先展示 PRD-06 返回的安全 `htmlSnapshot`；
- 仅返回 HTTPS 地址时使用 `WebView`；
- 当前版本失败时使用最近成功缓存；
- 当前和缓存均不可用时展示真实错误态和重试按钮。

导航与容器视觉按“活动说明”画板统一，正文不由客户端拼接实际奖励规则。

## 4. 视觉实现约束

1. 页面背景使用 `#AC7EFB -> #7C66D4` 纵向渐变。
2. 首页卡片外层为 350×动态高度，内层左右各内收 3px、上下内收 5px；圆角按 Sketch 24px 除以 2。
3. 标题帽、按钮、进度轨道、列表和规则正文全部使用真实 `View/Text/Button/Image`。
4. 蓝湖原图只裁切人物与空态插画；禁止将文案、按钮、导航和列表烘焙到图片。
5. 非底部静态图标优先原字节上传 OSS；本次测试环境缺少 `DEV_OSS_*` 上传参数，因此小型功能图标使用真实 DOM/CSS 原生绘制，未新增本地图标引用，也未伪造 OSS 上传结果。
6. 所有 CSS 继续使用 375 设计宽度的 `px`，避免 H5 被 `rpx` 放大。

## 5. 交互与异常

- “立即邀请”继续使用 `openType="share"`；能力不可用时复制可归因链接。
- “活动说明”“查看全部”继续真实导航。
- 返回按钮继续使用 `NativeNavigation`，无历史栈按原兜底路由处理。
- 加载、错误、空态、下拉刷新、触底分页和规则缓存提示均保留。
- 不添加透明热区、零透明度元素或背景截图按钮。

## 6. 验收

主基线按蓝湖 750 宽画板等比映射到 375 逻辑宽度；首页长图为 375×1256，记录页和活动说明页为 375×812。逐页评分：

- 结构层级 20；
- 尺寸位置 20；
- 字体/颜色/圆角/阴影 20；
- 素材 15；
- 交互 15；
- 适配与安全区 10。

低于 97 分不得交付；存在蓝湖源数据缺口时必须在验收报告登记，不得声称百分百。
