# 敏感词管理与前置机审实施方案

> 用户已确认：独立敏感词模块，增删查改，不做批量导入；按 Vocabulary.7z 原文件分类初始化；本地不通过与微信不通过走相同流程。

## 范围与契约

- 词条按附件 18 个原始文件分类，分类名称保持原样（页面省略扩展名），代码枚举提供稳定分类编码；同词跨分类保留，文件内重复去除。初始化 76,702 条分类词记录，对应 51,344 个原文词。
- 所有初始化词启用，本地命中返回 REJECT，不新增复核策略。原有资料、动态、诚意贴、评论各自的驳回状态和 C 端回执保持一致。
- 用户已补充确认：仅走微信内容审核的文字前置本地词库。图文先校验正文；图片、语音保持原微信审核，不做 OCR/ASR。
- 无批量导入、导出、规则审批或新复审流程。初始化是部署迁移，不提供上传接口。
- 匹配：词条和待审文字统一 NFKC、Locale.ROOT 小写，按字面子串匹配，不执行正则，不删除内部空格或标点。先匹配的词立即拒绝；后台维护和证据保留原词及分类。图片 URL 不作为文本词库的审核内容。
- 新增词条表 `content_sensitive_word`；字段 id/category_code/word/status/source_file/source_key/remark/version 和 BaseEntity 审计字段。word 上限 256 字符。`active_marker` 为未删除记录生成 1，删除记录生成 NULL，唯一索引 `(category_code,word,active_marker)` 允许删除后新增。source_key 为初始化原分类+原词的 SHA-256，唯一且修改/删除后保留，重复初始化不会覆盖人工修改或复活已删除词。
- 单行版本表 `content_sensitive_word_revision`，每次 CRUD 在同一事务递增 revision。匹配索引缓存于服务内存，每次文字校验读取轻量版本；版本变更后完整重建并原子替换。构建前后版本不一致时重新读取，重试仍失败按内容安全不可用处理，不放行微信。
- 公共 matcher/DAO 位于 common；管理服务位于 admin，严格六层；Controller 返回 R<T>。分类为固定代码枚举，首期无分类维护接口。
- 直接在唯一实际微信适配器的 checkText 前置本地服务，覆盖资料 TextSafetyProvider 及社区 checkText/checkPost。空文本沿用原逻辑。没有命中继续微信；本地词库异常返回 UNAVAILABLE，沿用各业务异常路径。
- 本地拒绝使用 `local_sensitive_word:<id>` 机审码与结构化命中证据；Provider 映射来源为 `local-sensitive-word`，对用户的拒绝原因保持普通审核失败文案，不能暴露内部词库。审核来源依旧 MACHINE。

## API 与前端

页面 `/moderation/sensitive-words`，菜单「敏感词管理」。权限前缀 `moderation:sensitive-word`。

| Method/URL | 权限后缀 | 入参 | 返回 |
| --- | --- | --- | --- |
| GET /admin/sensitive-words | list | page,size,keyword,categoryCode,status | R<Page<SensitiveWordVO>> |
| GET /admin/sensitive-words/categories | list | 无 | R<List<SensitiveWordCategoryVO>> |
| GET /admin/sensitive-words/{id} | list | id | R<SensitiveWordVO> |
| POST /admin/sensitive-words | add | word,categoryCode,status,remark | R<Long> |
| PUT /admin/sensitive-words/{id} | edit | word,categoryCode,status,remark,version | R<Void> |
| DELETE /admin/sensitive-words/{id} | delete | id,version(query) | R<Void> |

SensitiveWordVO：id,word,categoryCode,categoryName,status,remark,sourceFile,createTime,updateTime,version。分类 VO：code,name。status 为 ENABLED/DISABLED；version 非负。查询 size 最大 100。新增和修改检查分类、长度、空白及同分类重复词；修改与删除使用版本 CAS，冲突返回可读业务提示。

前端使用现有 Card/Table/Dialog/Select/Pagination；支持关键词、分类和状态筛选，新增/编辑/删除确认，按钮权限。服务端状态放 Hook，API 位于 frontend/src/api/，页面不直调 request。无权限不加载词库。
