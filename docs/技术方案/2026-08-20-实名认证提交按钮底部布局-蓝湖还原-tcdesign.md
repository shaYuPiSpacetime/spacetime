# 实名认证提交按钮底部布局技术方案

## 1. 范围与基线

| 项目 | 内容 |
|---|---|
| 页面 | `APP-01-PAGE-real-name` 实名认证页 |
| 端 | 微信小程序（Taro 4 + React） |
| 路由 | `/pages/verification/real-name` |
| 设计来源 | 用户提供的运行态截图 |
| 基线状态 | 未提交、表单为空、协议已勾选、提交按钮禁用 |
| 目标 | 将错误出现在导航下方的提交按钮移动到页面底部安全区上方 |

本次仅修复提交按钮的布局位置，不调整标题、状态标签、表单、协议与客服入口的既有视觉参数。

## 2. 问题定位

实名认证页原先使用 `EducationVerificationShared.SubmitButton`。该组件采用绝对定位并要求传入 `top`，但实名认证页调用时未提供 `top`。运行态因此无法得到按钮纵坐标，按钮出现在导航下方并遮挡标题区域。

## 3. 实现方案

1. 为 `VerificationSubShell` 增加可选 `bottomAction` 插槽，并在滚动区外渲染。
2. 实名认证页改用项目已有的 `VerificationBottomAction`：
   - `position: fixed`；
   - 左右各 `25rpx`；
   - 高度 `98rpx`；
   - 距底部 `24rpx + env(safe-area-inset-bottom)`；
   - `z-index: 20`，避免被滚动内容遮挡。
3. 页面存在底部操作区时，滚动内容增加 `220rpx` 底部留白，避免长内容被按钮覆盖。
4. 保留原业务行为：
   - 表单未完成时展示禁用色；
   - 提交中展示“提交中”；
   - 未勾选协议时点击禁用按钮仍进入原校验提示；
   - `canSubmit === false` 时不展示按钮；
   - 点击后仍调用原 `handleSubmit`，不改变接口与跳转链路。

## 4. 组件映射

| 页面元素 | 项目组件/实现 |
|---|---|
| 页面滚动容器 | `VerificationSubShell` |
| 底部提交按钮 | `VerificationBottomAction` |
| 禁用态 | `active={false}`，背景 `#C9DDF7` |
| 启用态 | `active={true}`，背景 `#2876FF` |
| 安全区 | `env(safe-area-inset-bottom)` |
| 点击标识 | `real-name-submit-button` |

## 5. 回归门禁

在 `miniapp/scripts/validate-verification-profile-ui.mjs` 增加以下检查：

- 实名页必须通过 `bottomAction` 渲染提交按钮；
- 必须复用 `VerificationBottomAction`；
- 禁止重新引入未传纵坐标的 `SubmitButton`；
- 必须保留真实按钮组件 ID；
- 底部操作区必须渲染在滚动区之外。

## 6. 验证方式

1. 运行认证 UI 静态门禁。
2. 运行认证流程 Node 测试。
3. 编译微信小程序产物，并检查实名认证产物包含真实按钮 ID 与底部操作组件。
4. 本机安装微信开发者工具后，以 375×812 和 414×896 两档补充运行态截图。
