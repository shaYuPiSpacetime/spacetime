# 邀请首页蓝湖切图修正技术说明

## 1. 变更范围

- 仅修改小程序 `/pages/promotion/invite-home` 的展示层与相关静态门禁。
- 不修改邀请记录页、活动说明页、HTTP API、分享归因和邀请业务类型。
- 注册奖励金额、邀请人数、累计到账与阶梯档位继续使用接口返回值。

## 3. 实现方案

### 3.1 背景

- `miniappOssIcons.promotionInviteBackground` 作为页面底层绝对定位图片，运行尺寸 375×1256。
- 背景仅承载顶部非交互品牌文案和人物插画。
- 导航、白卡、动态数据、按钮与入口继续由真实组件绘制并绑定事件。
- 删除原 CSS 描边标题、货币水印和独立人物图，避免微信端文字重影。

### 3.2 奖励图标组

- `miniappOssIcons.promotionInviteEquationSprite` 保留为无损整图。
- 页面创建三个独立 44×44 `Image` 裁窗，分别显示分享、用户、千寻币图标。
- `＋`、`＝`、标签和动态奖励金额均为真实文本。
- 删除字符箭头以及 CSS 手绘人物、货币图标。

### 3.3 阶梯坐标

当前阶段的每个节点新增内部展示字段 `positionPercent`：

```text
positionPercent = clamp((threshold - stageBase) / (stageMax - stageBase) × 100, 0, 100)
```

进度条采用相同的阶段基线和跨度。轨道、填充条与节点容器共享同一左右 inset，避免 10/30/50 或跨阶段动态档位被等分布局后错位。

### 3.4 滚动导航

- 顶部导航在首屏保持透明，与蓝湖主视觉融合。
- 监听首页 `ScrollView` 的滚动位置；超过 8px 后切换为实色紫色背景，遮挡继续上移的卡片内容。
- 状态仅在透明/实色边界变化时更新，避免滚动过程频繁重复渲染。
- 静态门禁同时约束滚动监听、事件绑定和背景切换，防止卡片标题与导航标题再次重叠。

### 3.5 阶梯纵向对齐

- 奖励胶囊高度为 19px，轨道高度为 5px，两者共用距阶梯顶部 9.5px 的垂直中心线。
- 轨道 `top` 设为 7px，中心为 `7 + 5 / 2 = 9.5px`；奖励胶囊中心为 `19 / 2 = 9.5px`。
- 三个奖励胶囊、轨道和紫色起点保持同一中心线；“完成 N 人”标签的纵向位置不变。
- 静态门禁同时约束 19px 胶囊和 `top: 7px / height: 5px` 轨道，防止后续样式调整再次错位。

## 4. 资源与安全约束

- 客户端只引用 `miniapp/src/constants/ossIcons.ts` 中的公网 URL。
- 不使用蓝湖 CDN、本地运行时回退、图片转换、压缩、缩放后上传或 CDN 图片处理参数。
- 上传后重新下载对象，按 SHA-256 和字节数核对原字节一致性。
- 背景设置 `pointer-events: none`，不存在透明热区。

## 5. 测试策略

- 单元测试覆盖 10/30/50、跨阶段、上下边界和空档位。
- 静态门禁校验两个 OSS 键、三个独立 sprite 引用、无 CSS 手绘图标、无重影标题、无蓝湖 CDN，并验证阶梯共享坐标和滚动导航遮挡。
- 构建覆盖 H5 和微信小程序；运行态按 375×812 验证滚动、活动说明入口、立即邀请与动态金额。
- 截图、差异清单、哈希证据和还原度评分统一记录在本次验收报告及证据目录。
