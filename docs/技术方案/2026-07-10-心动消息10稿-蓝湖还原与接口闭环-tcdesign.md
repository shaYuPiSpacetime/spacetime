## 5. 第一阶段交互闭环

1. 消息页“查看全部申请”进入相互喜欢列表。
2. 相互喜欢列表“查看主页”进入用户主页。
3. 未认证消息页“去认证”进入三重认证流程。
4. 心动页顶部 Tab 可切换“对我心动/访客”。
5. 非会员点击模糊人物卡，打开“解锁Ta是谁”。
6. “只看ta(100千寻币)”进入“解锁成功”状态。
7. 解锁成功后“查看主页”进入用户主页。
8. “解锁全部/解锁全部访客/开通会员”进入会员中心。
9. 用户主页“免费开聊”显示 Demo 成功反馈。
10. 底部心动、消息、推荐、千寻、我的保持真实 Tab 切换。

### 6.2 页面聚合接口

为避免一个页面串行请求 3 个以上接口造成明显卡顿，心动和消息首屏各使用一个聚合接口。聚合服务内部必须批量查询，不允许按用户逐条查询资料形成 N+1。

| 接口 | 状态 | 用途 | 性能门槛 |
| --- | --- | --- | --- |
| `GET /miniapp/heart/home?tab=likes|visitors&page=1&size=20` | 需新增 | 心动首屏、会员态、统计、人物卡分页 | 测试环境 P95 <= 300ms |
| ~~`GET /miniapp/messages/home?page=1&size=20`~~ | 已废弃 | 历史消息首页口径；由 `GET /miniapp/message/home` 及新契约取代 | 不再实施 |

## 7. 数据库与索引要求

建议新增或确认以下业务表：

| 表 | 用途 | 关键索引 |
| --- | --- | --- |
| `user_like_relation` | 谁喜欢谁、是否互相喜欢 | `(target_user_id, status, create_time DESC)`；唯一 `(user_id, target_user_id)` |
| `user_profile_visit` | 最近访客、今日访客、浏览量 | `(target_user_id, visit_time DESC)`；`(visitor_user_id, target_user_id, visit_date)` |
| `message_conversation` | 会话主表 | `(last_message_time DESC)` |
| `message_conversation_member` | 用户会话关系、未读数 | 唯一 `(conversation_id, user_id)`；`(user_id, unread_count, update_time DESC)` |
| `message_record` | 消息记录 | `(conversation_id, id DESC)`；唯一 `(sender_id, client_msg_id)` |
| `user_unlock_record` | 已存在，单人解锁 | `(user_id, unlock_scene, target_user_id, status, expire_time)`；`(user_id, request_id, status)` |

聚合查询要求：

1. 心动列表先分页取关系 ID，再批量读取用户公开资料和解锁状态。
2. 消息首页一次读取会话分页和未读摘要，批量补头像，不按会话逐条查用户。
3. 今日统计使用时间范围查询，禁止对时间列包 `DATE()` 导致索引失效。
4. 列表必须稳定排序，推荐 `create_time DESC, id DESC`，翻页数据不得重复或丢失。
5. 记录浏览事件可异步写入，但页面展示统计必须允许短暂最终一致。

## 8. 第二阶段前端改造清单

1. 新增 `types/heart.ts`、`types/message.ts`。
2. 新增 `services/heart.ts`、`services/message.ts`，统一经 `services/request.ts`。
3. 心动页首屏只调用 `heart/home`；消息页首屏使用新契约 `GET /miniapp/message/home`，不得再调用已废弃的 `messages/home`。
4. `Promise.all` 仅用于互不依赖的辅助请求，禁止串行请求 VIP、统计、列表。
5. 替换页面内 Demo 数组，但保留同一视图组件和同一空态/错误态容器。
6. 解锁请求必须传 `requestId`，防止超时重试重复扣币。
7. 解锁成功后用接口返回余额和目标 ID 局部更新卡片；字段不足时再刷新 `heart/home`。
8. 未认证按钮继续进入 `/pages/verification/triple`。
9. 接口 `401` 统一走固定登录/正式登录逻辑，不在页面重复处理。
10. 增加接口合同测试、慢查询检查和 10 状态微信截图回归。

## 9. 第二阶段验收门禁

| 维度 | 通过标准 |
| --- | --- |
| 视觉 | 10 张稿现有截图基线无回归，关键首屏 >= 97% |
| 数据 | 关闭 Demo 后 10 状态均由真实接口驱动 |
| 隐私 | 非会员响应不包含清晰可识别资料 |
| 幂等 | 相同 `requestId` 重试不重复扣币、不重复发消息 |
| 性能 | `heart/home`、`message/home` 测试环境 P95 <= 300ms |
| 分页 | 连续翻页无重复、无漏项、排序稳定 |
| 未读 | 进入会话后角标清零，返回消息首页一致 |
| 解锁 | 成功扣币、流水、解锁记录、清晰资料同步闭环 |
| 会员 | 会员开通后返回心动页立即显示清晰资料 |
| 构建 | 微信小程序编译通过，新增单资源 < 200KB |
