# 登录出生日期选择器蓝湖还原技术方案

## 1. 范围与基线

- 页面：首次登录资料填写第 2 步，出生日期选择页。
- 目标端：Taro 4.1 微信小程序。
- 蓝湖项目：`时空邂逅0625`。
- 蓝湖稿件：`登录-年龄选择`，`image_id=4ca59342-02bc-4052-b553-0baca9dbd8c9`。
- 蓝湖地址：<https://lanhuapp.com/web/#/item/project/detailDetach?tid=428e8368-c279-4369-947b-a5828487924d&pid=d9c9e50f-fee5-47ca-bd6b-ae05c0d5332b&project_id=d9c9e50f-fee5-47ca-bd6b-ae05c0d5332b&image_id=4ca59342-02bc-4052-b553-0baca9dbd8c9&fromEditor=true&type=set>。
- 原图：`1500×3248`，按项目单位归一为 `750×1624rpx`。
- 验收目标：选择器关键几何误差不超过 `2rpx`；年、月、日均为真实可滑动列。

## 3. 组件与交互架构

1. 使用一个 Taro `PickerView` 和三个 `PickerViewColumn`，分别承载年、月、日。
2. 原生组件继续负责触摸、惯性、吸附和每列值变更，不使用透明热区或截图伪交互。
3. 蓝湖五行透视通过选中项距离和方向类控制：选中、相邻、远端三档；五行以外使用 `visibility: hidden`，保留原生列表布局。
4. 微信基础库 `3.16.1` 会在原生内部绘制两条指示线，`indicator-style` 与 `indicator-class` 均无法覆盖。选中面上增加两条 `#E3F1FE` 实体覆盖层，位置为 `152rpx / 217rpx`，`pointer-events: none`，仅遮盖原生线且不拦截滑动。
5. 页面复用 `LoginProfileShell`，不修改返回、标题、说明和底部下一步按钮。

## 4. 日期数据规则

1. 年份由后端运行时年龄范围转换；月份固定为 1—12 月。
2. 日期列按选中年月动态生成 28/29/30/31 天。
3. 年月变化导致日期失效时，自动收敛到当前月最后一天，例如 `2023-01-31 -> 2023-02-28`。
4. 已有生日支持 `yyyy-MM-dd` 与 `yyyy/MM/dd` 回显；异常索引统一修正。
5. 提交协议保持 `saveInitStep(2, { birthday })`，日期格式保持 `yyyy-MM-dd`。

## 5. 测试与门禁

- 领域测试：闰年、平年、30 天月份、索引收敛、日期格式化。
- 结构门禁：必须包含 1 个 `PickerView`、3 个 `PickerViewColumn`，禁止退回单值 `Picker` 或静态点击行。
- 视觉门禁：固定选中框、五行透视、三列中心、字号色值、原生指示线实体覆盖。
- 安全门禁：覆盖层必须 `pointer-events: none`；五行之外使用 `visibility: hidden`，不得使用透明热区。
- 构建：`npm --prefix miniapp run build:weapp`，并执行页面注册、固定登录产物与包体门禁。

## 6. 风险与边界

- iOS/Android 的原生滚动阻尼由微信控制，视觉层不修改滚动物理参数。
- 默认年份继续由年龄范围、当前年份和已有生日共同决定，不为设计示例数据硬编码 `1997`。
- 本任务不修改年龄配置、接口协议和仓库内其他未提交业务改动。

## 7. 2026-08-10 流畅度回归修正

1. 空闲态继续使用本方案第 2 节的五行位置、色值和列中心，不修改已经验收的蓝湖视觉基线。
2. 手指按下年、月或日列时，只给当前列追加 `login-age-picker__column--picking`；该列临时取消上下人工位移，并显示五行之外的滚动数据，保证惯性滚动过程中始终能看到将要选中的值。
3. 未触摸的另外两列不切换样式、不改变索引，避免滑动单列时其他列跟随位移。
4. `PickerView` 的 `pickend` 事件清除当前列状态，停止后恢复五行静态视觉；滚动物理、吸附和最终 `change` 仍完全由微信原生组件负责。
5. 不在滚动帧持续受控回写，不恢复 `top/transform` 过渡动画。
