# 登录协议与我的未认证蓝湖还原技术说明

## 1. 问题与根因

1. 登录背景使用原生 `Video`，品牌 Logo 使用 `CoverView/CoverImage`。微信原生层高于普通视图，普通协议弹窗提高 `z-index` 仍无法稳定覆盖 Logo。
2. “我的”页面此前只按认证状态隐藏徽标，未按 `coreAccessStatus` 分流，因此未完成认证也会提前进入普通个人中心。
3. 首页已经具备蓝湖“未认证/填完部分资料”节点，但“我的”没有复用，容易出现视觉与交互漂移。

## 2. 实现约束

- 协议弹窗打开时直接卸载原生 `Video` 与 `CoverView/CoverImage`；以同坐标普通 `Image` 保留暗层下的品牌背景，弹窗关闭后恢复视频。
- “我的”始终停留 `/pages/profile/index`，由页面内部按后端最新 `coreAccessStatus` 渲染对应节点，不重定向到首页。
- 首页和“我的”共用 `VerificationEntryView`，保留蓝湖 750rpx 基线、OSS 原图与真实可点击组件。
- 服务端最新准入状态返回前只展示认证节点骨架，禁止缓存状态导致普通个人中心闪现。
- 核心准入未通过时不请求会员和千寻币资产。

## 3. 状态映射

| 服务端/资料状态 | 我的页面 |
| --- | --- |
| `coreAccessStatus === CORE_ALLOWED` | 普通“我的”页面 |
| 未允许且没有认证资料 | “我的-未认证”初始节点 |
| 未允许且存在部分认证资料 | “我的-未认证-填完部分资料”节点 |
| 请求未完成 | 同一节点骨架，不闪现普通个人中心 |
| 请求失败 | 同一节点错误态，可重试 |

## 4. 验证方式

- Node 静态/TDD 回归：原生层条件、共享节点、准入分流、资产请求门禁。
- 微信开发者工具 390×844 隔离 E2E：弹窗原生层、两种未认证节点、Tab 激活、关键像素几何。
- 完整 `npm run build:weapp`：全量项目门禁、Webpack、页面注册、固定登录产物和包体。
