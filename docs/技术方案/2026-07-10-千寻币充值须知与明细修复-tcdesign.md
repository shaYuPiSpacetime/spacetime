# 2026-07-10 千寻币充值须知与明细修复技术方案

## 背景

- 充值须知弹窗与蓝湖稿 `千寻币-充值须知` 的文案、字号、间距、遮罩和圆角不一致。
- 用户充值后余额为 6000，但明细页显示空状态。

## 根因

### 明细查询被错误筛选

小程序未选择流水类型时仍传入 `flowType: undefined`。微信请求序列化后形成：

```text
GET /miniapp/coin/flows?page=1&size=20&flowType=undefined
```

后端将其作为真实条件执行 `flow_type = 'undefined'`，结果为 0 条。不带该条件时，当前用户接口返回 1 条 `+6000` 充值流水。

### 返回旧页面后未刷新

明细页原来只在 `useLoad` 中请求一次。用户从空明细页进入充值页后，原明细页保留在页面栈中；充值页的 `useCoins()` 是独立状态实例，返回旧明细页时不会再次请求，因此继续显示充值前的空数组。

### 弹窗实现偏离设计节点

原实现替换了蓝湖原文，并将圆角、标题、正文和按钮整体放大。固定 `538rpx` 高度下还有内容溢出风险。

## 设计基线

设计来源：蓝湖项目 `时空邂逅0625`，设计稿 `千寻币-充值须知`，设计 ID `3f90a2e1-4622-4668-be65-3588d5ccd6f4`。

## 实现

1. GET 请求统一剔除 `undefined`、`null` 和空字符串参数；流水接口在没有筛选值时只传 `page/size`。
2. 明细页改用 `useDidShow`，首次进入和从充值页返回时都重新拉取流水。
3. 充值须知恢复蓝湖原文，并按 MCP 节点值重建遮罩、弹窗、正文和按钮。
4. 恢复 `/pages/coins/index?variant=recharge-notice` 直达验收状态。
5. 在 `validate-coin-closure.mjs` 增加请求参数、页面生命周期和弹窗设计门禁。

## 影响范围

- 统一 GET 请求只清理无业务含义的空参数，不改变 POST/PUT/DELETE 请求体。
- 后端表结构、索引和充值入账逻辑不变；当前 6000 账户已有有效流水，无需补数据。
- 明细页每次展示增加一次流水查询，以保证资产变化后的页面一致性。

## 验证

- 回归门禁先在旧实现上失败，修复后通过。
- 浏览器请求监听确认 URL 为 `/miniapp/coin/flows?page=1&size=20`，不再携带 `flowType`。
- 微信小程序构建通过。
