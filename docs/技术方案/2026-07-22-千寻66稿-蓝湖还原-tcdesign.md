## 1. 背景与目标

蓝湖画布底部千寻业务区域共有 66 张设计稿：同一坐标带内 63 张主区域稿与 3 张延伸稿。现有小程序已实现成家首页约 10 个状态、消息与商业化的部分页面，但互动、话题、动态详情、我的动态和发布过程态未形成统一的 66 稿闭环。

本次目标：

1. 66 张设计稿全部映射到真实页面或真实交互状态。
2. 关键首屏还原度不低于 97%，页面组总体不低于 95%。
3. 可交互元素全部使用真实 `View/Text/Image/Input/Textarea/Button` 与事件，不使用整屏图或透明热区。
4. 新增非 Tab 页面、组件和专用资源全部进入分包，主包不新增重页面与本地大图。
5. 保留当前真实社区接口、认证门禁、消息与商业化链路，不恢复生产路由 mock。

## 3. 关键决策

| 类型 | 内容 | 决策 | 来源 |
|---|---|---|---|
| 范围 | “千寻66稿”的含义 | 按蓝湖坐标区域 `position_y >= 3800` 的 66 张稿件锁定，并固定 UUID | MCP 列表统计恰好 66 张；仓库既有任务采用“模块+稿数”命名 |
| 视口 | 画布尺寸 | 普通稿按 375×812；少数 419.5 高度稿按 375×839；长页按设计高度并补 375×812 首屏 | MCP width/height 与蓝湖导出图 |
| 分包 | 新页面落点 | 新增 `pages/qianxun` 分包；5 个 Tab 页面继续留主包 | 用户明确要求控制主包大小 |
| 组件 | 页面实现 | 共享视觉 token 与页面壳放千寻分包；主包成家首页只保留首屏所需实现 | 小程序上传检查规范 |
| 数据 | 生产 mock | 成家首页不允许 query variant/mock；自动截图状态仅由开发固定登录环境的 QA storage 驱动，生产构建忽略 | 既有纠偏门禁 |
| 资源 | 图标/插画 | 底部 Tab 保留包内资源；其他图标使用 `miniappOssIcons` OSS URL；整页稿只归档到验收证据 | 项目 OSS 规则 |
| lazy loading | 组件懒加载 | 不启用 `lazyCodeLoading: requiredComponents`，保持现有 Taro 自定义 TabBar 兼容门禁；通过页面分包和依赖隔离控制主包 | `validate-qianxun-family-lanhu.mjs` 现有兼容约束 |

## 8. 主包体积约束

1. 新增页面全部在 `pages/qianxun` 分包。
2. 新增页面只引用 OSS 图标与远程业务图片，不新增主包本地大图。
3. Tab 首页不得 import 分包页面组件。
4. 构建后按 `dist/app.json` 与目录归属统计主包；目标主包小于 1.5MiB。
5. 主包图片/音频目标小于 200KiB；所有单文件小于 200KiB。
6. `qianxun-center.png` 既有 526KiB 告警必须在本轮消除：改为 OSS 资源引用，避免继续进入主包。

## 11. 风险与回滚

| 风险 | 处理 |
|---|---|
| 蓝湖 MCP 层树解析部分稿件失败 | 以已下载原始截图、MCP token 与像素对比为基线并登记 |
| 关注/粉丝、我的动态接口缺口 | 不伪造生产数据；完成真实组件与空态，报告联调缺口 |

| 现有用户未提交改动 | 仅修改千寻相关文件；不触碰 `docs/需求文档/B同学分工明细.md` |
