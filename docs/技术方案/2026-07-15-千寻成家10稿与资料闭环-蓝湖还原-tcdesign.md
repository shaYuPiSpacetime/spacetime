# 千寻成家 10 稿与资料闭环蓝湖还原技术方案

## 1. 范围

本次覆盖四条真实链路：开发固定 Token 启动、编辑资料六张相册与标签、千寻成家最新十个设计状态、指定测试账号三重认证。所有枚举、提示文案、举报原因和上传限制继续由接口/字典/运行时配置提供，页面不新增业务硬编码。

## 2. 设计基线

- 画布：375×812，按 `rpx` 等比适配安全区。
- 一级导航：成家/知音/立业；成家二级导航：关注/同城/热门。
- 背景：低饱和浅蓝绿渐变；内容卡片白底、18px 圆角。
- 交互控件必须使用真实 `View/Text/Image/Textarea/Button`，插画只承载非交互内容。
- 最新十稿映射：同城长列表、热门、更多弹层、缺省插画、举报弹层、未认证弹层、同城、关注空态、关注无更新、发布动态。

## 3. 数据与状态

```text
固定开发开关 -> app.config 启动页 + app.tsx 运行态 -> 同一环境变量

CORE_ALLOWED -> 千寻/成家/关注 -> FOLLOWING 接口
                                   ├─ total > 0：关注信息流
                                   └─ total = 0：关注空态
用户点击同城 -> CITY 接口             ├─ total > 0：同城信息流
                                   └─ total = 0：同城空态
用户点击热门 -> HOT 接口 -> 话题卡 + 热门信息流
```

相册上传上限由 `prd01.upload.rules` 中 `ALBUM.maxCount=6` 提供。前端只渲染接口允许且设计需要的六个槽位；服务端保存真实 `sortOrder`，重复或非法历史顺序按稳定空槽回填，避免静默丢图。

标签统一保留 code 与 label。颜色由 code 稳定映射；容器允许标签块之间换行，标签块内部禁止拆行。

## 4. 后端契约

- `GET /miniapp/community/posts` 增加 `scene=FOLLOWING|CITY|HOT` 与可选城市条件。
- 关注场景只查当前用户有效关注对象；同城场景按当前用户资料城市；热门场景按互动量和发布时间排序。
- 作者资料统一读取 `app_user`，不再读取后台 `sys_user`。
- 发布、点赞、关注、举报继续复用现有社区接口；举报原因从字典接口读取。

## 5. 认证 SQL

SQL 严格锁定手机号唯一用户，只处理头像、实名、学历各自最新记录；材料缺失立即回滚。非通过记录先写 `app_user_audit_history`，再更新为 `APPROVED`，保证幂等与可审计。

## 6. 验收标准

- 开发监听启动不再跳登录，显式真实登录脚本仍可进入登录页，发布构建不携带固定登录。
- 六个相册槽均可上传、刷新后按原槽回显。
- 三处标签颜色一致、块级换行、文字不拆行。
- 最新十稿逐状态有 375×812 截图证据，交互元素均为真实组件。
- 指定账号接口返回三级认证成功；默认关注空态与同城分流由真实接口数量决定。
