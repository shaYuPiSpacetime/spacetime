# 商业化小程序卡片与滚动区蓝湖还原技术记录

## 范围与验收口径

- 页面：小程序 `千寻币`、`会员中心` 默认未开通态。
- 设计来源：蓝湖 MCP 项目 `时空邂逅0625`，节点 `千寻币`、`会员中心-会员未开通，支付按钮固定下方`、`会员中心-全`。
- 目标视口：蓝湖基准 `750 x 1624`，补充检查不同底部安全区设备。
- 验收门禁：关键首屏还原度不低于 97%，全部套餐可横向滚动，会员 9 项权益可纵向滚动到末项。

## 根因

1. 两页套餐标签都使用负 `top`，但横向滚动容器没有蓝湖规定的顶部留白，标签被 ScrollView 边界裁切，看起来与卡片重叠。
2. 千寻币套餐金额、原价、折扣、标签字号分别大于蓝湖标注，右侧 `¥428.00` 超出可见卡片。
3. 千寻币横轨使用 `668rpx` 宽度叠加 `-97rpx` 负边距，父卡片又设置 `overflow: hidden`，形成双重裁切。
4. 会员滚动区用固定 `328rpx` 猜测支付栏高度；支付栏同时受安全区和协议换行影响，导致滚动区在不同设备上过短或末项被遮挡。

## Token 与组件映射

| 设计元素 | 千寻币 | 会员中心 |
|---|---:|---:|
| 套餐轨道顶部留白 | `15rpx` | `16rpx` |
| 套餐卡 | `242 x 183rpx` | `220 x 248rpx` |
| 标签 | `36rpx / 16rpx` | `36rpx / 16rpx` |
| 主数量 | `26rpx` | `42rpx`，单位 `26rpx` |
| 原价 | `18rpx` | `18rpx` |
| 实付金额 | 币种 `28rpx`、数值 `38rpx` | 月均价 `26rpx` |
| 页面壳 | 导航 + 弹性 ScrollView + 普通流底部支付栏 | 同左 |

## 实现约束

- 横轨保留蓝湖“邻卡露出”提示，但通过正常宽度 ScrollView 和选中项 `scrollLeft` 定位，不再移动滚动视窗本身。
- 根容器使用 `100vh` 纵向 flex；ScrollView 使用 `flex: 1; height: 0; min-height: 0`；支付栏作为底部 flex 子项，实际高度由内容和安全区决定。
- 底部安全区使用 `max(基础留白, env(safe-area-inset-bottom))`，避免把基础留白与安全区重复相加。
- 所有按钮、协议、卡片和标签继续使用真实组件与事件，不引入整页截图或透明热区。

## 2026-07-10 会员中心修复记录

### 问题与根因

- 用户反馈“中间部分没有完全展示”。未开通会员页的 `PayBar` 使用 `position: fixed`，而上层 `ScrollView` 用 `calc(100vh - 导航 - 328rpx)` 猜测支付栏高度。协议换行和不同设备安全区会使实际支付栏高于预留值，导致最后的权益卡被遮挡或滚动区提前结束。
- 用户反馈会员卡背景与蓝湖稿不匹配。蓝湖节点 `会员中心-会员未开通，支付按钮固定下方`（`77fad5f8-086b-4f02-81f5-a356b7f69e8b`）的 MCP `slices` 返回 `totalSlices=0`；仓库内 `member-vip-bg.webp` 含旧头像和旧文案，不能作为动态会员卡背景复用。

### 修复方案

- 页面根容器改为固定视口的纵向 flex 布局；`ScrollView` 使用 `flex: 1`、`height: 0`、`minHeight: 0` 获取支付栏外的真实可用高度。
- 支付栏移回普通 flex 文档流，保留 `flexShrink: 0`；底部安全区使用 `max(30rpx, env(safe-area-inset-bottom))`，不再与基础留白重复叠加。
- 保留 `MemberHeroPattern` 作为结构化动态背景占位，不使用带静态文案的整图，也不从整页蓝湖参考图裁切热区。

### 视觉校正

- 首轮滚动修复不会改变默认首屏的排版，用户截图仍能看到旧纹理位置；因此不能以“编译成功”代替视觉验收。
- 将会员卡最左侧的菱形纹理由 `right: 256rpx` 调整为 `right: 89rpx`，使其从卡片中右区域起笔；同步移除蓝湖稿中不存在的左下暗斑，并将卡片底色统一为 `#2B2B2B`。

### 素材缺口

- 仍需设计侧补充一张无头像、无昵称、无权益文案的 `700rpx x 268rpx` 会员卡背景切片，才能完成背景像素级验收。

## 2026-07-10 会员权益全页复核

### 覆盖页面

- `会员中心-全`、`会员中心-会员未开通，支付按钮固定下方`。
- `我的会员开通状态`、`我的会员已过期状态`。
- `会员记录`、`会员记录详情（已支付/已退款）`、`订阅管理`。

### 发现与修复

1. 会员套餐轨道没有千寻币页面的选中项滚动逻辑，后续选择右侧套餐时金额卡可能不能完整显示；折扣标签还使用负定位且未预留顶部高度。现改为 `270rpx` 轨道，预留 `22rpx` 标签空间，并基于选中套餐计算像素 `scrollLeft`，保证当前金额卡完整可见。
2. 会员套餐接口刷新后，旧的演示套餐 ID 可能失效，底部金额会退化成 `¥0.00`。现会校验当前 ID 是否仍存在，不存在时同步选择当前列表的默认套餐。
3. 会员中心和订阅管理固定使用演示头像与昵称。现优先读取登录态头像和昵称，缺失时才回退蓝湖演示资源。
4. “我的会员”横幅在未开通态使用带按钮和旧 `VIP` 文案的整图；已开通和已过期态的标题、到期信息、按钮形态也与蓝湖不一致。现改为真实文本、按钮和几何背景组件，头像补上浅蓝底座和资料进度标识。
5. 会员详情没有独立 ScrollView，低屏会截断金额和明细；蓝湖直达路由只传状态时还会显示“记录不存在”。现加入滚动区，并按 `paid/refunded` 状态加载已登记的预览订单。
6. 会员记录的套餐名未限宽，真实后台长名称会与右侧周期重叠。现增加单行省略并为周期保留固定空间。

### 运行态约束

- 会员中心保留横滑套餐轨道，蓝湖首屏本身只露出右侧邻卡；“完整展示”保证的是任何已选套餐的完整金额卡、标签和文案均能自动滚入可视区域，并非强行在首屏同时塞下全部四张卡。
- 9 项权益的顺序、标题、数值和图标映射均按 `会员中心-全` 长页锁定；权益区在底部支付栏之外的 ScrollView 内，可滚到第 9 项。
